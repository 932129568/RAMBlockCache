- **本轮重点**：高并发场景下的 CPU 效率（非空闲占用）、动态缓存策略、安装器可靠性

---

## 1. 高并发 CPU 效率优化（三项）

### 1.1 锁争抢自适应退避【核心】

**问题（实测确认）**：`RB_YIELD` 内核态是**固定 1ms 睡眠**。高并发下（多 worker 争同一 stream 的 `flush_active`、多 flusher 争 dirty 链），每次争抢付 1ms —— **延迟放大 1000 倍**。本该微秒级完成的临界区等待被拖成毫秒，并发越高越慢。

**修复**（`core/cache.c` 新增 `RB_BACKOFF`）：
```c
前 64 次争抢 → YieldProcessor()（内核 PAUSE 指令，纳秒级，不给调度器让核）
之后       → RB_YIELD()（指数退避到 1ms 上限，长等待不空转）
```
**效果**：常见场景（锁马上释放）零睡眠；极端场景不烧 CPU。

应用于 `flush_acquire` 的两处等待（`flush_active` 与 `zflush_cnt`）。

### 1.2 worker 池工作窃取【负载均衡】

**问题**：per-CPU worker 只消费自己的队列——某 CPU 上分派的 IO 全部积压在其 worker，其他 worker 空闲。高并发时**最忙的那个核成为串行瓶颈**。

**修复**（`driver/rbio.c` 新增 `RbStealOne`）：自身队列空时，round-robin 扫描其它 worker，从**队尾**窃取一个节点（队头留给属主，减少争用）。窃取失败立即返回，不轮询空转。

**效果**：多核满载时负载自动均衡，不再被单核卡住。

### 1.3 动态预算刷新频率修复【前轮已做，本轮确认】

预算刷新已从"循环末尾"移到 `continue` 之前——每秒刷新，不再因"无脏数据"而饿死。

## 2. 动态缓存逻辑优化（三项）

### 2.1 迟滞（Hysteresis）

**问题**：预算每秒重算，可用内存小幅抖动 → 预算频繁变动 → 反复 evict/create（"缓存抖动"是高并发下最隐蔽的 CPU 与命中率杀手）。

**修复**：
- **向上调整需超过 5%** 才生效（吸收抖动）
- **向下调整立即生效**（应用抢内存时必须马上退让，不能等）

### 2.2 下限保护

预算不低于 **256MB**（除非可用内存本身不足 384MB）——避免"预算趋零 → 缓存形同关闭 → 命中率崩塌"的悬崖。

### 2.3 压力分级对齐实际阈值

**问题**：原压力分级最高只到 level=2（`avail < reserve`，而 reserve 默认 0）→ 只有可用内存真的接近 0 才收缩，等于不收缩。

**修复**（预算驱动）：
| 条件 | 等级 | 动作 |
|---|---|---|
| 缓存占用 > 新预算 | HIGH(2) | 立即驱逐到预算内 |
| 缓存占用 > 预算 90% | MOD(1) | 预警 |
| 可用 < 保留×2 | HIGH(2) | 安全网 |
| 可用 < 保留 | CRIT(3) | 驱逐 + 刷脏 |

**闭环**：应用吃内存 → 预算下降 → 缓存秒级退让。

## 5. 性能预期

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 高并发锁争抢（常见） | 每次争抢 ~1ms 睡眠 | ~纳秒级（PAUSE）+ 快速获得 |
