## A. 候选与选择

### A.1 需求画像（选型输入）

| 维度 | 结论（来自需求摘要 §1） | 对设计系统的硬性要求 |
|------|------------------------|----------------------|
| 场景 | Windows WPF 单窗口桌面应用，侧边导航 + 常驻状态条 | 需支持高信息密度、多页面、固定窗口 |
| 调性 | Tech Utility 骨架 + Modern Minimal 克制 | 深色、等宽数字、分层披露、无装饰 |
| 受众 | 性能用户 / 办公用户 / IT（技术素养跨度大） | 状态必须"结论优先"，术语默认零门槛 |
| 视觉硬约束 | **深色**（沿用 `#0E0E11` 系）、五色语义固定 | 需成熟深色中性阶梯 + 克制语义色 |
| 核心痛点 | 状态散落（B2）、错误不可解释（B7）、危险操作无护栏（B4） | 需强"状态徽标语言"与"可逆动作"范式 |

### A.2 三套候选对比

| 方案 | 设计系统 | 匹配度 | 特征 | 适合原因 | 风险 |
|------|---------|--------|------|---------|------|
| **A** | **Linear** | ★★★★★ | 深色中性阶梯、1px 精确描边、克制语义色、等宽数字、紧凑高密度、强状态徽标/任务语言 | 与本产品"仪表盘 + 状态单一事实"几乎同构；徽标语义体系可直接承接六态；密度适配 6 页 + 状态条 | 偏 Web 应用气质，需补 Windows 桌面原生控件手感 |
| **B** | **Vercel** | ★★★★☆ | 极致单色（近黑/近白）、几何无衬线、大留白、高对比 | 与"深色为硬约束"天然契合；克制、无装饰、Anti-Slop 友好 | 语义色语言弱、偏营销/文档气质；数据密集场景显得过空 |
| **C** | **Sentry** | ★★★★☆ | 可观测性工具语言、深色、图表/时间线/健康检查范式成熟 | §E 联调可观测性（自检清单/日志时间线/通道健康）可直接借其范式 | 主色为紫，与原型 `#60CDFF` 青色身份冲突；紫色对"正常/降级/危险"语义干扰较大 |

### A.3 选定：方案 A —— Linear（叠加 Tech Utility 方向）

**选择理由**：
1. **状态语言天然同构**：Linear 的"状态徽标 + 精确描边 + 克制的语义色"正是"状态单一事实（P2）"的成熟解法；六态可直接映射为其徽标语言，无需自造。
2. **深色中性阶梯成熟**：提供 5 层背景 + 3 层描边的标准阶梯，满足需求摘要 §4.3 的深色硬约束，且比原型的 2 层（`#0E0E11` / `#1E1E24`）更细腻，能承载"窗口/卡片/悬浮/边框"四层结构。
3. **数据密度适配**：紧凑间距 + 等宽数字 + 右对齐数值，契合"每秒轮询统计 + 64 分片"的数据密集场景。
4. **Anti-Slop 友好**：Linear 风格本身就是"无渐变、无装饰阴影、无多余图标"的代表，直接满足约束 §4.10。
5. **可继承原型身份**：保留原型的青色强调色基因（`#60CDFF` → 收敛为 `#4CC2FF`），深色底沿用 `#0E0E11`，做到"继承主线、推翻粗糙"。

**对原型配色的取舍（需求摘要 §4.3 允许继承或推翻，须给理由）**：

| 原型值 | 处置 | 理由 |
|--------|------|------|
| 底 `#0E0E11` | **继承** | 符合深色硬约束，且是产品已建立的视觉身份 |
| 卡片 `#1E1E24` | **保留但降层** | 原型卡片色被同时用作"卡片"和"悬浮"，层级塌陷；现拆为 `#17171C`（卡片）/`#1E1E24`（悬浮/hover）两层 |
| 强调色 `#60CDFF` | **收敛为 `#4CC2FF`** | 原色饱和度过高、用于大面积按钮时刺眼；收敛后保持青色身份，同时提升文字对比与克制感 |
| 语义徽标色（`#9FE1CB`/`#FAC775`/`#F7C1C1` 等） | **推翻重做** | 原型语义色亮度不足、边框色偏暗，对比度接近临界；重做为经 WCAG 校验的 5 色体系（见 §B.1.4） |

**不选 B / C 的理由**：B 的语义色与图表语言不足以支撑"六态 + 通道健康"的高信息密度；C 的紫色主色与产品既有青色身份冲突，且会削弱"红=立即处理"的语义优先级。

- 所有语义 `-fg` 在 `--rbc-bg-app` `#0E0E11` 上均 ≥ 7:1（AAA 正文级）。

- `--rbc-text-tertiary` 3.6:1 仅用于 ≥14px 或非关键辅助信息；`--rbc-text-disabled` 不承载信息，必须配原因副文本（约束 §4.8）。

#### B.1.5 色彩使用规则

1. **一个屏幕内语义色不超过 3 种同时高饱和出现**（红/琥珀/绿）；蓝/灰为中性信息，不占配额。
2. **颜色永不单独承载语义**：每个语义色必须同时有文案（六态白名单文案）或图标形状，满足色觉障碍可读性。
3. **禁止用强调色表达状态**：`--rbc-accent` 只表达"可交互/已选中"，不表达"正常/异常"。
4. **实心色仅用于徽标底、进度填充、危险按钮**；大面积区块一律用 `-bg` 浅色底 + `-border` 描边，避免高饱和铺底。

## C. 状态语义规范（解决"状态单一事实"）

> 与**体验架构 §5.1 逐条核对一致**。下表即 Phase 3 原型与实现中 `UiState` 单一映射的唯一来源：**状态 → 文案 → 语义色 → 主行动 → 禁止动作**。任何页面/组件（状态条、卷卡、导航、徽标）必须复用本表，禁止自行拼装（对齐 RB.2 / RA.2）。

### C.1 六态映射表（含熔断子态）

| # | 用户态 | 判定依据（驱动字段） | 一句话文案（白名单） | 语义色 | 主行动 | 禁止动作 |
|---|--------|----------------------|----------------------|--------|--------|----------|
| 1 | **未安装** | 打开控制设备失败（Win32 2/3） | 未检测到 RAMBlockCache 驱动 | 灰 `neutral` | 运行安装向导 | 挂载 / 调优 / 熔断 |
| 2 | **已安装未挂栈** | 连接成功但无 `Bound==1` 卷 | 驱动已就绪，尚未挂到任何卷 | 蓝 `info` | 运行首次向导 / 重启挂栈 | 开启加速（无挂栈卷） |
| 3 | **就绪未加速** | 存在 `Bound==1` 且 `Attached==0` | `D:` 已挂栈，未开启加速 | 蓝 `info` | 开启加速 | — |
| 4 | **加速中·直写** | `Attached==1` 且 `WriteMode==0` | `D:` 正在加速（直写，最安全） | 绿 `success` | 切回写（需确认） | — |
| 5 | **加速中·回写** | `Attached==1` 且 `WriteMode==1` | `D:` 正在加速（回写，异常退出可能丢未落盘数据） | 绿 `success` + 琥珀角标 | 查看脏量 / 立即回写 | 关机前不提示风险 |
| 6 | **降级·安全模式** | `RB_STATS.SafeMode==1` | 上次未正常退出，已强制直写保护数据 | 琥珀 `warning` | 确认数据无误 → 退出安全模式 | 静默恢复回写 |
| 7 | **熔断·全局透传** | `RB_STATS.PanicActive==1` 且自愈已结算 | 熔断中：所有读写直接到盘，缓存暂停（数据最安全，速度最慢） | 红 `danger` | 解除熔断 | 直接恢复加速（须先等自愈） |
| 8 | **熔断·自愈中**（子态） | `PanicActive==1` 且自愈未结算（`PANIC_CLEAR` 返回 `0xC00000A3` 或解除被拒） | 正在把未落盘数据写完（自愈中），暂不可解除 | 红 `danger` + 呼吸圆点 | 等待自愈完成 | 解除熔断（置灰 + 原因） |

> **一致性声明**：与体验架构 §5.1 完全一致。唯一细化 = 把原表的"熔断·全局透传"拆出 **"熔断·自愈中"子态**（对应需求摘要 RB.1 的熔断子态），语义色仍为红，通过"呼吸动画 + 置灰主行动"表达进行中，**不新增颜色**（避免状态色膨胀）。

### C.2 联调通道状态映射（§E 复用）

| 通道状态 | 语义色 | 判定 | 用户可见表达 |
|----------|--------|------|--------------|
| **正常** | 绿 `success` | 最近一次调用成功 | 绿点 + 延迟 ms |
| **降级** | 琥珀 `warning` | 连续失败 ≥1 但仍在退避重试 | 琥珀点 + "重试中" |
| **不可用** | 红 `danger` | 确定性拒绝 / 超时耗尽重试 | 红点 + 三段式错误入口 |
| **未接通** | 灰 `neutral` | 尚未调用过 / 不适用 | 灰点 + "—"（**禁止显示 0**） |

|----|------|------|------|------|

## D. 错误呈现规范（解决"失败可解释"）

### D.1 三段式错误组件（令牌化）

**结构**（固定三段 + 可选次要行动）：

```
┌─[严重度图标]─────────────────────────────────────┐
│ ① 标题：发生了什么           （14px/600 主色）      │
│ ② 原因：为什么               （13px/400 次色）      │
│ ③ 行动：下一步做什么          （13px/400 主色 + 按钮）│
│                              [主行动] [打开诊断]    │
└──────────────────────────────────────────────────┘
```

- **标题**：一句话结论（如"没有权限访问缓存驱动。"）。
- **原因**：根因（如"控制设备仅允许管理员访问。"）。
- **行动**：可点击的下一步（如"右键以管理员身份运行本程序"）——**必须可点击**，不允许只给错误码（RC.5）。
- **次要行动**："打开诊断"（幽灵按钮）可选，跳转诊断页并高亮对应自检项。
- **归因元信息**（RF.2）：折叠区显示 `错误码（Win32/NTSTATUS）+ 消息号 + 时间戳`，等宽栈 11px。

### D.2 三级严重度

| 严重度 | 语义色 | 呈现形态 | 是否允许继续操作 | 是否阻断 |
|--------|--------|----------|------------------|----------|
| **信息** | 蓝 `info` | 信息卡 / Toast（右下，4s 自动消失） | ✅ 允许 | 否 |
| **警告** | 琥珀 `warning` | 内联警告条（页面顶部） | ✅ 允许（附风险说明） | 否 |
| **阻断** | 红 `danger` | 错误卡 / 弹窗 | ❌ 禁止相关写操作 | 是 |

### D.3 错误码 → 三段式文案（落地表，覆盖 RC.1）

| 错误码 | 严重度 | 标题 / 原因 / 行动 |
|--------|--------|--------------------|
| Win32 **5** | 阻断 | 没有权限访问缓存驱动。/ 控制设备仅允许管理员访问。/ 右键以管理员身份运行本程序。 |
| Win32 **2 / 3** | 阻断 | 未检测到缓存驱动。/ 驱动未安装或未启动。/ 点击「运行安装向导」。 |
| Win32 **21** | 警告 | 该卷尚未准备好。/ 卷信息仍在读取中。/ 稍候几秒后重试，或重启一次。 |
| Win32 **170** / `0x80000011` | 信息 | 驱动暂时繁忙。/ 正在执行其他操作。/ 程序会自动重试；若持续失败请稍后手动重试。 |
| Win32 **87**（协议不匹配） | 阻断 | 驱动与控制台版本不匹配。/ 安装包与控制台不是同一版本。/ 使用同一发布包重新安装。 |
| NTSTATUS **0xC00000A3** | 警告 | 暂时不能解除熔断。/ 驱动正在把未落盘数据写完（自愈中）。/ 等待风险段变为「无」后重试。 |
| `0xC0000011` / FLUSH 失败 | 警告 | 数据尚未完全写入磁盘。/ 磁盘报告写入错误。/ 检查磁盘健康；未落盘数据仍在缓存中，可稍后重试。 |

> **强制区分**：权限不足（5）与驱动未加载（2/3）的文案与下一步动作**必须不同**（RC.2）。判定函数须显式枚举 Win32 与 NTSTATUS 两个域，禁止依赖数值巧合（RC.3）。

### E.3 统计不可用的呈现（禁止显示 0）

  - 卡右上角：琥珀小徽标"数据暂停"
- 原因取自上表 D.3（如"驱动未加载""权限不足"），并给"重试"幽灵按钮。
- 趋势图/环图同步显示"暂不可用"占位，**不画归零曲线**（对齐 RD.5 / C4）。

### E.4 版本协商失败与协议不匹配呈现

| 场景 | 呈现 |
|------|------|
| **协议号不匹配（硬校验失败，RE.1）** | ① 状态条驱动段转红；② 首页异常卡三段式："驱动版本与控制台不匹配（驱动 vX / 控制台 vY）。原因：安装包与控制台不是同一版本。下一步：使用同一发布包重新安装。"；③ 诊断页自检"协议版本"项标红；④ **禁用所有写操作**（开关/按钮置灰 + 原因副文本） |
| **驱动三段版本软校验不一致（RE.2）** | 仅诊断页记 WARN（琥珀），**不阻断**；状态条不变色 |
| **版本显示** | 面向用户仅 1 个版本串 `RAMBlockCache V10.4.3 Build 19（10.3.4.19）`（RE.3/RE.4）；驱动内部三段号仅诊断页并标注"驱动内部版本（用于支持排查）" |

### E.5 自检清单与日志时间线（RF.1/RF.4）

- **自检清单**：逐项"正常/异常 + 证据"，含：驱动连接（+错误码）、协议版本、驱动版本 vs 控制台版本、卷过滤链实际值（UpperFilters）、安全模式、熔断状态。
- **日志时间线**：同屏对照 UI 日志与驱动日志，来源标签可区分：`[驱动 INFO]` / `[UI INFO]` / `[驱动 WARN]` / `[驱动 ERR]`，等宽栈 12px，时间戳左对齐，来源标签按级别着色。
- **一键导出诊断包**：含 64 条驱动日志 + 自检清单 + 版本信息 + UI 日志，导出为单个文件（RF.3）。

## F. Anti-Slop 自查

### F.1 逐条自查

| 低质特征 | 本设计如何避免 |
|----------|----------------|
| **渐变滥用** | 全程零装饰渐变。唯一的"渐变感"来自深色背景阶梯（`#0E0E11`→`#17171C`→`#22222A`），是**层级而非装饰**；按钮/卡片/徽标一律纯色。 |
| **无意义阴影** | 卡片/状态条/表格默认**零阴影**（Flat）；阴影仅用于浮层/弹窗（Raised/Floating），且深色下主要靠描边分层。禁止"卡片重投影"式伪 3D。 |
| **装饰性图标** | 图标仅 3 类用途：状态点、三段式错误严重度、空态插图（24px 线性）。禁止每个标题/按钮配装饰图标。 |
| **字号过多** | 字号阶梯固定 9 档（B.2.2），页面内实际使用 ≤5 档；禁止出现 15/17/19px 等非阶梯值。 |
| **字重过多** | 仅 2 档（400 / 600）。弱化一律用颜色而非字重。 |
| **层级混乱** | 背景 5 层 + 描边 3 层，语义固定（窗口<侧栏<卡片<悬浮<浮层）；颜色语义 5 色一一绑定状态，禁止"同色多义"。 |
| **AI 味排版** | 全中文界面、无营销腔；数字等宽 + tabular 防抖动；留白用固定阶梯（4/8 基准）而非随手值；标题层级靠字号+颜色双维度，不靠装饰线。 |
| **状态色滥用** | 一屏语义色 ≤3 种；颜色永不单独承载语义（必配文案/形状）。 |
| **弹窗动效浮夸** | 仅透明度 + 8px 位移（120ms），禁止缩放弹跳。 |

### F.2 禁止清单（Never Do）

1. ❌ 装饰性渐变、玻璃拟态（glassmorphism）、发光（glow）边框。
2. ❌ 卡片/状态条使用重投影阴影制造层级。
3. ❌ 用强调色（`--rbc-accent`）表达"正常/异常"状态。
4. ❌ 数字抖动：统计值必须等宽 + tabular-nums。
5. ❌ 同一状态在不同页面用不同文案或颜色（违反 P2 / RB.2）。
6. ❌ 禁用态无原因（"点了没反应"）。
7. ❌ 统计不可用时显示 0（必须显示"暂不可用（原因）"）。
8. ❌ 徽标使用六态白名单以外的临时文案。
9. ❌ 面向用户界面出现原始字段（`Attached=1`、`WriteMode=2` 等，仅限诊断页 + 中文解释）。
10. ❌ 危险按钮做默认焦点；危险操作无三段式确认。
11. ❌ 超过 2 档字重混用；页面字号超过 5 档。
12. ❌ 彩虹色数据可视化；图表外框/背景块/阴影。
13. ❌ 深色底上使用"亮底白字"的低对比按钮（必须满足 AA）。

### G.3 Agent Prompt Guide（给 Phase 3 的生成指引）

**关键指令**：
1. 严格使用本文件令牌，**禁止发明新色值/字号**；所有颜色引用 `--rbc-*` 变量。
2. 状态渲染**必须**走 §C 单一映射表：状态 → 文案 → 语义色 → 主行动 → 禁止动作；状态条与卷卡共用同一映射。
3. 每个语义色必须**同时**带文案或形状，不得仅靠颜色。
4. 每页必须实现五态（正常/空/加载/错误/危险操作）。
5. 数字用等宽栈 + `tabular-nums`；日志用 `--rbc-mono`。
6. 危险操作弹窗三段式 + 危险按钮非默认焦点。
7. 统计不可用显示"暂不可用（原因）"，**禁止 0**。
