第 1 章  项目背景、目标与演进（V1 → V8）
================================================================================

1.1 产品目标
--------------------------------------------------------------------------------
做一个免费、可自由使用、功能对标（并在易用性上超越）商业软件 PrimoCache 的
"内存给硬盘加速"工具。核心诉求（用户原始需求归纳）：
  (1) 读、写【均】加速：读入内存、写入内存，而不仅是写缓存；
  (2) 块大小采用 4KB（与现代 SSD/NTFS 簇/内存页粒度匹配，综合效果最好）；
  (3) 内存【按需动态占用】，不固定预占：设为 0（自动）时，用多少占多少，
      空闲内存尽量用于缓存，但系统/其他程序需要内存时能主动收缩、绝不把
      机器拖垮、绝不因内存耗尽而崩溃；
  (4) 可自由选择对哪块盘（卷）启用/关闭加速，运行时切换、尽量免重启；
  (5) 网页/软件修改配置必须【真正生效】，不能只改界面样子；
  (6) 提供精致、流畅、不简陋的可视化控制中心（WPF 原生为主，保留 HTML）；
  (7) 强数据安全：防蓝屏、写满保护、关机/休眠保存脏数据、异常重启识别修复；
  (8) 多核优化：充分利用现代多核 CPU，读写真正并行；
  (9) 一键部署、换机硬件自适应（重跑脚本即可，不硬编码核数/内存/卷）；
 (10) 纯本地、不联网；自签名证书长期有效、可续签。

1.2 版本演进与关键转折
--------------------------------------------------------------------------------
V1–V4（云沙箱阶段）：
  - 建立平台无关缓存核心 core/cache.c（块哈希表、LRU、脏链、回写/补读回调）；
  - V4 将"每流一把大锁"重构为 64 分片条纹锁（striped locks），同一文件不同
    区域在多核真正并行；锁序固定为 streams → stripe(升序) → chain。
  - 云端用 gcc + AddressSanitizer / UndefinedBehaviorSanitizer / ThreadSanitizer
    反复验证核心（注：TSan 仅在 Linux 用户态可用）。

V5–V7（文件系统 minifilter 阶段，真机反复蓝屏）：
  - 驱动形态为文件系统微过滤器（minifilter，挂在 FltMgr 栈内、缓存管理器 Cc 之上）；
  - 真机出现多起蓝屏，典型代码：
      KERNEL_SECURITY_CHECK_FAILURE  0x139，arg1=3（FAST_FAIL_CORRUPT_LIST_ENTRY）
      IRQL_NOT_LESS_OR_EQUAL        0x0A
  - 经多份内核转储与代码分析，定位为【结构性根因】（见 1.3）；
  - V7 曾安全退缩为"仅加速非缓冲（non-cached）I/O"，但日常负载绝大多数是
    cached I/O，导致体感"开了等于没开"。

V8（块层重写，当前版本）：
  - 用户明确选择把驱动从文件系统 minifilter 重写为【卷块设备上层过滤驱动】
    （volume upper filter，普通 WDM PnP 过滤驱动，非 minifilter）；
  - 驱动工作在文件系统 / 缓存管理器 Cc 【之下】的卷块设备层，与 PrimoCache
    同层；单一数据视图、无第二句柄、无 Cc 冲突，从而能加速【一切】块 I/O
    （系统、普通程序、游戏、cached、paging、非缓冲）。

1.3 V7 蓝屏结构性根因（决定 V8 架构的关键分析）
--------------------------------------------------------------------------------
V7 在文件系统层（Cc 之上）对 cached I/O 自行完成（self-complete），并另开一个
带 FILE_NO_INTERMEDIATE_BUFFERING 的第二句柄去落盘。这造成：
  - 同一份文件数据存在"两个不一致的写者 / 两个不一致视图"——缓存管理器 Cc
    的视图与过滤驱动第二句柄的视图；
  - 第二句柄的非缓冲写绕过 Cc，却不更新/不失效 Cc 内部缓存页与其同步结构
    （ERESOURCE、内部链表），污染 Cc 的内部状态；
  - 最终触发 Cc/内存管理器内部链表一致性校验失败（0x139 FAST_FAIL_CORRUPT_LIST_ENTRY）
    或非法访问（0x0A）。
这类问题无法靠"再加锁"在文件系统层彻底消除，因为根因是【在错误的层制造了
第二视图】。V8 下移到块层后：
  - 文件系统/Cc 仍是其上方唯一的文件视图拥有者，块层只看到 NTFS 已经构造好的
    块级读写，天然单一视图；
  - 块层不再需要"第二文件句柄"，彻底消除该类蓝屏根因。

1.4 V8 子版本
--------------------------------------------------------------------------------
V8.0：块驱动骨架（AddDevice / PnP / 控制设备 / IOCTL），控制通道冻结。
V8.1：合并三轮评审 + 独立审查修复：per-CPU I/O worker 池、zone 并行回写、
