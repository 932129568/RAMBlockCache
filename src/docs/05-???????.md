# 05 签名与安全启动

## 一、为什么驱动需要签名

Windows（x64 起）只允许加载**有数字签名**的内核驱动。RAMBoostFS 是自研驱动，
没有微软签名，因此需要一种合法加载路径。方案按成本从低到高：

| 方案 | 成本 | 适用 | 备注 |
|---|---|---|---|
| **自签名 + 测试签名模式**（本项目默认） | 免费 | 个人自用 | 需重启、需在 BIOS 关闭 Secure Boot 或接受相关限制 |
| 购买 EV 代码签名证书 + 微软 Attestation 签名 | 每年数千元 | 商业分发 | 可脱离测试模式 |
| WHQL 认证 | 贵 + 流程长 | 正式产品 | 微软官方认证 |

> 免费路线：自己生成证书、给 `.sys` 签名、开启系统测试签名模式。效果：驱动能正常加载运行，
> 但系统会提示处于测试模式（桌面右下角有水印"测试模式"）。

## 二、长效自签名流程（脚本已封装）

```bat
scripts\sign_test.cmd        （必须管理员运行）
```

内部动作：
1. 在 `LocalMachine\My` 创建或**复用**自签名代码签名证书
   `CN=RAMBoostFS Root`，参数为 **RSA 4096 / SHA256 / 有效期 100 年**
   （`-NotAfter (Get-Date).AddYears(100)`，私钥可导出）；
2. 把该根证书导入 `LocalMachine\Root`（受信任根）与
   `LocalMachine\TrustedPublisher`（受信任发布者）；
3. 用内置 PowerShell `Set-AuthenticodeSignature -HashAlgorithm SHA256`
   对 `driver\x64\Release\RAMBoostFS.sys`，以及（若存在）`ctl\ramboostctl.exe`
   做 Authenticode 签名；
4. 用 `Get-AuthenticodeSignature` 在**本机**校验签名，并打印当前 testsigning 状态。

### 纯本地 / 不联网 / 无 CRL

- 签名时**不指定时间戳服务器**（旧版脚本里的 `/t timestamp.digicert.com` 已去掉），
  因此整个签名过程完全离线，不会访问任何时间戳或吊销服务器。
- 根证书自签并装进本机 `Root` 库，证书链在本机即可闭环，
  **不依赖公网 CA、不依赖 CRL（证书吊销列表）/ OCSP**。

### 续签 / 重新签名（兜底逻辑）

脚本是**幂等**的，可随时重复运行：

- 证书存在且未过期 → 直接复用该证书；
- 证书缺失或已过期 → 自动新建一张 100 年证书并重新签名；
- 改了驱动代码后重跑 `sign_test.cmd`，即"重新签名"。

> 由于证书有效期长达 100 年，正常使用中几乎不会遇到过期；兜底分支主要用于
> 重装系统、换证书库或证书被误删的场景。

验证签名（本机离线）：

```powershell
Get-AuthenticodeSignature .\driver\x64\Release\RAMBoostFS.sys
# 看 Status 是否为 Valid
```

## 三、游戏模式 / 加速模式切换（game_mode.cmd）

测试签名模式（testsigning on）与带内核反作弊的游戏互斥。
为此提供干净的一键切换脚本，**只做 `bcdedit /set testsigning off|on`，
不做任何隐藏/欺骗 testsigning 的逻辑**：

```bat
scripts\game_mode.cmd            （管理员运行，自带 UAC 自提权）
scripts\game_mode.cmd game       游戏模式：testsigning off
scripts\game_mode.cmd accel      加速模式：testsigning on
```

| 模式 | 命令 | 效果 | 重启后 |
|---|---|---|---|
| **游戏模式** | `bcdedit /set testsigning off` | RAMBoostFS 驱动不加载 | Valorant / Vanguard 等内核反作弊游戏可正常启动 |
| **加速模式** | `bcdedit /set testsigning on` | 恢复内存加速 | 出现"测试模式"水印；此时反作弊游戏拒绝运行 |

要点：
- **两种模式都必须重启电脑才生效**，脚本切换前会明确提示，并可选择 10 秒后自动重启
  （取消重启：`shutdown /a`）。
- 脚本会先 `bcdedit /enum {current}` 显示当前 testsigning 状态。
- 这是**干净切换**：要玩游戏就关测试签名重启，要加速就开测试签名重启，二者不兼得。

## 四、Secure Boot（安全启动）注意事项

- **Secure Boot 开启**时，Windows 会拒绝加载"非微软签名的驱动"，即使开着测试签名模式。
  - 解决：进 BIOS（开机按 Del/F2）→ 找到 Secure Boot / 安全启动 → 设为 **Disabled**。
  - 部分新主板（Win11 强制 Secure Boot）关闭后 Win11 仍可正常启动，只是系统提示不受信任环境。
- **不想关 Secure Boot** 的替代路线：
  - 购买 EV 证书后做微软 attestation 签名（贵，个人一般不选）；
  - 或用本项目默认路线"自签名 + 测试签名模式 + Secure Boot 关闭"。

## 五、签名文件与证书位置

- 证书：
  - `Cert:\LocalMachine\My`：含私钥，用于签名
  - `Cert:\LocalMachine\Root`：受信任根
  - `Cert:\LocalMachine\TrustedPublisher`：受信任发布者
- 签名后的驱动：`driver\x64\Release\RAMBoostFS.sys`（脚本就地签名）
- 签名后的控制程序：`ctl\ramboostctl.exe`（若存在）

## 六、常见问题

| 现象 | 原因/处理 |
|---|---|
| 加载报"签名验证失败" | 测试签名未生效：运行 `game_mode.cmd accel` 且**重启**；确认 Secure Boot 已关闭 |
| 桌面右下角"测试模式"水印 | 正常现象，测试签名模式的系统提示 |
| 重编译了驱动后加载失败 | 重新运行 `scripts\sign_test.cmd` 重新签名，再重启 |
| 换了电脑 | 新电脑重新跑 `sign_test.cmd`（证书在本机证书库，不随代码走） |
| 玩 Valorant/Vanguard 被反作弊拒绝 | 当前是加速模式（testsigning on），运行 `scripts\game_mode.cmd game` 并重启 |
