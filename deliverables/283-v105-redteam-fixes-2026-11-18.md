## 3. 已做的修复

| 文件 | 改动 | 对应 |
|---|---|---|
| `rb_common2.h` | 结构体字段更名：`BootEpochLo32→EngineEpochLo32`、`ShutdownPersistWhy→ShutdownPersistWhyPrev`、`PersistSkipReason→PersistSkipReasonPrev`；注释改为「`*Prev` 才是上次关机、`EngineEpoch` 不跨引导」；补 `FILE_WRITE_ACCESS` 的真实边界（只在开句柄时判一次、不记调用者）；锚点订正 `rbdriver.c:892→:904`、`rb_common.h:429-437→428-437` | D-1 / D-6 |
| `rbctl.c` `RbCtlShutdownDiag` | 改读 `ShutdownPersistWhyPrev` / `PersistSkipReasonPrev`；`BootFailCount` 改报**注册表**值（下次引导的实际输入），读失败报 `0xFFFFFFFF` 未知、不补零；补 `KeGetCurrentIrql()==PASSIVE` 门 | D-1 |
| `rbctl.c` `RbCtlHealthCommit` | 重写：① 新增 `s_HealthCommitLatch` 单飞闩；② 判据改取注册表值；③ **留证 → 回读确认留证已落地 → 才清零**；④ 回读通过后才提交内存；⑤ 成功后 `RbSelfDisableClear()`；⑥ 清零后再复核 panic，若期间熔断则写 `HealthCommitContended=1` 并返回 `STATUS_DEVICE_NOT_READY`（不报成功）；⑦ `HealthCommitSeq` 注释明确「缺失不得反推没清过」 | D-2 / D-3 / D-4 / D-5 |
| `rbfeatctl.c` | `SHUTDIAG` 同步更名；`shutdiag` 打印 `*Prev` 与「引擎世代，非跨引导锚」；`BootFailCount=UNKNOWN` 单列；`health-commit` 成功文案改为「已建卷不受影响 / 被自断环拒建的需重启重新枚举 / 不替下次引导写 healthy 票」；订正「唯一能解除 Guard 的路径」这一错误说法 | D-1 / D-2 |
| `check_ctl_codes.py` | 见 §5（由独立工人硬化 P2/P3/P4/P5/P6/P7 与 `forward_chain_vals`） | D-7 |

**关键顺序变更（D-3 的核心）**：旧顺序是「清内存 → 回读」，新顺序是
「留证 → 回读留证 → 清注册表 → 回读注册表 → 提交内存」。任何一步失败，**内存都未被改**，
因此不会再出现「报失败但副作用已生效」。
