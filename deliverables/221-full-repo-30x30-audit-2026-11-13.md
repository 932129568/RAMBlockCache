## §3 方法：为什么 60 轮必须机器化

74k 行、4 种语言、跨 7 层（驱动 → core → 桥接 → Web / WPF）。靠叙述「第 N 轮做了 X」
不可复验。因此：

1. **30 轮升级** = 30 个质量维度 × 6 个模块。每轮必须**遍历所有模块**，不允许
   「找到一个点就算一轮」。
2. **30 轮缺陷猎杀** = 30 个缺陷类别 × 全仓。每类写成一条**高精度**规则，
   命中后人工确认/否决，记录结论。
3. 规则与结论都落盘：`tools/audit_sweep.py --round <ID>` 可随时复跑同一轮。

扫描器用法：

```bash
python tools/audit_sweep.py --list                  # 列出 30 类
python tools/audit_sweep.py --round C08             # 单轮复跑
python tools/audit_sweep.py --all --json out.json   # 全量 + 机器可读
python tools/audit_sweep.py --all --fail-on-high    # CI 形态：留 HIGH 即 exit 1
```

## §4 已修复的 10 处缺陷（按严重度）

### F1 【HIGH】驱动重启被画成正向吞吐尖峰（Web 统计）

`src/ui/web/src/state/stats-history.ts`

- **缺陷**：回退检测做在**派生差值** `ReadBytes - ReadHitBytes` 上。驱动重启后两个
  计数器同时归零再涨，派生差值可能满足 `cur >= old`，于是**一次重启被当成真实下盘流量**。
- **数值证明**：prev `8,000,000 / 8,000,000`（全命中，下盘 0），重启后 `1,000 / 0`
  → 旧公式输出 `+0.0010 MB/s`；另一组 prev `10,000,000 / 5,000,000` → 重启后
  `10,000,001 / 1` → 旧公式输出 **`+4.768 MB/s` 假尖峰**。新公式均为 `0`。
- **契约依据**：该文件自己的文档写着「计数器回退视为清零重建，该周期差值记 0，
  绝不画负值/假值」。
- **修复**：改为在**原始计数器**上判定回退（`diff()` 返回 null），任一回退 ⇒ 该周期记 0；
  下盘量 = `max(0, dRead - dHit)`。
- **回归**：新增用例「驱动重启只回退 ReadBytes 时不得产生下盘假吞吐」，
  并把原用例的 `>= 0` 弱断言收紧为 `=== 0`（原断言正是掩盖此缺陷的原因）。
  测试 8/8 通过。

### F2 【HIGH】CLI 把「驱动拒绝」误报成「驱动未加载」（ctl）

`src/ctl/ctl_conn.c` / `ctl_internal.h` / `ramboostctl.c`

- **缺陷 1**：`cli_conn_hint()` 在**提示时**才调 `GetLastError()`。中间任何一次成功的
  Win32 调用（含 `fprintf` 内部）都会改写错误码；驱动返回非零 `Status` 时根本没有
  Win32 错误，读到的是陈旧无关值。结果：参数越界被报成「驱动未加载，请重装」。
- **缺陷 2**：`rb_send()` 在 `rb_connect()` 失败时**直接 return**，`reply` 仍是调用方
  未初始化的栈内存；而 `rb_attach_volume()` 的失败分支会读 `reply.Status` 回填
  `*pStatus` ⇒ 把栈垃圾当 NTSTATUS 交给用户。
- **修复**：新增 `g_lastWin32` / `g_lastNt`，在**失败现场**记录；`rb_send` 入口
  `memset(reply,0,...)`；提示文案优先判「驱动在线但拒绝」，再判 Win32。
- **真机证据**（非提权实跑）：
  ```
  [错误] 权限不足：控制设备仅允许管理员访问，请以【管理员身份】运行本程序（Win32=0x00000005 NTSTATUS=0x00000000）
  ```

### F3 【HIGH】Toast 挤压缩放把自己的出场动画立刻摘掉（WPF）

`src/ui/controller/.../Services/ToastService.cs`

- **缺陷**：`while (Count > 3)` 里先把 `Toasts[0].Closing = true` 并起 120ms 出场，
  但**同一次循环**里 `Count` 未变 ⇒ 下一轮看到 `Closing == true` 直接
  `RemoveAt(0)` ⇒ 刚启动的动画当场被摘掉。原注释「[FIX B22] 挤压最旧项也走出场动画」
  实际从未生效，且随后 120ms 的 Task 还会去删已不存在的项。
- **修复**：软上限 3（播 120ms 出场，期间允许短暂 4 条）+ 硬上限 4（突发才硬摘）；
  新增 `RemoveAfterExitAsync`；`async void` 改为 `async Task` + 调用点显式丢弃。
- **验证**：WPF 构建 0/0，控制器测试 13/13。

### F4 【HIGH】L2 容量三端不一致：Web 允许 512GB，驱动静默截到 128GB

`SettingsPage.tsx` / `bridge/server/index.ts`

- **事实链**：驱动 `RB2_L2_MAX_GB = 128`（`rbL2.c:59`，`:642` **静默截断**）；
  CLI `rbfeatctl.c:258-259,296-297` clamp 1–128；WPF `MainViewModel.Settings.cs:273`
  clamp 1–128；**Web 输入框 `max={512}`，桥接也放行 512**。
- **后果**：用户填 256GB → 无任何提示，实际拿到 128GB 容器。
- **修复**：Web 常量 `L2_MAX_GB = 128` + 标注范围；桥接同样收紧，
  并**拒绝**非法 `gb`（旧式 `Math.max(1, Math.min(512, NaN||0))` 会把 `gb:"abc"` 变成
  1GB ⇒「参数写错」伪装成「成功创建 1GB 容器」）。
- **附带**：Web 缺省容量 16 → **32**，与驱动 `Rb2GetDW(L"L2SizeGB", 32)` 及 WPF `_l2SizeGb = 32` 对齐。

### F5 【MED】事件轮询器 `Stop()` 之后 `Start()` 永久失效 + 卡死无告警（WPF）

`Services/DriverEventPoller.cs`

- **缺陷 1**：`Stop()` 只停 Timer，不清 `_started` ⇒ 之后的 `Start()` 被幂等判断直接
  return，**轮询永久不再启动**，且无日志。捕捉工具在同一进程里连续拍多组状态正需要
  Stop→Start 往返。
- **缺陷 2**：`_inFlight` 闸门在 IOCTL 挂死时**静默永久停摆**，用户只看到「进度条不动」。
- **缺陷 3**：`_cursor` 在逐条投影**之前**提交 ⇒ 投影抛异常时这批事件既没投出去、
  游标也越过了它们（静默丢事件）。
- **修复**：`Stop()` 清 `_started`；连续跳过 ~10s 记一条 INFO（不刷屏、不强清 `_inFlight`，
  因为无法取消已发出的同步 IOCTL）；游标改为**投影成功后再提交**。

### F6 【MED】只读请求对任何错误都重试，且超时文案恒为 1500ms（Web）

`bridge/http-transport.ts`

- **缺陷**：只读方法（1/4/7/9/10/14）对**任何**异常都重试一次，包括 503（驱动未加载）
  与 401/403（权限不足）——这两类重试不可能成功，只是把失败延迟一倍并掩盖真实原因。
- **缺陷**：`mapNetworkError` 固定用 `this.timeoutMs`(1500) 拼消息，于是 30s 的
  FLUSH/ATTACH 超时被报成「控制通道 1500ms 无响应」，误导用户以为通道卡死。
- **修复**：仅 `TimeoutError` 重试；`effectiveTimeout` 随重试更新并传入错误文案。

### F7 【MED】「打开日志目录」失败会把全局连接态闪成离线（Web）

`features/diagnostics/DiagnosticsPage.tsx`

- **缺陷**：失败用 `code:'UNREACHABLE'` 上报 ⇒ `driver-store.reportError` 把
  `phase` 改成 `offline`。而「资源管理器打不开」与驱动连通性无关，会闪出一条
  莫名其妙的断连横幅（下一次 1s 统计轮询又翻回在线）。
- **修复**：改报 `IOCTL_FAILED`（不影响 phase），并补 `r.ok` 检查。

### F8 【MED】日志写入竞态：并发时静默丢行（WPF）

`Services/LogService.cs`

- **缺陷**：`File.AppendAllText` 完全在 `_gate` 之外。轮询线程与 UI 线程同时记一行时，
  两次以 `FileShare.Read` 打开同一文件 ⇒ 后者抛共享冲突 `IOException` ⇒ 被 catch 吞成
  「写盘失败计数 +1」，**这一行日志永久丢失**。本项目恰恰靠日志做故障复盘。
- **修复**：新增 `_fileGate` 串行化写盘（独立于 `_gate`，不阻塞环形缓冲与 UI 日志页）。

### F9 【MED→测试有效性】长期红灯的无障碍断言（WPF 测试）

`RAMBlockCache.Controller.Tests/Program.cs`

- **事实**：`RunVolumeLabelStyleAssertions` 断言 `MainWindow.Resources["VolumeLabelText"]`
  存在（MaxWidth=160 / 省略号 / ToolTip 绑定 / HelpText 绑定）。但
  `MainWindow.xaml` 自 **[UI-HOST 2026-11-05]** 起只是 WebView2 外壳（原生页面已归档到
  `docs/legacy-wpf-ui/`），WPF 侧既无该 Style 也无消费者 ⇒ 该断言**永久失败且无法通过**。
- **危害**：13 项断言里固定 1 项红，其余 12 项的真实回归失去信号（红灯常态化）。
- **处理**：删除该断言并在原位留下 8 行说明（含 a11y 契约的新归属：
  `VolumesPage.tsx:209` 的 `<article aria-label="卷 X 卡片">`），
  同时说明「若恢复原生卷列表必须同步恢复等价断言」。
- **验证**：控制器测试由 12+1FAIL 变为 **13 PASS / 0 FAIL**。

### F10 【LOW】审计器自身的三类误报（工具精度）

`tools/audit_sweep.py`

- C08 未识别**单行守卫**（`if (!x) { free(x); return; }`）与**同名变量重新声明** ⇒ 9/9 误报。
- S03 把 `VolumeGuard.Result` 这类**嵌套类型名**当成 `Task.Result` ⇒ 4/4 误报。

- **结果**：HIGH 19 → **0**，扫描器可作 CI 门禁（`--fail-on-high`）。
