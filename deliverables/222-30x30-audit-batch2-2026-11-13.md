## §3 R19 落地：配置回读 diff（本批唯一新功能）

### 3.1 缺陷（`221` §5 R19 的 🟡 项）

`SettingsPage.onSaved` 在 `transport.setConfig()` 返回 `Status=0` 后，直接提示
**「已保存（驱动返回 Status=0），配置查询将自动刷新」**。但 `Status=0` 只代表驱动
**收下了这次写入**，不代表每个字段按请求生效。驱动侧多处静默 clamp：

| 字段 | 驱动行为 | 证据 |
|---|---|---|
| L2 容量 | `> 128GB` 静默截到 128 | `rbL2.c:59` `RB2_L2_MAX_GB`、`:642` 截断 |
| `BlockSize` | 非白名单回落默认 | `rbctl.c` `rb_legal_bs[]` |
| `DirtyLowPct` | ≥ 高水位时被纠正 | `ramboostctl.c:265` 同款 CLI 侧逻辑 |

即：**Web 曾经放行 512GB（`221` F4），用户填 512 会得到 128，而界面说"已保存"。**
CLI 早在 `ramboostctl.c:273 FIX[R5]` 就做了回读（"杜绝界面显示一套、驱动生效另一套"），
Web 一直是缺的 —— 同一产品两条前端，一条守纪律一条不守。

### 3.2 实现

- 新增 `src/ui/web/src/features/settings/config-diff.ts`（纯函数，无 React 依赖）：
  - `diffConfig(want, got)` —— 逐字段比较，**undefined ≠ 0**（回读缺字段也算漂移）；
  - `VolumeFilter` 归一化掉尾部 NUL（驱动定长补齐不算漂移）；
  - `configFieldLabel()` 给 24 个字段配中文短名，提示直接可读；
  - `describeDiff()` 输出 `块大小：请求 131072 → 生效 65536`。
- `SettingsPage.onSaved` 改为三段式：
  1. 回读成功且无差异 → 「已保存，**回读核对通过**：驱动实际生效值与请求完全一致」；
  2. 回读成功但有差异 → 红色 + **逐项列出**「请求 X → 生效 Y」，toast 改 `warn`；
  3. **回读失败** → 明确「无法确认实际生效值」，**不许**说"已生效"。
- 结果面板加 `whiteSpace:'pre-line'`（多行 diff 否则会挤成一行）。

### 3.3 验证

`config-diff.test.ts` 6 条用例：一致→空数组 / 单字段 clamp 被点名 / 多字段顺序稳定 /
`undefined` 不得当 0 / NUL 归一化 / 未知字段回落原名。vitest **14/14 通过**，
`tsc --noEmit` 0 错，`npm run build` OK。

> **生效方式**：纯前端 ⇒ 刷新控制台页面即可（`dist/index.html` 每次请求现读，桥接无需重启）。

`AGENTS.md` 是新会话入口，且**指令性**地告诉读者下一个编号用什么：

```
:32   - `<N>` = `deliverables/` 下最大编号 + 1（当前 143，下一个 144）。
:129  `<N>` 当前最大 = **143**，下一个 **144**。
```

实际：`deliverables/` 最大已是 **221**，且 **`144-gate-audit-2026-11-11.md` 已存在**。

无报错、无告警、无版本控制兜底（R1：本仓库长期不提交 git）。

> 这类缺陷比代码 bug 更隐蔽：代码错了测试会红，文档错了只会安静地毁数据。

- `README.md` → `Gate1..Gate22`；删掉那份门禁子集清单，改为「清单只在 `Invoke-Gates`」+
  指向方式；补 Gate21/Gate22 两行说明；宿主数去数字。
- 新增 `src/scripts/check_docs_numbering.py`（**Gate22**）：
  1. `deliverables/` 编号**同号同 slug** 重名 = FAIL（同号不同 slug 允许，如 `107-handover` + `107-incident`）；
  2. `AGENTS.md` 与 `HANDOVER-CURRENT.md` 里所有「下一个 NNN」/「当前最大 = NNN」声明必须 = 实际最大 + 1；
  3. **fail-closed**：`AGENTS.md` 缺失、或**认不出任何编号声明**（措辞漂移）⇒ FAIL。

### 4.5 Gate22 的变异验证（证明有牙，不是装饰）

```
基线                        → [OK] max=221 next=222          exit 0
变异① 下一个 222 → 下一个 999 → [FAIL] says next 999 ...      exit 1
变异② 全部「下一个」→「后续」 → [FAIL] no longer declares ...  exit 1   ← 空集不得通过
变异③ 注入后跑 -Target gates  → [X] gate FAILED: check_docs_numbering.py  exit 1  ← 确已接入门禁链
恢复                          → [OK]                          exit 0
```

### 4.6 它当场抓到了我一次（设计的意外自证）

写本报告后必须在 `HANDOVER-CURRENT.md` §4 里**引述**旧文本（143 / 144）说明缺陷。
结果 Gate22 把这段引述**当成真声明**报红：

```
[FAIL] HANDOVER-CURRENT.md: says next number is 144, ... must be 223
[FAIL] HANDOVER-CURRENT.md: says current max is 143, ... real max is 222
```

处理方式是**改文档、不改门禁**：引述历史编号时不连写「下一个 NNN」。
理由：门禁的严格性正是它的价值，为一个引述去放宽规则，就回到「规则可以被绕过」，
而「规则可以被绕过」正是 D1 这类缺陷能存活半年的原因。这条约定已写进 HANDOVER §4-D1。
