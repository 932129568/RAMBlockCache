## 📌 TL;DR（执行摘要）

- **一句话**：把已在代码中落地但默认关闭的顺序读预取层（`src/driver/rbpref.c`）**激活并产品化**——连续读流自动向块层直发预读 IRP，配合每卷可配预读窗口与 SSD 温度护栏，与 L2 持久缓存组合兑现「开机即热、顺序读不等待」。
- **为什么是它**：预取是 PrimoCache 付费理由的另一半（启动预取 + 空闲预取 + 4.3.0 起 L2→L1 预取）；数据分析明确「顺序读场景 RAM 缓存优势本就薄弱」——**预取单独价值有限，与 L2 组合才是完整体验**，故本 PRD 与 PRD-01 互为搭档，共享验收环境与叙事。
- **现状（代码事实）**：倒流跟踪 + 连续 ≥4 段触发 + 8MB 分片 + 全局 ≤8 在飞（非分页突发 ≤64MB）+ 每流 2s 冷却 + 每卷 ReadAheadMB 默认 16MB；BUILD15 已完成引用计数对称、IRP/MDL 清理、链式判定修复、策略 10s 缓存等加固；温度护栏（`RbThermalPrefBlocked`）可阻断预取。
- **范围冻结（M1）**：激活策略（默认关→条件开）、每卷 ReadAheadMB 策略面（WPF/CLI/注册表）、温度护栏产品化、统计对账、基准调优验收；**不做启动预取（依赖 PRD-01 M2 + 热区预热）、不做应用级预取**。
- **硬门禁**：顺序读吞吐提升（基线由基准库校准）；随机读零退化；缓存命中率不降；在飞/内存边界强制；温度护栏生效；零新增归因崩溃。

## 1. 功能背景与目标

### 1.1 背景：顺序读的"最后一公里"

**用户问题**：顺序读负载（影视播放、大文件拷贝、数据库全表扫描、游戏关包加载、编译/解压）在缓存未预热时等于裸盘速度；即便块层覆盖（PRD-02）生效，首次顺序读仍受限于磁盘带宽。预取（readahead）把"用户还没要的数据"提前读入缓存，把串行等待转为并行流水——这是操作系统 readahead 的内核级等价物，且可跨进程、跨文件边界按卷级地址流工作。

**竞品坐标**：PrimoCache 的预取是其付费理由组合的另一半（启动预取/空闲预取/L2→L1 预取）；竞品分析将「预取」列为追平项 5，并明确与 L2 组合才是「开机即热」完整体验。本品已有实现但默认 OFF，**边际工作量在激活、策略面与验收，而非算法**。

**工程现状（代码事实，2026-10-15 核验）**：

| 组件 | 状态 | 证据 |
|---|---|---|
| `rbpref.c` 预取层 | **已实现，默认 OFF** | 倒流跟踪表（128 槽）、链式判定（上次结束地址==本次起始地址）、连续 ≥4 段触发、预读 IRP **直发 `ext->LowerDevice` 绕开本过滤设备顶层（回环防护）** |
| 分片与并发 | 已实现 | 预读按 8MB 分片、全局在飞 ≤8（非分页突发 ≤64MB）、每流冷却 2s |
| 每卷策略 | 已实现 | `Policies\<X>: ReadAheadMB`（默认 16）、`MaxWriteIops`（默认 2000）；注册表读取 10s 缓存（POL-1，移出热路径锁外） |
| 稳定性加固 | BUILD15 已完成 | PREF-1 引用计数对称（提交前 Increment、收尾减一，修 UAF）；PREF-2 IRP/MDL 分配失败完整清理；PREF-3 链式判定修复（原用起始地址比较，Seq 恒 1 永不触发）；PREF-4 8MB 分片 |
| 温度护栏 | 已实现（Build15） | `RbThermalNote`/`RbThermalPrefBlocked`：SSD 温度超限时阻断预取（降温后恢复） |
| 统计 | 计数器已预留 | `RB_STATS2.PrefIssued/PrefFillOk` |
| 关联设施 | 已实现 | `rbhot.c` 热区指纹（1MB 粒度、周期衰减、快照进注册表、attach 时预热）；`Rb2VolRead` 真预热（读下层盘 + `rb_read_commit` 入缓存，best-effort，≤16MB） |

### 1.2 目标（可衡量）

| # | 目标 | 目标值（估计基线，以基准库实测校准） |
|---|---|---|
| G1 | 顺序读吞吐提升 | 大文件/影视/数据库扫描负载：预取开启 vs 关闭 **≥+20%**（同一硬件、同一文件、冷缓存） |
| G2 | 随机读零退化 | 4K 随机读 P99 延迟退化 **≤5%**（预取不得挤占随机读路径） |
| G3 | 缓存命中率不降 | L1 读命中率开启预取后不低于关闭时 -2 个百分点（防预取污染淘汰热数据） |
| G4 | 内存边界强制 | 非分页预取突发 **≤64MB**（128 并发流压力下不变） |
| G5 | 温度护栏生效 | 模拟 SSD 超温：预取停止且日志可见；降温后自动恢复 |
| G6 | 归因本品的新增内核崩溃 | **0**（Driver Verifier + 压力场景） |

### 1.3 Non-goals

1. **M1 不做启动预取**（开机即从 L2/热区预热）——依赖 PRD-01 M2（L2 持久化）与热区预热链路成熟度，列入 M2。
2. **不做应用级/文件级预取**——卷层驱动无文件语义（PrimoCache 同样不能）；热区指纹（1MB 粒度）是卷内近似，不伪装成文件级智能。
3. **不做 L2→L1 主动转储式预取**（PrimoCache 4.3.0 语义）——属 PRD-01 M2 FR-L2-11 范围，本 PRD 只保证被预取/淘汰数据经 L1 淘汰自然流入 L2。
4. **不做 DirectStorage 路径预取**——应用直通路径绕过缓存栈，预取不介入（竞品分析 8.3：只读卷共存即可）。
5. **不做网络/iSCSI 卷预取**——映射网络盘不在支持矩阵（对齐 PrimoCache）。
6. **不做固定窗口拍脑袋值**——M1 默认 16MB/卷为继承值，是否保留以 G1–G3 基准结论为准。

## 2. 目标用户与使用场景

### 2.1 目标用户

| 用户层 | 画像 | 预取价值 |
|---|---|---|
| **S2 游戏玩家（主）** | 游戏关包二次加载、地图切换 | 连续段自动预读，切换等待下降；与游戏模式/只读卷配置联动 |
| **S1 影音/大文件用户** | 本地影视、素材拷贝 | 顺序读吞吐提升，播放缓冲减少 |
| **S3 技术/开发者** | 编译构建、数据库扫描、日志分析 | 工具链重复扫描受益；可自行调 ReadAheadMB |
| **SSD 寿命焦虑者** | 关注温度与写入 | 温度护栏 = 预取不牺牲 SSD 健康 |

### 2.2 使用场景与用户故事

**场景 A：顺序读不等待**
> 作为影音用户，我希望播放/拷贝大文件时驱动自动提前读入后续数据，以便带宽利用率饱和、减少卡顿与等待。

**场景 B：游戏关包二次加载**
> 作为玩家，我希望游戏切换场景时连续读块被自动预取，以便二次加载接近内存速度，同时不影响 DirectStorage 直读的游戏。

**场景 C：可调、可见、不伤盘**
> 作为技术用户，我希望每卷预读窗口可调、预取效果（预发字节/填充成功）可见、SSD 高温时自动停止预取，以便在效果、可见性与硬件健康间自主权衡。

## 3. 核心功能列表及详细描述

优先级：P0=M1 必须；P1=M1 应该；P2=M2。

### FR-PF-01 激活策略（P0）

- **描述**：预取从"代码就绪但默认 OFF"到"可运营地开"。
- **详细要求**：
  1. 特性位 `RB2F_PREFETCH`（部署默认 0 全关的红线保持）；激活路径：WPF 缓存页总开关 + 每卷独立开关；CLI `ramboostctl pref status|on|off [<Letter>]`（经既有 `rbfeatctl` 入口或协议 9 扩展——新消息须过 `check_proto_sync.py` 三副本门禁）；
  2. **激活前置条件**（全部满足才允许开，任一不满足 UI 明示）：该卷已验证加速（PRD-02 覆盖矩阵结论）；卷非系统卷（或用户已 opt-in，FR-BL-04）；SSD 温度正常；
  3. **与回写模式联动**：卷开延时写（回写）时预取保持但统计分列（回写卷的预取收益另行评估，不混入 G1 口径）；
  4. 配置注册表持久化 + 重启恢复 + 非法值回退。

### FR-PF-02 每卷策略面（P0）

- **描述**：`ReadAheadMB`（默认 16）产品化为用户可理解、可校验的配置。
- **详细要求**：
  1. WPF 缓存页每卷预读窗口下拉/滑块（建议档：关闭/8/16/32/64MB；对齐文档建议口径：小块随机为主选小窗、大块顺序选大窗——此处为卷级单一窗口，以负载实测为准）；
  2. CLI 同权；注册表 `Policies\<X>\ReadAheadMB` 持久化（既有结构）；
  3. 非法值（0 以外的越界/非 2 幂可选集）回退默认并日志；
  4. `MaxWriteIops`（默认 2000）暂维持内部策略，不暴露 UI（M1 范围控制，评估入 M2）。

### FR-PF-03 温度护栏产品化（P1）

- **描述**：将 `RbThermalPrefBlocked` 的内部阻断变为用户可见、可配置的健康策略。
- **详细要求**：
  1. WPF/日志可见：因温度停止预取的事件（卷、温度阈值、起止时间）；
  2. 阈值经注册表可配（默认继承 `rbthermal.c` 内建值，M1 不开放 UI 调节，先可观测）；
  3. 降温自动恢复（既有行为纳入验收，见 A-PF-5）；
  4. 与 PRD-01 L2 的温度叙事一致：预取与 L2 写入均不以 SSD 健康为代价。

### FR-PF-04 统计与效果可观测（P1）

- **描述**：`PrefIssued`（发出的预读作业数）/`PrefFillOk`（预读成功填充数）接入 WPF 缓存页与 CLI；新增"预取填充字节/命中字节"叙事指标（本次开机累计），支撑效果可感知（用户研究 R3：数字随使用增长本身是留存钩子）。
- **验收**：计数器与基准负载实际 IO 对账一致。

### FR-PF-05 与 L2 / 热区协同（P1）

- **描述**：把三个已有设施编成"开机即热"流水线：
  1. **预取 → L1**：预读作业经 `Rb2VolRead` 读下层盘 + `rb_read_commit` 入缓存（既有真预热路径，best-effort）；
  2. **L1 淘汰 → L2**：预取填充的热块（Hits≥2）在 L1 淘汰时流入 L2（PRD-01 FR-L2-01 接线后自然成立，本 PRD 负责验证该链路端到端）；
  3. **热区预热 → attach**：`RbHotSnapshot`（关机快照进注册表）+ `RbHotPrewarm`（attach 时预热）保持可用，作为 M2 启动预取的基础设施；
  4. 端到端验收：预热 → 重启 →（M2 起 L2 命中 + 热区预热）→ 顺序读第二遍吞吐。

### FR-PF-06 基准调优与默认值裁定（P0）

- **描述**：以基准库（内部基准 v1：影视顺序读、大文件拷贝、数据库扫描、游戏关包回放四类负载 × HDD/SSD/NVMe）裁定：默认 ReadAheadMB 去留（16 或调整）、冷却/分片参数是否需要暴露、G1–G3 达成性。
- **验收**：基准报告 + 默认值决策记录（数据驱动，禁止拍脑袋）。

### FR-PF-07 智能调优（P2，M2）

- **描述**：ReadAheadMB 按卷负载自适应（顺序流强度 × 命中率反馈），参考 Open CAS promotion 策略（nhit）与 Linux readahead 动态窗口思路；冷却/在飞上限参数化评估。

### FR-PF-08 启动预取（P2，M2）

- **描述**：开机后基于 L2 持久索引 + 热区注册表快照的主动预热流水线（对齐 PrimoCache 启动预取语义）；前置：PRD-01 M2（L2 多卷键/提升策略）与热区链路稳定。

## 4. 竞品对比分析（重点对标 PrimoCache）

### 4.1 PrimoCache 预取画像（事实来源：Romex 官网规格页/更新日志，2026-10-15 检索）

| 维度 | PrimoCache 事实 |
|---|---|
| 功能存在 | 规格页明列「Supports pre-fetching data into cache」；changelog：启动/空闲预取、**4.3.0 起 L2→L1 预取** |
| 语义 | 预热型（把常用/顺序后续数据提前搬进缓存），与 L2 持久化组合成「开机即热」付费理由 |
| 配合机制 | LFU+LRU 自调优淘汰 + 忙时采集间隔（L2）——预取与采集都避开系统忙时 |
| 已知边界 | 无进程/负载类型区分的预取开关（按卷统一）；顺序读场景的整体加速仍受"缓存空间 + 淘汰"制约（官方自认整体性能不如 RAMDisk 方案） |

### 4.2 正面对标（预取维度）

| 维度 | PrimoCache | RAMBlockCache M1 目标态 | 判定 |
|---|---|---|---|
| 顺序读预取 | ✅ 启动/空闲/L2→L1 | ✅ 倒流跟踪自动预取（代码已就绪） | 追平（机制不同：卷级地址流 vs 官方细节未公开） |
| 可配置性 | 按卷（缓存任务级） | 每卷 ReadAheadMB + 总/分卷开关 | 相当 |
| 温度/健康护栏 | 未见 | ✅ SSD 温度阻断预取 | **领先** |
| 效果可观测 | 统计面板（写入 L2/读取 L2 等） | PrefIssued/PrefFillOk + 填充字节叙事指标 | 相当 |
| 与 L2 组合 | ✅（4.3.0 L2→L1） | M1 自然流入（淘汰→L2）；M2 主动提升 | M1 追平、M2 对齐 |
| 随机读保护 | 依赖淘汰算法自平衡 | **硬门禁**：随机读退化 ≤5%、命中率不降 | 更严格的自我约束 |

### 4.3 GitHub 开源项目调研与可借鉴设计（检索时间 2026-10-15）

| 项目 | 可借鉴点（落入本 PRD 的位置） |
|---|---|
| **Linux readahead**（mm/readahead.c 主线） | 动态窗口、异步 pipelined read、per-file 流状态——本品为卷级地址流近似（无文件语义），FR-PF-07 自适应窗口的设计参照 |
| **bcache** | 顺序流检测与写合并的思路；miss 旁路不阻塞——本品预读 IRP 直发 LowerDevice 绕开顶层，同构的"不回环"纪律 |
| **Open CAS / OCF** | promotion 策略（always/nhit）——"多少热度才配被预取/提升"的行业参数化先例；FR-PF-07 与 PRD-01 FR-L2-11 共享 |
| **flashcache** | 早期 SSD 缓存的预取/预热实践与教训（预热放大读、无效预热治理）——G3 防污染门禁的来源 |
| **mhtvsSFrPHdE/prefetch**（用户态） | 反向证据：用户态预取受 OS 缓存机制制约、需手工配置——本品驱动级透明预取的差异化叙事 |

**调研结论**：预取算法在开源世界高度成熟（Linux readahead），但 Windows 卷级透明预取无可直接移植实现；本品的预取差异化不在算法新意，而在**与 L2/热区组合的「开机即热」叙事 + 温度护栏 + 硬门禁式的效果自证**。

## 5. 差异化亮点

1. **温度护栏**：SSD 超温自动停预取、降温自恢复、事件可见——把"预取可能伤盘"的隐性担忧变成可验证的健康策略（竞品无对应功能）。
2. **组合拳「开机即热」**：热区快照（关机）+ attach 预热 + L2 持久命中（PRD-01）+ 运行中顺序预取——四件套都是自研已落地件，组合叙事完整且边际成本低。
3. **效果自证的硬门禁**：顺序读 +20% 的同时承诺随机读零退化、命中率不降——用门禁约束自己，不做"预取刷分、随机读遭殃"的虚高。
4. **游戏场景双向安全**：预取加速缓存方式加载；DirectStorage 直通路径不受干扰（只读卷配置模板，竞品分析 8.3）；游戏模式一键切测试签名不受预取影响。
5. **低价 + 中文原生 + 现代 UI**：承接竞品定价卡位（¥39-69 vs $29.95），预取参数在 WPF 五页控制台直接可视可调。

## 6. 技术可行性初步评估

### 6.1 现状盘点（代码已验证）

- **算法与并发就绪**：倒流跟踪 + 链式判定 + ≥4 段触发 + 8MB 分片 + 在飞 ≤8（≤64MB 非分页）+ 2s 冷却；BUILD15 五项加固（引用计数/清理/链式/分片/策略缓存）已落盘。
- **回环防护就绪**：预读 IRP 直发 `ext->LowerDevice`，绕开本过滤设备顶层——预取不会递归触发自身。
- **IRQL 契约清晰**：`RbPrefStream` 由 PASSIVE worker 调用；自旋锁只护流表槽位，锁内无阻塞 API；扇出在锁外。
- **联动件就绪**：温度护栏、热区指纹、真预热通道（`Rb2VolRead`）、统计计数器。
- **部署安全**：`Flags=0` 时零开销空转，IRP 行为与 V10.2 字节等价——激活前合入不改变现网行为。

### 6.2 关键风险与技术债

| # | 风险 | 影响 | 化解 |
|---|---|---|---|
| R1 | **预取污染**：顺序流数据挤占缓存、淘汰热数据，随机读命中率下降 | G3 不过、老用户体感变差 | G3 硬门禁（-2pp 红线）；冷却 + 分片上限已内置；不过门不回默认开 |
| R2 | **慢盘上的在飞堆积**：HDD 上 8×8MB 在飞 + 深队列，随机读被挤 | G2 不过 | 每卷 ReadAheadMB 可调；基准含 HDD 场景；必要时按卷类型默认差异化（FR-PF-06 裁定） |
| R3 | **无效预取放大读**：流判定误触发（如跳跃式扫描被当顺序） | SSD 额外读、功耗/寿命 | 链式判定（首尾相接）已收紧；PrefFillOk/PrefIssued 比率观测；M2 自适应窗口 |
| R4 | **温度护栏阈值失当**：阈值过低误停/过高失效 | 效果或健康二选一失败 | M1 先可观测不调阈；阈值评估入 M2；护栏事件日志先行 |
| R5 | **与 L2 接管的交互未验**：预取块→淘汰→L2 链路端到端无数据 | 「开机即热」叙事落空 | FR-PF-05 端到端用例（依赖 PRD-01 接线）；M1 先验 L1 段，L2 段随 PRD-01 M1 交付联验 |
| R6 | **验证债**：本机无工具链，一切未经编译/真机 | 同上（PRD-02 R1） | 排期在 Gate 0 后；无 Verifier 证据不合并 |

## 附录 B · 术语

- **倒流跟踪**：按"上次读结束地址 == 本次读起始地址"判定连续段（BUILD15 PREF-3 修复后语义）。
- **在飞上限**：全局同时预读作业 ≤8、单作业 ≤8MB → 非分页突发 ≤64MB。
- **真预热**：`Rb2VolRead` 直读下层盘并 `rb_read_commit` 入缓存（区别于仅标记）。
- **热区指纹**：`rbhot.c` 的 1MB 粒度访问频率衰减表，关机快照进注册表。
