# 04 数据安全与防蓝屏（务必阅读）

## 一、先说结论

1. **缓存是"加速层"，不是"数据备份"**。任何缓存类软件（含 PrimoCache）
   都不能替代备份。重要数据请定期备份。
2. 本项目为数据安全做了多层设计（下面详述），**脏数据永不因内存淘汰丢失**，
   **句柄关闭即回写**，**卸载前全量回写**。
3. 但仍存在理论风险：突然断电/内核崩溃瞬间可能丢失"已写入缓存但还没落盘"
   的最后一批数据（回写模式固有属性，PrimoCache 回写模式同理）。
   **介意这点的人请用"直写模式"**（控制台关掉回写模式开关即可，写数据直接落盘）。

## 二、本驱动的数据安全设计

| 机制 | 说明 |
|---|---|
| **全内存写优先** | 写入**全部先进内存**（写缓存模式）：完整覆盖子块直接写缓存置脏；部分覆盖且缓存有旧数据原地合并；部分覆盖且无旧数据经 readback 读盘补齐缺口（RMW）——数据正确性优先，无缺口才吸收 |
| **脏块不淘汰** | LRU 只淘汰**干净**缓存块；脏数据永远保留在内存直到回写成功，杜绝"静默丢写" |
| **余量分级整理（≥80%）** | 缓存占用到 80% 水位自动整理：①不常调用且干净的临时缓存块直接丢弃（纯内存数据，不写盘）；②非临时脏数据按"脏量多 → 少、读写顺序"依次回写，回写后变干净下一轮淘汰释放内存。全程流锁内串行，不阻塞新读写 |
| **硬上限写满保护（95%）** | 占用到 95% 硬上限：新写入改为直写兜底（直接落盘），**宁可牺牲一点加速也绝不把内存写爆、绝不丢数据** |
| 句柄关闭强制回写 | 应用关闭文件句柄（CLEANUP）时，该文件全部脏数据立即写回磁盘 |
| 应用主动刷新 | 应用调用 FlushFileBuffers / 控制台"立即回写"→ 全量写回 |
| 后台水位回写 | 脏数据到高水位（默认 60%）强制回写至低水位（40%），防止内存爆满 |
| 合并大块回写 | 脏子块按连续段合并成最大 4MB 写盘，减少 SSD 写放大（护寿命） |
| 直写兜底 | 无法安全缓存的写（readback 缺失/失败、或硬上限已满）直接落盘，不伪造成功 |
| 读不覆盖脏数据 | 读盘回填缓存（commit）绝不覆盖已脏子块，保护未回写数据 |
| 卸载先回写 | 卸载脚本先 flush 再卸载；驱动卸载回调也会全量回写 |
| **关机保存** | 驱动注册系统关机通知（IRP_MJ_SHUTDOWN）：正常关机/重启前**全量回写所有脏数据**，关机不丢缓存 |
| 系统卷默认不缓存 | 默认不缓存 C 盘（系统盘 IO 最复杂、最不该碰），要开需手动开启 |
| 分页 IO 不拦截 | 系统缓存（Cache Manager）自身的回写放行，避免"双重缓存"互相打架 |

## 三、防蓝屏设计

| 机制 | 说明 |
|---|---|
| **安全模式（蓝屏识别修复）** | 驱动在注册表记录"上次是否正常退出"。异常退出（蓝屏/断电/强杀）后下次启动**自动进入安全模式**：写缓存关闭、一切写入直写落盘（读缓存保留，仍可加速且不丢数据）；控制台顶部显示红色横幅，用户确认系统稳定后一键"恢复写缓存" |
| 全路径错误放行 | 缓存/回写任何一步失败（内存不足、磁盘错误），驱动**放行原 IO 走系统路径**，不返回伪造成功 |
| 同步串行化 | 每个文件流一把锁，核心不持锁、驱动加锁，避免并发竞态 |
| 引用计数释放 | 流上下文与回写线程之间用引用计数，杜绝"使用已释放内存" |
| 回写/读盘 IO 防递归 | 驱动回写与 RMW 读盘都用底层文件对象（无缓存上下文），不会再次进缓存（防无限循环） |
| 只附加 NTFS | 非 NTFS 卷直接不附加（少一类兼容面） |
| 保守的内存分配 | 缓存块 64KB/子块 4KB 固定大小，非分页池；分配失败即放行，不硬撑 |
| 硬上限保护 | 占用 95% 即新写直写，缓存引擎永不因写满崩溃 |
| 测试先行 | 缓存核心在 Linux 上跑了 13 个一致性用例（含 RMW/余量整理/硬上限）+ AddressSanitizer 无内存错误 + 4 流 × 7500 次随机读写多流并发压力全部一致，逻辑层可信 |

## 四、真实风险与免责

- **内核驱动在测试阶段仍有蓝屏可能**（尤其在不同机器/不同文件系统行为下）。
  本驱动未经过微软 WHQL 认证，属"自用测试软件"性质。
- 首次部署建议：先只缓存一个**非重要的数据卷**（例如 D 盘），观察 1~2 天
  正常后再扩大到其他卷。
- 回写模式下，**不要在写入后立刻拔电源**（跟任何回写缓存一样）。
- 出现蓝屏：重启 → 按 `04` 末尾的卸载流程卸载，然后查看
  事件查看器 → Windows 日志 → 系统，把蓝屏代码发给我排查。
- 使用本项目即表示你已知悉并接受上述风险。

## 五、出问题时的急救流程

```bat
# 1. 重启进入系统后，管理员运行（先回写再卸载）
scripts\uninstall.cmd

# 2. 如需关闭测试签名模式
bcdedit /set testsigning off
```

如果进不了系统：进入安全模式（WinRE → 疑难解答 → 启动设置 → 安全模式），
再执行上面步骤。驱动默认**手动启动**（start=demand），不会在开机时自动加载，
因此安全模式下系统可以正常进入。

### 蓝屏后的自动识别与恢复（安全模式）

1. 蓝屏/断电/强杀后重启，驱动加载时检测到"上次非正常退出"，
   **自动进入安全模式**（写直写，不丢任何已确认写入的数据）。
2. 打开控制台（WPF 程序 `dist\wpf\RAMBlockCache.Controller.exe`；**本包未提供 `scripts\serve.cmd`**），顶部出现红色**安全模式横幅**。
3. 确认系统运行稳定、数据无误后，点横幅上的**"恢复写缓存"**
   （或命令行 `ramboostctl safe-mode off`），即恢复全部加速。
4. 之后正常关机/卸载会记录"干净退出"，下次启动不再进入安全模式。
