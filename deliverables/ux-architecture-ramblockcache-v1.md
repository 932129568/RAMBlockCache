## 1. 设计目标与原则

### 1.1 一句话目标
**把"驱动级真相"翻译成"用户级结论"**：用户不需要理解 Bound / Attached / WriteMode / PanicEpoch，只需要随时能回答三个问题——*现在有没有在加速？安不安全？出问题怎么退回去？*

### 1.2 六条设计原则

| # | 原则 | 具体要求 | 反面（现状） |
|---|---|---|---|
| P1 | **结论优先** | 界面只呈现判定结果（"D: 正在加速 · 直写"），原始字段降级到"诊断"页 | 直接暴露 attached=1 bound=1 writeMode=2 等原始字段 |
| P2 | **状态单一事实** | 全局状态条 + 每卷状态卡，二者用同一套状态机与同一套文案 | 同一状态在导航、卡片、日志三处说法不同 |
| P3 | **动作可逆** | 每个"开启/挂载"动作旁必须有对应"停止/卸载"，且入口相邻 | 卸载散落在别处，应急时找不到 |
| P4 | **失败可解释** | 错误必须回答"发生了什么 / 为什么 / 下一步做什么"三段式 | 一律"驱动未加载"（实为权限不足） |
| P5 | **渐进披露** | 默认只给 3 个数字（命中率 / 省下 IO / 缓存占用），细节折叠 | 64 个 stripe 指标与脏量混在同一页 |
| P6 | **一键回到安全态** | 任何异常下，用户可在 1 次点击内进入"全局透传"（熔断），且知道数据不会丢 | 熔断入口此前完全不可达 |

## 2. 用户与核心任务（JTBD）

| 角色 | 典型场景 | 核心任务（JTBD） | 成功判据 |
|---|---|---|---|
| **性能用户**（玩家 / 开发者） | 游戏装在 D:、编译缓存在 F: | "让这两块盘明显更快，我要看到证据" | 3 分钟内完成配置并看到命中率/延迟改善 |
| **办公用户**（被推荐安装） | 只想电脑快一点，不懂缓存 | "别把我电脑搞坏，出问题能退回去" | 全程无需理解术语；异常时有明确下一步 |
| **运维 / IT** | 批量部署到多台机器 | "可批量、可审计、可回滚" | 单一安装入口 + 回滚路径可文档化 |

**结论**：三类角色的共同刚需不是"更多参数"，而是 **确定感**（状态确定 / 结果确定 / 退路确定）。

## 3. 断点诊断（8 条，均有审计实证）

| # | 断点 | 实证（审计/代码） | 体验后果 | 影响面 |
|---|---|---|---|---|
| B1 | **安装入口语义互斥** | `install.cmd → install.ps1`（UpperFilters + BOOT_START 挂栈）与 `setup/ramboostsetup.ps1`（NEVER UpperFilters + demand-start）两套哲学并存；入口链曾断在废弃脚本 | 用户不知道"我到底装了没有"；"免重启"承诺与"需重启挂栈"事实冲突 | 100% 新用户 |
| B2 | **五个状态散落** | `Bound`(挂栈) / `Attached`(加速) / `WriteMode` / `SafeMode` / `PanicActive` 分散在卷列表、统计、banner | 无法一眼判断"盘现在什么情况"；误以为没生效而反复点击 | 100% |
| B3 | **写模式不可见不可改** | `MainWindow.xaml` 无写模式控件；默认值曾为回写（P1-11） | 用户无法选择直写/回写，也无法知道当前用哪种 | 100% |
| B4 | **危险操作无护栏** | 一键熔断/缓存 C: 盘无影响说明、无二次确认（P1-10 刚补入口） | 误触熔断后不知所措；或不敢用（等于没有） | 应急场景 |
| B5 | **无收益反馈** | 首页只显示"已挂载 N / 平均命中率"；无"省下多少磁盘 IO / 延迟变化" | 用户感受不到价值，装完即忘、后续卸载 | 留存 |
| B6 | **回滚路径用户不可达** | `offline_rollback.cmd` 需 WinRE 手工执行；UI 无任何指引（P1-9 修了脚本正确性，未修可达性） | 0x7B 时用户在无网环境找不到出路 → 重装系统 | 极端但致命 |
| B7 | **错误语言不统一** | CLI 曾把 `ERROR_ACCESS_DENIED` 报成"驱动未加载"（P2-5 已修文案）；UI 仍只显示 `ex.Message` | 用户按错误提示操作（重装驱动）反而更糟 | 高频 |
| B8 | **版本三轨显示** | `1.1 Build19`（驱动上报）/ `10.3.4.19`（机器版本）/ `V10.4.3 Build 19`（发布名）同时出现在 UI 与 CLI（P2-10 部分收敛） | 用户无法判断"要不要升级" | 支持成本 |

| — | **首次配置向导**（独立全屏流程） | 新增（B1/B3）：一次性把挂栈、卷选择、写模式讲清楚 |

### 4.2 常驻全局状态条（新增，解决 B2）

位于窗口顶部，四段式，永远可见：

```
[ 驱动 ● 已连接 v10.3.4.19 ]  [ 挂栈 ● 已挂 2 卷 ]  [ 加速 ● 1 卷直写 / 1 卷回写 ]  [ 风险 ● 无 ]
```

- 四段任一异常 → 该段变琥珀/红，并成为可点击入口（点击直接跳到对应处置页）。
- 风险段取值：`无` / `有未落盘数据 N MB` / `安全模式（上次异常退出）` / `熔断中（全局透传）`。
- 状态条是 P2（状态单一事实）的载体：它与每卷状态卡共用同一状态机与文案表（§5）。

## 5. 状态模型（统一状态机）

### 5.1 六个用户态（取代原始字段）

| 用户态 | 判定依据（驱动字段） | 一句话文案 | 颜色语义 | 主行动 | 禁止动作 |
|---|---|---|---|---|---|
| **未安装** | 控制设备打开失败（错误 2/3） | "未检测到 RAMBlockCache 驱动" | 灰 | 打开安装指引 | 挂载/调优 |
| **已安装未挂栈** | 打开成功但无 Bound 卷 | "驱动已就绪，尚未挂到任何卷" | 蓝 | 运行首次向导 / 重启挂栈 | — |
| **就绪未加速** | Bound 且 `Attached=0` | "D: 已挂栈，未开启加速" | 蓝 | 开启加速 | — |
| **加速中 · 直写** | `Attached=1` 且 `WriteMode=0` | "D: 正在加速（直写，最安全）" | 绿 | 切回写（需确认） | — |
| **加速中 · 回写** | `Attached=1` 且 `WriteMode=1` | "D: 正在加速（回写，异常退出可能丢未落盘数据）" | 绿 + 琥珀角标 | 查看脏量 / 立即回写 | 关机前不提示 |
| **降级 · 安全模式** | `SafeMode=1` | "上次未正常退出，已强制直写保护数据" | 琥珀 | 确认数据无误 → 退出安全模式 | 静默恢复回写 |
| **熔断 · 全局透传** | `PanicActive=1` | "熔断中：所有读写直接到盘，缓存暂停（数据最安全，速度最慢）" | 红 | 解除熔断（自愈完成后可用） | 直接恢复加速（须先等自愈） |

> 颜色语义说明：本产品为**非金融场景**，沿用通用语义 **红=需立即处理 / 琥珀=降级但可用 / 蓝=就绪待配置 / 绿=正常工作**。

### 5.2 状态迁移图（用户视角）

```
未安装 ──安装──▶ 已安装未挂栈 ──挂栈/重启──▶ 就绪未加速 ──开启加速──▶ 加速中(直写)
                                                    ▲                    │
                                                    │                    ├─切换─▶ 加速中(回写)
                                                    │                    │            │
                                                    └────停止加速────────┘            │异常退出
                                                                                     ▼
     熔断(透传) ◀──自动熔断/手动一键── 加速中(任意) ──检测异常──▶ 降级·安全模式
         │                                                              │
         └──解除熔断(需自愈完成)──▶ 就绪未加速 ◀──确认数据无误──────────┘
```

**关键设计决策**：`解除熔断` 按钮在自愈未完成时**不可点**（置灰 + 悬停说明"正在把未落盘数据写完，请稍候"），而不是点了报错。驱动侧已实现 epoch 握手（P0-3），UI 只需把该状态如实可视化。

## 6. 核心旅程重设计

### J1 首次安装（解决 B1）

| 步 | 界面 | 内容 | 完成判据 |
|---|---|---|---|
| 1 | 环境自检卡 | 管理员权限 / 驱动是否已装 / 是否存在残留 UpperFilters / 是否需要重启 | 四项全绿或给出修复按钮 |
| 2 | 安装方式二选一（**唯一入口**） | 推荐：**标准模式**（挂栈 + 可缓存任意卷，含系统卷，需一次重启）；备选：**保守模式**（不挂栈、运行时挂载、无需重启，但开机过程不加速） | 用户显式选择，文案写明差异与回滚方式 |
| 3 | 首次加速 | 列出可加速卷，默认勾选**非系统数据卷**，写模式默认**直写**并解释"想更快可改回写，代价是异常退出可能丢未落盘数据" | 至少 1 卷进入"加速中" |

> 与实现对齐：`install.cmd → install.ps1` 作为标准模式唯一入口（P1-7 已修）；`ramboostsetup.ps1` 在 UI 中显式命名为"保守模式"，不再让用户面对两个互斥的 .ps1/.cmd 自行猜测（P1-8 已在脚本头部标注，UI 层需跟进）。

### J2 开启加速（解决 B3）

选卷 → 写模式（默认直写）→ **即时验证**：动作完成后 3 秒内卡片必须显示"已加速 · 命中率 xx%"，而不是等用户自己找统计页。

### J3 日常监控（解决 B2/B5）

首页三数字（命中率 / 省下磁盘读 / 缓存占用）+ 全局状态条 + 每卷一行状态卡（状态文案 + 主行动）。

### J4 性能调优（解决 B3/B5）

写模式切换控件（每卷）+ 内存预算（全局，`AutoUsePct`/`MemReserveMB`）+ 效果对比（切换前后 5 分钟命中率与吞吐对比）。

### J5 故障应急（解决 B4/B6）

```
① 触发（自动熔断或用户点"一键熔断"）
   └ 确认弹窗：影响说明（读写将直接到盘、速度下降、未落盘数据会由后台写完）
② 状态条转红 + 首页出现"应急处理"卡
   └ 卡片内容：当前是否有未落盘数据（DirtyBytes / LostDirtyBytes）、自愈进度
③ 解除熔断（自愈完成后可点）→ 恢复加速
④ 若数据可疑：提供"核对丢失量"入口（LostDirtyBytes 与日志时间线）
```

### J6 卸载与回滚（解决 B6）

| 场景 | 入口 | 内容 |
|---|---|---|
| 正常卸载 | 设置页 | 停止加速 → 回写全部脏数据 → 移除 UpperFilters（保留第三方过滤器）→ 提示重启 |
| 开机失败（0x7B） | **应急页固定区块 + 可导出的救援卡** | 三步图文：进入 WinRE → 定位系统盘 → 运行 `offline_rollback.cmd`（含"该脚本会保留其他卷过滤器"的说明） |
| 救援卡导出 | 应急页按钮 | 生成 `救援说明.txt`（含命令与脚本路径），便于在无网、无法进系统时使用 |

## 7. 页面与组件重规划

每页必须同时定义 **正常态 / 空态 / 加载态 / 错误态 / 危险操作**（现状四态全缺）。

### 7.1 状态（首页）

| 项 | 设计 |
|---|---|
| 目的 | 3 秒回答"现在有没有在加速、安不安全" |
| 关键组件 | 全局状态条（常驻）· 三数字摘要卡 · 每卷状态卡（状态文案 + 主行动）· 异常提示卡（仅异常时出现） |
| 空态 | "尚未加速任何卷 → 运行首次向导"（不是空白页） |
| 加载态 | 状态条显示"正在读取驱动状态…"，卡片骨架屏 |
| 错误态 | 三段式卡片（见 §8.1）+ "重试"与"打开诊断"两个按钮 |
| 危险操作 | 一键熔断（红色按钮 + 确认弹窗 + 影响说明） |

### 7.2 加速

| 项 | 设计 |
|---|---|
| 目的 | 逐卷开启/停止加速，选择写模式 |
| 关键组件 | 卷列表（盘符 / 卷标 / 容量 / 状态 / 写模式选择 / 开关）· 批量操作 · 写模式说明气泡 |
| 空态 | "未检测到可加速卷" |
| 危险操作 | 缓存系统卷 C: → 明确风险提示 + 二次确认（写清"若开机异常可用应急页回滚"） |

### 7.3 收益

| 项 | 设计 |
|---|---|
| 目的 | 让用户"看见价值"（B5） |
| 关键组件 | 命中率趋势（近 5 分钟）· 省下磁盘读字节 · 平均延迟（若可得）· 缓存占用/上限 · 脏量与回写速率 |
| 披露层级 | 一级：3 个数字；二级（折叠）：64 stripe、rmw_reads、trim_count、pressure_level |
| 错误态 | 采样失败时显示"统计暂不可用（原因）"，不显示 0（避免误读为"没生效"） |

### 7.4 诊断

| 项 | 设计 |
|---|---|
| 目的 | 出问题时自助定位；支持人员取证 |
| 关键组件 | 驱动日志（自动拉取，不再要求用户手动点"拉取"）· 自检清单（驱动版本 / 协议 / 挂栈状态 / UpperFilters 实际值 / 是否安全模式）· 版本单轨展示 · 一键导出诊断包 |
| 空态 | "暂无日志" |
| 错误态 | 拉取失败给出可操作提示（权限 / 未加载 / 超时三类，见 §8.1） |

### 7.5 应急（新增）

| 项 | 设计 |
|---|---|
| 目的 | 危险与故障时的唯一去处（B4/B6） |
| 关键组件 | 熔断开关 + 影响说明 · 解除熔断（自愈完成才可点）· 退出安全模式 · 未落盘/丢失量核对 · **回滚指引三步图** · 导出救援卡 |
| 危险操作 | 熔断 / 退出安全模式 / 回滚指引均需"影响说明 + 确认" |

### 7.6 设置

| 项 | 设计 |
|---|---|
| 关键组件 | 全局启用 · 内存预算（自动/固定 + 保留量）· 回写间隔 · 开机自动挂载 · 随 Windows 启动 · 卸载入口（含 UpperFilters 恢复说明） |
| 危险操作 | 卸载需二次确认并说明"会保留第三方卷过滤器" |

### 7.7 全局组件规范

| 组件 | 规范 |
|---|---|
| 状态徽标 | 只允许 6 态文案（§5.1），颜色与文案一一绑定，禁止临时文案 |
| 确认弹窗 | 三段式：**将发生什么 / 影响与风险 / 如何撤销**；危险按钮不做默认焦点 |
| 进度反馈 | 超过 1 秒的动作必须有进度或"正在…"文案（自愈、回写、卸载均属此类） |
| 禁用态 | 禁用必须给出原因（悬停/副文本），不允许"点了没反应" |
| 术语 | 面向用户只允许用：挂栈、加速、直写、回写、熔断、安全模式、命中率、未落盘数据 |

## 8. 文案与语言规范（解决 B7/B8）

### 8.1 统一错误语言（三段式）

格式：**发生了什么 → 为什么 → 下一步做什么**

| 场景 | 现状（问题） | 目标文案 |
|---|---|---|
| 打开控制设备失败 · 错误 5 | "无法连接驱动（驱动未加载或未提权）" | "没有权限访问缓存驱动。原因：控制设备仅允许管理员访问。下一步：右键以管理员身份运行本程序。" |
| 打开控制设备失败 · 错误 2/3 | 同上（误报为未加载） | "未检测到缓存驱动。原因：驱动未安装或未启动。下一步：点击『运行安装向导』。" |
| 协议不匹配 | "协议不匹配：驱动 vX，控制台 vY" | "驱动版本与控制台不匹配（驱动 vX / 控制台 vY）。原因：安装包与控制台不是同一版本。下一步：使用同一发布包重新安装。" |
| 解除熔断被拒 | 仅日志 | "暂时不能解除熔断。原因：驱动正在把未落盘数据写完（自愈中）。下一步：等待状态条风险段变为『无』后重试。" |
| FLUSH 失败 | 静默/仅日志 | "数据尚未完全写入磁盘。原因：磁盘报告写入错误。下一步：检查磁盘健康；未落盘数据仍在缓存中，可稍后重试。" |
| 卷几何未就绪 | "设备未就绪" | "该卷尚未准备好。原因：卷信息仍在读取中。下一步：稍候几秒后重试，或重启一次。" |

### 8.2 版本单轨呈现（B8）

- **面向用户只显示一个版本**：发布名 + 机器版本，例如 `RAMBlockCache V10.4.3 Build 19（10.3.4.19）`。
- 驱动上报的内部三段号（`1.1 Build19`）只出现在**诊断页**，并标注"驱动内部版本（用于支持排查）"。
- 生成源：`common/version.h` → `gen_version.ps1` → 两棵 UI 树的 `Version.cs`（已在修复轮落地）；禁止任何界面硬编码版本串。

### 8.3 禁止术语表（面向用户界面）

| 禁止 | 替换 |
|---|---|
| Bound / Attached / IsAttached | 已挂栈 / 正在加速 |
| WriteMode=2 / RB_WRITEMODE_GLOBAL | 跟随全局设置 |
| PanicPassthrough / PanicEpoch | 熔断中 / 自愈进度 |
| DirtyBytes / LostDirtyBytes | 未落盘数据 / 已确认丢失数据 |
| UpperFilters | （仅设置/诊断页可出现，附一句解释）"卷过滤链配置" |

## 10. 体验度量（上线后跟踪）

| 指标 | 定义 | 目标 |
|---|---|---|
| 首次成功加速率 | 安装后 10 分钟内至少 1 卷进入"加速中"的比例 | ≥ 90% |
| 首装失败可解释率 | 安装失败时用户能看到三段式错误的比例 | 100% |
| 状态判断耗时 | 用户打开 UI 到能说出"是否在加速"的观察耗时 | ≤ 3 秒 |
| 应急可达性 | 熔断/回滚指引在 UI 内的点击深度 | ≤ 2 次点击 |
| 回滚成功率 | 0x7B 场景按救援卡操作后恢复开机的比例 | ≥ 95% |
| 支持工单归因 | 因"不知道装没装/没生效"产生的咨询占比 | < 10% |

## 11. 落地路线图与验收

### 第一期（体验骨架，可与驱动修复同批发布）
1. 全局状态条（四段式）+ 状态机文案表（§5.1）落为单一实现，所有页面共用。
2. 首页改造：三数字 + 每卷状态卡 + 主行动。
3. 加速页补**写模式控件**（默认直写，回写需确认）。
4. 错误文案统一为三段式（§8.1），含 CLI 与 UI 两侧。

### 第二期（闭环与应急）
5. 应急页：熔断确认弹窗、解除熔断（自愈完成后可点）、退出安全模式、未落盘/丢失量核对。
6. 回滚指引三步图 + 导出救援卡。
7. 诊断页：日志自动拉取、自检清单、版本单轨、导出诊断包。
8. 首次配置向导（环境自检 → 模式二选一 → 首次加速）。

### 第三期（价值感知与规模化）
9. 收益页：命中率趋势、省下 IO、切换前后对比。
10. 内存预算与压力可视化；批量部署文档（对应运维角色）。
11. 体验度量埋点（§10）。

### 验收标准（与真机验收 T1–T6 对齐）

| 体验验收项 | 对应 | 通过标准 |
|---|---|---|
| U1 | B1 | 全新机器上仅按首页向导即可完成安装并加速，全程无需读文档 |
| U2 | B2 | 任意时刻状态条能唯一表达"是否加速 / 是否安全 / 有无风险" |
| U3 | B3 | 用户可在加速页切换直写/回写，且回写时能看到"异常退出风险"说明 |
| U4 | B4 | 熔断前后各出现一次影响说明；解除熔断在自愈未完成时置灰并说明原因 |
| U5 | B5 | 首页可看到"省下磁盘读"数值且随使用增长 |
| U6 | B6 | 应急页能导出救援卡；按救援卡可在 WinRE 完成回滚（T5 联动验证） |
| U7 | B7 | 三类连接失败分别给出可区分的三段式文案 |
| U8 | B8 | 任一界面只出现一个用户可见版本串 |

> 说明：本设计为**体验架构方案**，落地需在 Controller（WPF）侧按 §7 逐页实施；其中状态条与文案表建议先做成 `UiState` 单一映射（一处定义状态→文案→颜色→主行动），避免再次出现"同一状态多种说法"。
