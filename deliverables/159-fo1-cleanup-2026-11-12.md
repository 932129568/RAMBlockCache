## §2 为什么第 1–3 条是工具误报（不是代码缺陷）

原来是：

```python
cand = {}
try:
    m = re.search(PAT, DEPLOY_PS1.read_text(...))
    if m: cand["deploy.ps1"] = m.group(1).lower()
except OSError:
    pass                       # ← 工具在此报 FO1
missing = [n for n in ("deploy.ps1", "dist sidecar",
                       "verify_deploy_signature.ps1") if n not in cand]
if missing:
    return "", "missing anchors: " + ",".join(missing)   # ← 真正的 fail-closed
```

读失败 ⇒ `cand` 没有该键 ⇒ `missing` 非空 ⇒ 返回错误 ⇒ 调用方判 A 失败。**异常分支的 `pass` 完全被下游接住了**，判据从未因此放松。工具只做单条 `except` 的局部 AST 判定，不做跨语句数据流分析，所以看不见这条链路。

**处置原则：不修工具、不为了消警糊 print，而是把"失败局部化"写明显。**

## §3 逐条改动

### 3.1 `d3_verify_after_reboot.py` — `anchor_pin()` 前 38 行

引入局部读取器，把"读不到"折叠成空串，让正则自然不匹配：

```python
    def _read(path, enc):
        # An unreadable anchor file is NOT swallowed here: it yields an empty
        # string, so the regex below fails to match and the anchor lands in
        # `missing`, which returns an error -> the caller fails closed.
        try:
            return path.read_text(encoding=enc, errors="replace")
        except OSError as e:
            return ""  # -> missing anchor -> fail closed downstream

    cand = {}
    m = re.search(r"DefaultExpectedSha256\s*=\s*'([0-9a-fA-F]{64})'", _read(DEPLOY_PS1, "utf-8"))
    if m:
        cand["deploy.ps1"] = m.group(1).lower()
    sidecar_lines = _read(DIST_SIDECAR, "ascii").splitlines()
    m = re.search(r"([0-9a-fA-F]{64})", sidecar_lines[0]) if sidecar_lines else None
    if m:
        cand["dist sidecar"] = m.group(1).lower()
    m = re.search(r"DefaultExpectedSha256\s*=\s*'([0-9a-fA-F]{64})'", _read(VERIFY_PS1, "utf-8"))
    if m:
        cand["verify_deploy_signature.ps1"] = m.group(1).lower()
```

**语义等价性证明（必须看的三个分支）**：

| 情形 | 改前 | 改后 |
|---|---|---|
| 文件存在且格式正确 | `cand` 有该键 | 同 |
| 文件读不到（OSError） | `pass` → `cand` 无该键 → `missing` 命中 → 返回错误 | 空串 → 正则不匹配 → `cand` 无该键 → 同 |
| sidecar 是空文件（原 `IndexError`） | `splitlines()[0]` 抛 → `pass` → 无键 → `missing` 命中 | `sidecar_lines` 为空 → `None` → 无键 → 同 |

**实测**（真仓库上直接调该函数，非真机探针）：

```
pin    : c7f0a55a744a9fe32a8319c8cfca680dd83649e8d8c81171b3f9808f7e1ffc82
anchors: deploy.ps1+dist sidecar+verify_deploy_signature.ps1
```

返回值 = **当前已部署**镜像的 sha（`c7f0a55a`），三锚点一致 —— 这是正确行为：新构建 `048478c2` 尚未部署，三个锚点当然还指向旧的。函数被重构后仍能正常解析并保持一致。

### 3.2 `d3_verify_after_reboot.py` — `wait_bridge()`

```python
    last_err = None
    while time.time() < deadline:
        try:
            with urllib.request.urlopen(BASE + "/rb/health", timeout=4) as r:
                if json.loads(r.read().decode()):
                    return True
        except Exception as e:
            last_err = e          # 轮询：连接被拒是任务未起的正常态，但保留证据
        time.sleep(3)
    if last_err is not None:
        print("wait_bridge: last error %r" % (last_err,), flush=True)
    return False
```

下游 `return False` 本来就是 fail-closed（调用方拿 False 会判失败），改动只增加可诊断性，**判据不变**。
