## 三、建议的产品成功指标体系

### 3.1 North Star 指标

> **周活跃设备的周缓存命中读取数据量（Cache-Served Read Volume per WAU Device）**

定义：统计周期内，所有周活跃设备（WAU，即当周至少成功挂载过一个缓存卷的设备）从缓存命中并完成服务的读数据总量 ÷ WAU 设备数。

为什么是它：
- 同时承载**采用**（装机且缓存启用）、**活跃**（持续使用被缓存卷）、**价值**（命中数据量=用户实际获得的加速量）三个维度，单一指标无法靠单一动作刷高（刷命中率会牺牲数据量，刷数据量会暴露命中率问题）。
- 与商业目标一致：命中数据量越高，用户感知的"加速价值"越强，留存与付费转化（如有）越稳固。

目标区间（初始冷启动目标，待首批遥测数据校准）：以 8GB 缓存配置、日均 2 小时活跃的桌面用户估算（**估计**），单设备周命中读取量落在 **20-60 GB** 区间视为健康水位；低于 10 GB 说明缓存未进入用户热路径，高于 150 GB 需核查是否写缓存被计读或工作负载特殊。

### 3.2 KPI 树

```
North Star：周活跃设备周命中读取数据量
├── A. 价值实现层（缓存命中与加速）
│   ├── A1 读命中率（块级）
│   ├── A2 写合并率（回写模式脏块合并比）
│   ├── A3 应用可感知加速比（P50/P95 读延迟降幅）
│   └── A4 热路径覆盖率（用户高频访问文件在缓存中的比例，估计口径待定）
├── B. 可靠与信任层（内核产品的生死线）
│   ├── B1 归因本驱动的蓝屏率 / 崩溃率
│   ├── B2 数据安全指标：LostDirtyBytes 非零事件数、FLUSH 失败穿透率
│   ├── B3 部署成功率（install 单路径）与卸载干净率
│   └── B4 panic 熔断恢复握手成功率
├── C. 增长层（采用与留存）
│   ├── C1 装机量（累计安装 / 月新增）
│   ├── C2 WAU/MAU 与功能启用率（缓存卷启用、游戏模式、空闲释放）
│   └── C3 留存：D1 / D7 / D30 与"缓存持续启用率"
└── D. 经济层（如引入付费）

    └── D3 内存占用成本（用户为缓存让出的 GB 数 × 机会成本，叙事指标）
```

### 3.3 指标定义卡（定义 / 目标区间 / 测量方式）

#### A1 读命中率（块级）
- **定义**：命中缓存的读 I/O 块数 ÷ 总读 I/O 块数（分卷、分时段、分块大小统计；只计应用读，不计驱动内部补读）。
- **目标区间**：日常桌面负载 **70%-90%**；新装设备前 7 天允许 30%-60%（预热期）；**>95% 需警惕**——对照 2.6 节，竞品在短时基准下轻易达到 97-100%，若真实负载也 >95%，先核查统计口径是否把内部 I/O 计入了分母。
- **测量**：驱动 `RB_STATS`（已有 GET_STATS 通道）+ 用户态 StatsService 聚合；建议增加匿名遥测上报（见 §3.4）。

#### A2 写合并率（回写模式）
- **定义**：回写模式下，被合并进缓存未即时落盘的写块中最终只落盘一次的比例 = 1 -（落盘写块数 ÷ 收到的写块数）。
- **目标区间**：回写开启时 **40%-70%**（估计，依据桌面写负载的重复性；首批遥测后校准）。
- **测量**：cache.c 脏块计数与落盘计数差值；与 A1 一起决定"加速比"叙事。

#### A3 应用可感知加速比
- **定义**：同一真实工作负载（游戏关卡加载、IDE 首次构建、浏览器冷启动集合）在缓存启用前后的 P50/P95 读延迟之比；辅以随机 4K 读 IOPS 提升倍数。
- **目标区间**：P95 读延迟下降 **30%-60%**（混合 SSD/HDD 场景可更高）；4K 随机读 IOPS 提升 **3-10 倍**（物理上限参考：延迟差约 1000 倍，带宽差约 5-10 倍，实际受命中率与负载稀释）。**明令禁止**用大文件顺序读写作为宣传指标（带宽约束下 SSD 本身已够快，且会落入 2.6 节竞品被质疑的"跑分魔术"陷阱）。
- **测量**：`scripts/benchmark.ps1` + diskspd 前后对照 + 用户场景脚本化回放；发布前建立内部基准库。

#### B1 归因本驱动的蓝屏率 / 崩溃率
- **定义**：单位设备-月中，崩溃转储可归因于 RAMBlockCache.sys 的蓝屏事件数。
- **目标区间**：**0**（内核产品无"可接受崩溃率"）；驱动加载失败/卸载失败率 < 0.1%（估计）。
- **测量**：WER/崩溃转储符号解析（.sys PDB）+ 用户工单；当前真机验收 T1（Driver Verifier + PnP/睡眠循环）是前置门槛。

#### B2 数据安全指标
- **LostDirtyBytes 非零事件数**：目标 **0**（每非零一次 = 一次真实或近真实的数据丢失事件，无论量级）。P0-4 修复后该计数器已如实记账（chunk_destroy count_lost=1），遥测必须上报原始值而非布尔化。
- **FLUSH 失败穿透率**：目标 **100%**（下层盘故障时 FLUSH 必须向应用返回失败；任何"失败报成功"都是数据丢失）。测量：T3 故障注入用例 + 现场监控 STATUS_IO_DEVICE_ERROR 占比。
- **panic 恢复握手成功率**：panic-clear 后自愈握手成功比例，目标 100%（失败走 fail-closed 拒绝恢复，属安全行为但需计数告警）。

#### B3 部署成功率与卸载干净率
- **定义**：从干净 Win11 按 README 单路径安装成功的设备比例；卸载后 UpperFilters/服务/计划任务恢复原态（含第三方过滤器保留）的比例。
- **目标区间**：安装成功率 **≥99%**；卸载干净率 100%；**部署门禁误拦截率目标 0**（fail-closed 宁可误拒不可误放——哈希锚点必须与构建流水线联动更新，这是流程指标而非脚本指标）。
- **测量**：安装/卸载脚本 exit code 遥测 + T5 真机用例。

#### B4 装机量与增长
- **装机量**：累计安装设备数、月新增安装；目标区间由市场策略定（首年内部试点建议以**数千台真实用户设备**为第一阶段目标，估计——参考：游戏 PC 年出货 2600 万台中可通过垂直渠道触达的子集， Newzoo PC 玩家 9.36 亿的总盘子决定了小众工具的天花板足够高但获取成本是主要约束）。
- **WAU/MAU**：目标 ≥40%（桌面工具常规水位的估计值）；缓存卷启用率（装机后至少启用一个卷）目标 ≥80%——这是"激活率"定义。
- **留存**：D7 ≥ 50%、D30 ≥ 40%（估计，工具类产品常规区间）；比留存更能说明问题的是**缓存持续启用率**（30 天后仍开着缓存的用户占比）目标 ≥60%（估计）。

#### D 经济层（预留）
- 免费→付费转化率 2%-5%（工具类常规区间，估计）；LTV/CAC ≥ 3；"每用户让出内存 GB 数"作为叙事指标管理（内存涨价周期中该数字即用户的真实成本，见 §4）。

### 3.4 指标体系落地前提（当前最大空白）

产品当前**无任何遥测埋点**：以上指标中，A1/A2 的原料已在驱动 `RB_STATS` 中具备，但缺上报通道；B 组依赖 WER 解析与工单；C/D 组完全不可测。建议将"最小遥测集（命中率、加速比采样、稳定性事件、激活/留存事件，全部匿名、可一键关闭）"列为功能路线图第一优先级——没有它，本节所有目标区间只能停留在假设。

## 四、对 PRD / 竞品分析 / 路线图的数据启示

### 4.1 对 PRD（2-3 条）

1. **把"验证完成度"写进 Definition of Done。** 当前 40/40 项修复 100% 静态落盘但 0% 验证；PRD 的发布门禁必须显式包含：可编译环境构建、Driver Verifier、T1-T6 真机验收、失败注入单测——功能验收清单不能替代稳定性验收清单。建议 PRD 为每个内核变更定义"无 Verifier 证据不合并"的硬规则。
2. **默认值安全化 + 内存成本透明化。** 写模式默认直写（已修复）、内存预留可配、空闲自动释放已在位；PRD 应进一步要求 UI 明示"当前缓存占用 X GB"与"按当前内存价格的机会成本约 ¥Y/年"（依据：DDR5 约 $5-8/GB vs NVMe 约 $0.10/GB，且 2026 年内存处于历史高价位）——把"占内存"从用户的顾虑变成可决策的数字。
3. **场景白名单优先于通用加速。** 物理数据（延迟差约 1000 倍 vs 带宽差 5-10 倍）与竞品实测（大文件顺序拷贝增益可忽略、真实负载增益有限）共同指向：PRD 应把游戏加载、应用冷启动、开发构建缓存作为主打场景，并明确不做"大文件拷贝加速"承诺。

### 4.2 对竞品分析（2-3 条）

1. **对比基准必须用真实工作负载。** PrimoCache 官方 200 倍读分是 100% 命中下的理论上限，第三方实测（PCWorld：机械硬盘随机读 +50%、高端 SSD 上主要收益是延寿）与批评性实测（跑分命中率与真实拷贝脱节）都证明短时基准会严重误导。竞品分析矩阵应统一采用"真实场景 P95 延迟 + 30 天命中率曲线"口径。
2. **存量市场是差异化空位。** Win10 仍占 Windows 桌面 27.83%（2026-09，StatCounter）、全球 PC 出货 2026E -14%（高盛）意味着大量老机器超期服役；主流竞品叙事偏"新硬件再挖掘"，而"老 SSD/混合磁盘 + 老系统"场景的针对性优化（含对 DDR4 老机器的缓存 sizing 建议）竞争强度更低（此为基于市场份额数据的推断）。
3. **内核级正确性是竞品少讲的卖点。** 公开评测对 PrimoCache 类产品的最大担忧是延时写入的数据丢失风险（PCWorld 明确警示）；本产品的 LostDirtyBytes 记账、panic epoch 握手、透传失效优先、fail-closed 部署门禁，恰好命中该类担忧——竞品分析应把这组机制转化为"可信缓存"叙事，但前提是 T2/T3 真机证据先落地。

### 4.3 对路线图（2-3 条）

1. **Phase 0（唯一阻塞项）：验证基建。** 可编译环境（WDK 26100 + .NET 8 SDK）+ T1-T6 真机验收 + 三类失败注入单测。在此之前的任何增长/变现动作都是空中楼阁（pre-launch 全检与全量审计两次 No-Go 已给出组织内共识）。
2. **Phase 1：最小遥测集 + 内部基准库。** 命中率/加速比/稳定性事件的匿名上报；benchmark 脚本标准化为前后对照基准。没有数据，后续所有排序都是拍脑袋。
3. **Phase 2：场景化产品化（市场窗口期）。** 内存超级周期至少延续到 2027H2（高盛/TrendForce 一致判断），换机需求被压抑、老机器服役延长——这是"软件加速替代硬件升级"叙事的窗口期；游戏模式（已有特性层）应对齐 Steam 43.5M 峰值同时在线、9.36 亿 PC 玩家（Newzoo）所代表的玩家基本盘做深度打磨。窗口期后的备选叙事：SSD 延寿（写合并降低 NAND 写入量，PCWorld 评测中亦被列为主要收益）。
