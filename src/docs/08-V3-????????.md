# 08 V3：多线程并行回写 · 空闲自动释放 · 并发加固

本篇说明 V3 在 V2 基础上的增强、设计取舍与验证结果。

## 一、多流并行回写（读写更快）

### 问题
V2 的回写由单条后台线程**串行遍历**所有文件流：即便机器上有两块 SSD
（NVMe + SATA），同一时刻也只回写一块盘，第二块盘的带宽被浪费。

### 方案
- 后台线程每个回写周期，为每个需要回写的流分配并投递一个
  **通用工作项（Generic Work Item）**，交由 Windows 系统工作线程池
  （`CriticalWorkQueue`）执行：
  - 不同流 / 不同卷的回写**真正并行**，双 SSD 吞吐叠加；
  - 同一流的回写由该流的 `FastMutex` 串行，数据结构不会并发损坏。
- 流上下文新增 `FlushInProgress` 在途标志，**防止同一流被重复投递**。
- 工作项分配 / 投递失败、或用户关闭并行开关时，自动退回**串行兜底**，
  功能不中断。

### 开关
可视化控制台与 CLI 均提供「多流并行回写」开关（`parallel=1/0`），默认开。

## 二、空闲自动释放（长时间空闲自动收缩）

- 每个缓存块记录 `last_access`（单调毫秒时间戳），读写访问即刷新。
- 核心不直接读取系统时钟：由驱动后台线程周期性调用 `rb_engine_tick`
  传入单调时钟（`KeQueryInterruptTime`），便于测试、也避免核心与平台耦合。
- 后台线程约每 **60 秒**做一次空闲整理：
  - 超过阈值未访问的**干净块** → 直接释放（属可重建的临时缓存，不写盘）；
  - 超时的**脏块** → 先回写本流落盘，再释放，**绝不丢数据**。
- 默认阈值 **30 分钟**，可在控制台调整（1–120 分钟），可整体关闭。
- 释放后若再次访问，自动从磁盘重读（用例验证数据完全一致）。

## 三、并发加固：引擎记账字段原子化

代码审查 + ThreadSanitizer 发现：缓存总量、脏总量、流数量、各项计数器是
**跨流共享**字段，多 CPU 上不同流并发修改却无统一保护。V3 将这些字段全部
改为原子操作（内核 `Interlocked*`，用户态 `__atomic_*`），既消除数据竞争，
又**不串行化前台读写**（无锁原子，不引入全局大锁）。

同时把原来「在流 A 锁内操作流 B」的跨流整理，重构为**单流 trim**：
核心从此永不跨流操作，从根上杜绝多线程锁竞争与潜在死锁。

## 四、关机 / 卸载数据安全

- 关机（IRP_MJ_SHUTDOWN 与关机通知）、驱动卸载统一改为
  **逐流加锁强制全量回写**，并等待已投递的并行工作项完成，
  不再使用跨流无锁的批量回写。
- 卸载顺序：停回写线程 → 全量回写（含等待在途工作项）→ 关通信端口
  → 注销过滤器（触发流上下文清理）→ 销毁引擎 → 写「干净退出」标志。

## 五、验证矩阵（全部通过）

| 验证项 | 工具 | 结果 |
|---|---|---|
| 14 项核心功能用例 | gcc + 断言 | 全过 |
| 内存 / 未定义行为 | ASan + UBSan | 零报告 |
| 多线程数据竞争 | TSan（多流压力） | 零报告 |
| 多流并发压力（4 流×数千操作） | ASan/TSan，多轮 | 全过，脏=0、丢弃=0 |
| 刁钻场景 6 组 | ASan | 全过 |

刁钻场景覆盖：
1. **磁盘满 / 回写持续失败**：脏块保留，流销毁时计入 `lost_dirty_bytes`，不崩溃；
2. **readback 失败**：部分写无法补旧数据时直写兜底，盘数据正确；
3. **空闲释放后重读**：数据从盘重读，逐字节一致；
4. **休眠 / 唤醒时钟大跳变**：单调向前，不崩溃、不溢出；
5. **硬上限写满**（1MB 小缓存）：超限部分直写，盘最终数据完整；
6. **回写间歇抖动**：失败保留脏位，恢复后全部回写，数据一致。

> 驱动在 Windows 11 26H2 上的实际加载，请按 `03`、`05` 文档操作并确认。
