# 02 构建

## 一、一键构建

在**开发者命令提示符（x64）**中，进入项目根目录执行：

```bat
scripts\build_all.cmd
```

产物：
- 驱动：`driver\x64\Release\RAMBoostFS.sys`
- 控制台：`ctl\ramboostctl.exe`

## 二、分步构建（可选）

### 编译驱动（VS 界面方式）
1. 双击 `driver\RAMBoostFS.vcxproj`，用 VS2022 打开。
2. 顶部选 **Release / x64**。
3. 生成 → 生成解决方案（Ctrl+Shift+B）。
4. 输出在 `driver\x64\Release\RAMBoostFS.sys`。

### 编译驱动（命令行方式）
```bat
msbuild driver\RAMBoostFS.vcxproj /p:Configuration=Release /p:Platform=x64
```

### 编译控制程序
```bat
cd ctl
cl ramboostctl.c /O2 /W3 /Fe:ramboostctl.exe /link FltLib.lib ws2_32.lib
```

## 三、工程说明

- 驱动工程把平台无关缓存核心（`core/cache.c`）一起编译进 .sys，
  通过 `/DRB_KERNEL_BUILD` 让核心使用 WDK 非分页池分配；
  测试时同一份代码在 Linux 上用 libc 跑单元测试 —— **核心只有一份源码**，
  不存在"测试版和发布版逻辑不一致"的问题。
- 编译选项：/W4 全警告、禁用弃用 API 警告（4996）、C11 语言标准。
- 驱动未启用任何未签名扩展行为，仅依赖标准 WDK API。

## 四、验证（可选，需 Linux/WSL）

核心算法自带单元测试（9 个用例：读命中/部分命中/写回/直写/水位/合并回写/
LRU 淘汰/影子一致性/多流压力），在 Linux 或 WSL 下执行：

```bash
cd core
gcc -O2 -Wall -Wextra -o test_cache cache.c test_cache.c -pthread && ./test_cache
# 期望输出: 全部用例通过 (失败 0)

# 内存错误检测（AddressSanitizer）:
gcc -O0 -g -fsanitize=address -o test_cache_asan cache.c test_cache.c -pthread && ./test_cache_asan
```
