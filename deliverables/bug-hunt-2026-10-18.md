## 一、主诉根因：磁盘页纯黑无内容

### 【致命-1】Sparkline.Stroke 依赖属性类型是 Color，XAML 却喂了 SolidColorBrush 资源

**证据链**：
1. 日志 `ctrl-20261018.log` 02:21:12-13 一秒内 **2194 条**：`未处理异常："#FF63D6A0"不是属性"Stroke"的有效值`
2. `MainWindow.xaml:284`：`<ctl:Sparkline Height="48" Value="{Binding WriteMbps, Mode=OneWay}" Stroke="{StaticResource RbcSuccessFg}"/>`（磁盘页每卷卡片的写吞吐曲线）
3. `Controls/Sparkline.cs:23-24`：`StrokeProperty` 注册为 `typeof(Color)`
4. `Theme/Dark.xaml:26`：`RbcSuccessFg` 是 `<SolidColorBrush>`——类型错配

**触发条件与后果**：每次磁盘页 ListBox 为每个卷实例化数据模板时，WPF 把 SolidColorBrush 转换给 Color 属性失败抛异常 → 项模板渲染失败 → **磁盘页只剩标题、内容区全黑**（ListBox 无一项渲染成功）；布局系统每轮 measure 重试再抛，形成 2194 条/秒的异常风暴；`App.xaml.cs:12` 的全局 handler `Handled=true` 全吞 → 用户看到"纯黑但进程正常"。

**修复建议（根治，同步改三处）**：
```csharp
// Sparkline.cs —— Stroke 改 Brush（WPF 惯例：笔画属性用 Brush）
public static readonly DependencyProperty StrokeProperty = DependencyProperty.Register(
    nameof(Stroke), typeof(Brush), typeof(Sparkline),
    new FrameworkPropertyMetadata(new SolidColorBrush(Color.FromRgb(0x60, 0xCD, 0xFF)), FrameworkPropertyMetadataOptions.AffectsRender));
public Brush Stroke { get => (Brush)GetValue(StrokeProperty); set => SetValue(StrokeProperty, value); }
// OnRender: var pen = new Pen(Stroke, 1.6);   // 不再 new SolidColorBrush(Stroke)
```
`MainWindow.xaml:284` 不变（`{StaticResource RbcSuccessFg}` 即 Brush，直接可用）。此改法同时消灭"下一处 XAML 再踩同类坑"的可能（已全树核查：这是唯一类型错配 DP）。

## 二、致命问题（3）

### 【致命-2】总览页"全部挂载/全部卸载"两个命令全程静默死亡（100% 复现）
**位置**：`MainViewModel.cs:146-155`
```csharp
var mountSnapshot = Drives.ToArray();      // 构造函数里采集——此刻 Drives 还是空集合
MountAllCommand = new AsyncRelayCommand(() => Task.Run(() =>
    Task.WhenAll(mountSnapshot.Select(d => d.MountAsync(...)))));
var unmountSnapshot = Drives.Where(d => d.Mounted).ToArray();
```
**描述**：快照在**构造函数**执行时采集，而 `Drives` 要等握手完成才填充。闭包捕获的是构造期的空数组，之后永不更新。R2-U2 的修复（"UI 线程先快照"）把快照挪错了位置。
**后果**：打开总览点"全部挂载/全部卸载"→ 遍历空数组直接返回 → **无任何操作、无任何报错**，按钮像死的一样。
**修复**：采集移进执行体：`() => Task.Run(() => Task.WhenAll(Drives.ToArray().Select(...)))`（Task.Run 内即在后台线程，枚举安全）；卸载同理实时过滤 `d.Mounted`。

### 【致命-3】install.ps1 安装入口：无签名门禁 + sc.exe 链零校验——复装必现 1072 静默失败，且无护栏
**位置**：`src/scripts/install.ps1:18-24`
```powershell
sc.exe delete $Script:ServiceName | Out-Null          # 无 Stop-Service、无 $LASTEXITCODE 检查
sc.exe create $Script:ServiceName ... | Out-Null       # 服务已标记删除时返回 1072，静默
Write-Host '[ok] 服务已注册（demand start）'            # 无条件打印成功
```
**描述**：①`sc.exe delete` 对运行中的服务只打删除标记，紧随的 `create` 必返 1072（ERROR_SERVICE_MARKED_FOR_DELETE，项目历史事故同款），但脚本照报 [ok] 并继续写 UpperFilters → 重启后卷类引用一个已删除的服务；②全文无 `Get-AuthenticodeSignature` 验证、无哈希锚点比对、不写 FilterArmed armed 基线（boot_guard.ps1 首行即 exit 0、驱动 s_selfDisable 不激活）→ **这条安装路径没有任何 0x7B 护栏**，正是 10-17 砖机事故的 fail-open 变体；③它建的是 demand-start 服务，与 deploy.ps1/ramboostsetup 的 BOOT_START 语义不一致，用户无法分辨哪条是权威入口。
**修复**：delete 前 `Stop-Service` 并确认 Stopped（或移植 ramboostsetup.c 的 15s 轮询）；每步 sc.exe 检查 `$LASTEXITCODE` 失败即 throw；签名后加 `Get-AuthenticodeSignature -ErrorAction Stop` + `Status -ne 'Valid'` 即 throw + `signtool verify /pa`；补齐 armed 基线写入（与 deploy.ps1 第 3 步一致）；README 明示"唯一权威安装入口 = ramboostsetup / deploy.ps1，install.ps1 仅 legacy 开发调试"。

## 三、严重问题（5）

### 【严重-1】C 安装器 A2 签名预检位置在拆除旧安装之后——"失败零副作用"不成立
**位置**：`ramboostsetup.c:237-245`。`DeleteServiceIfExists()`（L238，Stop+Delete 旧服务）和两处 `RegMultiSzRemove`（L239-240，摘 UpperFilters）执行完之后，L245 才 `VerifyDriverSignature()`。注释却声称"先于一切变更"。未签名 sys 喂进去 → 返回 1，但旧安装已被先行拆除（"安装失败且原功能消失"）。不砖机（摘过滤器是安全方向），但违背门禁设计意图。**修复**：VerifyDriverSignature 调用移到 L237 之前。

### 【严重-2】UnmountAll 的"等待全部完成"修复未生效：仍在经 async void Execute 点火
**位置**：`MainViewModel.cs:152` + `Helpers/RelayCommand.cs:58`。`Task.Run(() => d.UnmountCommand.Execute(null))` 返回的 Task 在 `async void Execute` 同步段结束即完成，**不等待真正的卸载 IOCTL**——`Telemetry(UnmountCompleted)` 提前上报、快速关窗时卸载未完成进程即退。**修复**：给 AsyncRelayCommand 加 `ExecuteAsync` 返回 Task，或 DriveItemViewModel 暴露 `UnmountAsync()`。

### 【严重-3】StateBar 异常段变色功能是改一半残留：语义色从未应用到段背景
**位置**：`Controls/StateBar.xaml.cs:28-48`。`AnimBackground(Border b, Brush to)` 只播了一个 `1→1` 的透明度空动画，参数 `to`（语义色）从未使用（`_ = dur;` 死变量）。四段胶囊底色恒定中性色，异常态只剩 8px 圆点可辨。**修复**：按 CardHover.SwapColor 的克隆画刷 + ColorAnimation 模式实现，或删除死参数并注释"仅圆点承载语义色"。

### 【严重-4】全局异常 handler 无条件 Handled=true——UI 损坏态的静默放大器
**位置**：`App.xaml.cs:9-13`。本次黑屏的 2194 条渲染异常全部被吞，页面保持空白而窗口"看起来正常"。历史同款机制还制造过"窗口不显示但进程活着"。**修复**：仅对已知可恢复异常置 Handled；其余记日志后置 false 快速失败（或至少弹 Banner 告知界面部分不可用）。

### 【严重-5】offline_rollback.cmd（WinRE 唯一人工恢复手段）核心步骤无退出码检查 + ControlSet 探测不全
**位置**：`src/scripts/offline_rollback.cmd:65-73 / 29-36`。摘 UpperFilters 的 PowerShell 步骤失败不可见；`reg unload` 失败时 hive 惰性写回可能丢失回滚；`Select\Current` 只映射 0x1/0x2/0x3，其余静默回退 ControlSet001（写到非活动控制集 → 回滚"成功"但 0x7B 依旧）。**修复**：每步 errorlevel 检查+失败 exit 1；未命中映射时打印原始值退出要求人工确认，不做静默回退。
