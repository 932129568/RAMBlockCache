# 06 Windows 11 26H2 适配说明

## 一、兼容性结论

RAMBoostFS 使用**标准 WDK 文件系统 minifilter 架构**（海拔 373000.123456），
构建目标为 **WDK 10.0.26100（Windows 11 26H2 对应的 SDK/WDK 版本）**，
因此：
- **Windows 11 26H2（正式版）**：直接支持；
- Windows 11 22H2/23H2/24H2、Windows 10 1809+：同一二进制兼容（使用 WDK
  的兼容库，目标最低 10.0.17763）；
- 未来新系统：只要 minifilter 架构不变，可重新用新 WDK 编译即适配。

## 二、为什么选择 minifilter 而不是传统 filter driver

| 维度 | minifilter（本项目） | 传统 legacy filter |
|---|---|---|
| 微软推荐 | ✅ 唯一推荐的现代文件系统过滤架构 | ❌ 已弃用 |
| 与 Cache Manager 协作 | 有标准回调（FLT） | 手工处理易冲突 |
| 26H2 兼容 | 官方持续维护 | 无新支持 |
| 开发正确性 | Flt* API 封装了大量 IO 细节，蓝屏面小 | 裸 IRP，极易出错 |

## 三、26H2 上的具体适配点（已处理）

1. **内存分配**：使用 WDK 26100 的 `ExAllocatePool2`（旧 `ExAllocatePoolWithTag`
   在新 WDK 已弃用，本项目全部用新 API，无弃用警告）。
2. **海拔**：注册在 `373000.123456`（文件系统缓存类海拔区间，
   "FSFilter Cache Manager" 加载组），与系统自带缓存过滤器共存不冲突。
3. **分页 IO 放行**：26H2 的 Cache Manager 行为与旧版略有变化，
   本项目对 `IRP_PAGING_IO` 一律放行，**绝不与系统缓存双重缓存**，
   这是 minifilter 在 26H2 上稳定运行的关键取舍。
4. **只附加 NTFS**：26H2 默认文件系统（NTFS）直接支持；ReFS/其他卷不附加。
5. **签名**：26H2 强制驱动签名策略与 24H2 一致（测试签名模式 + 自签名可用，
   需关闭 Secure Boot，见 `05-签名与安全启动.md`）。

## 四、在 26H2 上验证是否加载成功

```bat
fltmc          # 看到 RAMBoostFS 实例与 373000.123456
fltmc instances -f RAMBoostFS   # 查看附加到哪些卷
```

## 五、如果 26H2 未来更新后出问题

1. 先卸载（`scripts/uninstall.cmd`），确认是 RAMBoostFS 引起的问题；
2. 更新到最新 WDK（与系统版本匹配），重新编译即可；
3. 把蓝屏/错误信息截图给我，我来修。

## 六、性能预期（你的机器：64GB 内存 + 双 SSD）

- 场景：重复读（启动软件、打开工程、浏览图片/视频素材）→ 命中率可达 90%+，接近内存速度；
- 场景：大量小文件写入（编译、下载、解压、缓存文件）→ 写入先进内存，
  脏段合并回写，明显减少 SSD 写放大，**延长致态 TiPlus7100 / MX500 寿命**；
- 大文件顺序读写：命中收益小（SSD 本身快），收益主要在小块随机 IO 与重复 IO。
- 建议缓存大小：数据卷 8~16GB；写缓存开启 + 回写模式，脏水位 60/40。
