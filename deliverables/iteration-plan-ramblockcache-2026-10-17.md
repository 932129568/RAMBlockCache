# RAMBlockCache 分阶段功能迭代方案（路线图执行层）

**日期**：2026-10-17 · **状态**：待评审 V1.0
**定位**：既有路线图（Phase 0 验证基建 → Phase 1 L2/签名/商业化 → Phase 2 块层/规模化，Gate 0/1/2）之下的**可执行迭代层**——战略框架不变，本方案把未来 1–2 个季度组织为 Now/Next/Later 四个波次 + 每项五字段（目标/改动点/预期收益/影响范围/优先级）。
**方法论**：波次间依赖门控（不过门不进下一波）；波次内 RICE 打分（估计值，仅用于相对排序）。
**纪律声明**：所有工作量与时间窗为估计；任何"已验证"表述以真机 + Driver Verifier 证据为凭；未签名/锚点不同步的驱动禁止部署。

### 关键决策（grill-me 评审结论）

① 本方案为路线图执行层，不取代 Phase/Gate 框架；② 范围取全池六主题（部署闭环/三 PRD 功能/修复收尾/信任遥测/签名合规/商业化）；③ 依赖门控 + 波次内 RICE；④ 验证基建显式为 Wave 0；⑤ 双受众输出（本页 + 明细表）。

### 三条硬规则（违反即回滚）

1. **W0 不过门，W1–W4 不启动**——今日全部修复的上线证据是本方案的地基；
2. **无 Driver Verifier 证据的功能不合并**（写入工程 DoD）；
3. **源码改动→重编译→哈希变→必须过 `sync_anchors.ps1` 同步三锚点 + 重签名**——fail-closed 不得绕过。
