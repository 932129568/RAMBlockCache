## 1. 五要素（Surface / Audience / Tone / Brand / Scale）

| 维度 | 结论 | 依据与边界 |
|------|------|-----------|
| **场景（Surface）** | **Windows 桌面控制台（WPF，net8.0-windows）**：单主窗口（现 1180×780，min 900×600）+ 左侧导航五页 + 顶部常驻四段状态条 + 顶部 Banner + 首次运行三步向导（560×480 固定）+ 系统托盘常驻。非网页、非移动端。允许团队先产 **HTML 高保真原型作视觉靶标**，但最终交付物是 WPF XAML/控件，所有结论须按 WPF 落地表述（无 CSS 等价物的用 WPF 惯用法，见 §6 偏差备案）。 | 现行 MainWindow.xaml 结构实况；驱动侧零改动约束决定 UI 只能是"真相翻译层"。 |
| **受众（Audience）** | 三类，按优先级：① **性能用户**（玩家/开发者/硬件爱好者：懂术语、要证据、要调优——命中率/吞吐/分片热力是他们的语言）；② **办公用户**（被推荐安装：不懂缓存、怕搞坏机器、要退路——零术语、结论先行、一键回安全态）；③ **运维/IT**（批量部署、可审计、可回滚——注册表可下发、诊断可导出）。共同刚需 = **确定感**（状态确定 / 结果确定 / 退路确定）。 | 体验架构 §2 JTBD 三角色；用户四项诉求的痛点表述（"画面简陋/特效不足/页面不直观"）主要来自 ①② 的观感。 |
| **调性（Tone）** | 推荐 **方向 A：Tech Utility 精密仪表**（继承 02 设计系统已选定的 Linear 骨架 + Tech Utility 方向）——深色中性阶梯、1px 精确描边、克制五色语义、等宽数字、bento 数据卡、图表仅青蓝数据系 + 绿/琥珀/红语义系；语言"工程直白、结论先行"。备选 **方向 B：Soft Warm 工具化**（圆角+暖色，降低内核工具的冷感、讨好办公用户）——可作为信息卡/空态插画的局部借用，**不可作全局方向**（与暗色硬约束下的"信任感"和驱动级工具有冲突）。**方向 C：Brutalist/实验风明确否决**（安全关键产品，用户要确定感不要实验性）。 | 02-design-system §A.3 已选定 Linear；02b §B 已把特效边界划清。本文不推翻既有方向，只做"执行层细化"（见 §3 任务映射）。 |
| **品牌上下文（Brand Context）** | **弱品牌、强产品名**：无外部品牌手册。品牌资产 = 产品名 `RAMBlockCache` + 单一版本串 `V10.4.3 Build 19（10.3.4.19）`（version.h→gen_version.ps1→Version.cs 单一事实源，禁止硬编码）。已有资产：Dark.xaml 令牌 V1.0（Rbc* 语义键 + 5 个存量别名）、Motion.cs 动效单一事实源、02/02b 两份规范、final 原型 HTML（视觉靶标参考）。**已发现令牌漂移**：Dark.xaml 与 02-design-system.md 存在 8 处色值不一致（§3-T1.1 列明），Phase 2 必须裁定对齐方向。 | Dark.xaml 实读比对；U-05 已删除死令牌（RbcChart*/RbcSkeleton* 随消费方重建）。 |
| **规模（Scale）** | **目标 6 主页面 + 1 常驻状态条 + 1 向导 + 托盘**（现行 5 页；UX 架构 §4.1 目标 IA 为 状态/加速/收益/诊断/应急/设置，本文建议采纳，见 §4）。每页覆盖 **5 态**（正常/空/加载/错误/危险操作）≈ 30 个界面状态；交互含 1s 统计轮询、数字滚动、图表刷新、二次确认弹窗、进度反馈、reduced-motion 三选。**响应式非目标**（固定窗口桌面工具，需支持 1080p/2K 与 125%/150% DPI 等比，布局不重排）。 | 01-requirements §1 规模结论仍有效；页数建议从 5→6 的理由见 §4.2。 |

## 2. 硬性约束（不可违反，Phase 2 所有产出的前提）

1. **暗色主题硬约束**：不得做浅色主题、不得做明暗切换（02b §C.12 已声明非目标）。
2. **目标平台 WPF**：所有视觉/动效结论必须可落在 WPF（XAML + Controls 自定义控件）；HTML 原型只是靶标，不是交付物。
3. **零新增 NuGet 依赖**；**驱动侧零代码改动**（`dist/RAMBlockCache.sys` 哈希 b6fb097b… 禁止变动、禁止重编译部署）。
4. **构建与门禁**：`dotnet build -c Release` 0 错误 0 警告；五件套门禁全绿（check_repo / check_proto_sync --strict / refcount_model / check_ps_syntax / check_signature）。
5. **规范即宪法**：02-design-system.md（§F.2 十三条禁止清单）+ 02b-charts-motion.md（§B.4 十四条禁止清单 + §B.5 reduced-motion 降级）继续生效；本文所有任务验收标准引用其条款号。
6. **无假接线纪律**：预留接口必须"随消费方一起加入"（U-03 后的 FeatureRegistry 新纪律）；任何"看着接好了其实没接"的占位都是回归。
7. **诚实标注**：沙箱无交互桌面，UI 无法真机验证——所有"已验证"仅指静态证据（门禁 + 构建 + grep），运行时状态必须显式移交真机冒烟清单。

## 4. 信息层级重构建议

### 4.1 当前五页结构的问题诊断（按严重度排序）

**问题 1 · 总览页：信息过载 + 职责混乱 + 危险操作裸奔（最严重）**
- 一页塞了三种互斥职责：状态首页（三数字卡）+ 全局操作台（全部挂载/全部卸载/拉取驱动日志/退出安全模式/解除熔断/一键熔断 六个按钮）+ 技术说明书（"协议 9 · IOCTL 0x222000 · 结构体 Pack=8…"静态文本卡）。
- 后果：用户 3 秒内找不到"现在安不安全"；**一键熔断（红色危险按钮）与"全部挂载"并排**，误触无三段式护栏；驱动协议细节暴露给终端用户，违反"结论优先"（UX §P1）。
- 佐证：体验架构 B2/B4/B5 三条断点全部落在本页。

**问题 2 · "缓存"页：是配置页不是价值页，且与磁盘页职责重叠**
- 本页四个配置块（L2 持久缓存/顺序读预取/回写周期/每卷预读窗口）全是"机制视角"；用户**看不见收益**（命中率趋势、省下磁盘读、缓存占用环——02b 七类图表无一承载）。
- 每卷配置散落两页：配额滑块在磁盘页、预读窗口在缓存页、写模式在磁盘页——同一张卷卡被撕成三个地方。
- 佐证：体验架构 B5（无收益反馈）；01-requirements 早已把此页目标改为"收益"页，代码未跟进。

**问题 3 · 导航逻辑：功能导向命名 + 日志孤岛 + 状态条跳转死链**
- 导航名"磁盘/缓存"是资源视角，用户任务是"加速/看效果"；新用户无法从导航名推断页面用途。
- 日志页孤岛：驱动日志要回总览页手动点"拉取驱动日志"才更新；无自检清单、无版本单轨、无诊断导出——"诊断"作为目的没有承载页。
- 状态条四段点击跳转硬编码为 总览/磁盘/缓存/日志（F3），**风险段（未落盘/熔断/安全模式）没有对应页面可跳**——状态条承诺的"异常段可点击直达处置"是死链。

**问题 4（次）· 设置页：预留面与正式设置混排**
- "预留功能与实验"卡（遥测/减少动效/许可/重跑向导）与正式设置（自动挂载/开机启动/进程排除）同页；遥测开关混在设置里而非首次向导知情流；无卸载入口、无全局内存预算控件（UX §7.6/J4 要求项缺失）。

### 4.2 重组方案（建议采纳 UX 架构 §4.1 目标 IA，六页 + 应急）

| 现行 | 建议 | 内容重组要点 |
|---|---|---|
| 总览 | **状态**（首页） | 只回答"现在怎样"：全局状态条（已有）+ 三数字 bento（命中率/省下磁盘读/缓存占用环）+ 每卷一行状态徽标卡 + 异常时才出现的三段式异常卡。六个全局操作按钮全部迁出；危险操作迁应急页 |
| 磁盘 | **加速** | 卷卡补齐：盘符/卷标/状态徽标（六态白名单）/写模式下拉（固定文案）/挂载开关/配额滑块/预读窗口下拉（从缓存页迁入，**每卷配置归一页**）/迷你 sparkline。系统卷 C: 默认不加速 + opt-in 入口（W3-5） |
| 缓存（拆） | **收益** | 02b 七类图表的主场：命中率趋势（5 分钟）、缓存占用环、读写吞吐双线、64 分片热力、未落盘堆叠条、写模式构成。一级 3 数字、二级折叠细节（UX §7.3 渐进披露） |
| （下沉） | 配置块去向 | L2 配置 + 预取总开关 + 回写周期 → **设置页**"缓存策略"分组（与"启动/进程准入/预留/关于"并列）；每卷预读窗口 → 加速页卷卡 |
| 日志 | **诊断** | 驱动日志自动拉取 + UI/驱动日志同屏对照（来源标签）+ 自检清单（驱动连接/协议/版本对比/UpperFilters 实际值/安全模式/熔断）+ 版本单轨 + IOCTL 通道健康点阵（02b 图 #6）+ 一键导出诊断包 |
| （新增） | **应急** | 一键熔断（三段式确认）/ 解除熔断（自愈未完成置灰+原因）/ 退出安全模式 / 未落盘与丢失量核对（LostDirtyBytes）/ 回滚指引三步图 / 导出救援卡。**异常时常驻导航高亮，正常时可收起为状态条风险段入口** |
| 设置 | **设置** | 启动项（自动挂载/随 Windows 启动）/ 缓存策略（L2/预取/回写周期）/ 进程准入排除 / 预留与实验（遥测/动效降级/许可/向导）/ 卸载入口（含 UpperFilters 恢复说明）/ 关于 |

**导航形态建议**：侧栏六项固定顺序 状态/加速/收益/诊断/应急/设置；应急项在无异常时以中性色呈现（不制造焦虑），异常时语义色 + 徽标计数。状态条四段跳转改为：驱动→诊断、挂栈→加速、加速→状态、风险→应急。

**术语纪律**：面向用户界面只用白名单（挂栈/加速/直写/回写/熔断/安全模式/命中率/未落盘数据）；Bound/Attached/WriteMode/Panic/DirtyBytes 等只允许出现在诊断页并附中文解释（UX §8.3 禁止术语表）。
