## 二、数据安全整改（WS-RACE 三轮竞义，终判结构性闭合）

**竞义类**：写者"镜像落盘+失效清脏"与回写器"锁外在途旧版写"交错 → 已 ack 数据被旧数据永久取代（计数器全绿但数据已坏）。三轮轨迹：R1 抓逐区间 direct 路径 → R2 报 BLOCKER-2（P2-1 整块未闭合）→ R3 证伪 BLOCKER-2 为**测试口径伪阳性**（QA 复现器的 mirrorall dc>0 整段镜像属驱动不可达模式，覆盖率实证 -2 从未触发），同时用 p21/bigwrite 新模式把 -2 路径从死代码变成确定性覆盖 → 终验确认结构性闭合。

**修复包**（cache.c + rbio.c）：① rb_write_ex 出口单一收口排空（drain 移至函数最末端，覆盖 reclaim 新起段）；② flush_pass stage 后 gen 复检（stage_revalidate，不符弃写）；③ invalidate 升代 + 入口排空；④ 直写成功后逐区间失效（P0-1 补齐）；⑤ finding-2 失败后续块路径修复（前序块回滚失效提前到首个失败探测点、任何后续块镜像之前）。**7 条全镜像路径审计表**逐条闭合（逐区间成功/失败、P2-1 整块、失败后后续块、passthru、非回写直写、admit 排除）。

**诚实记账**（三方证据）：QA 两轮 BLOCKER 的证据均建于超驱动行为的测试模式（已认账并写入报告）；工程师"丢锁致败"的具体归因被对照实验证伪（补锁后仍 3/15），但其"失败含伪阳性"的更宽结论成立；-2 路径结论是"修复后通过+设计级论证"而非"修复实证有效"（用户态盘=内存缓冲，~µs 窗口，生产 ~ms——测试无法自然区分，结构性保证靠代码收口+审计表）。三条残余微窗已在 README §四/交付报告披露（读者 miss-fill 世代校验需新 API 后续单列；调用方镜像全吸收区间属调用契约）。
