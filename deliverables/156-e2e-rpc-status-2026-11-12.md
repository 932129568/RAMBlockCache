## 3. `finally` 的 T2 改造（A2 / A3 / A5）

三个文件原本都是这个形态（同一份抄写）：

```python
    finally:
        rpc(2, c0)
        result["recovery"] = {"WriteBack": cfg()["WriteBack"], ...}
```

现在 `rpc` 会对 `status != 0` 抛异常 → 若不改，finally 会**抛着走**，把 try 段的原始异常顶掉，
并且 `a2_reverify:182-199` / `b_reverify:238` 的 `checks`/`VERDICT` 整段不会执行（153 §A.3 风险栏原文）。

改成（三处同构）：

```python
    finally:
        _rb, rerr = try_rpc(2, c0)      # 恢复写
        _cb, cerr = try_rpc(4)          # 配置读回
        _sb, serr = try_rpc(1)          # 统计读回
        _c = _cb.get("data") or {}
        _s = _sb.get("data") or {}
        result["recovery"] = {"WriteBack": _c.get("WriteBack"), ...}
        if rerr or cerr or serr:
            result["recovery_error"] = {"restore": rerr, "config": cerr, "stats": serr}
            print(json.dumps({"RECOVERY_FAILED": ...}), flush=True)
```

效果（判据侧，不改任何判据表达式）：

| 文件 | 恢复失败时 | 结论 |
|---|---|---|
| `a2_reverify_after_reboot.py` | `recovery["WriteBack"]=None` → `checks["config_restored"]` False；`LostDirtyBytes=None` → `lost_dirty_zero` False | **VERDICT 从 PASS 变 FAIL**（原本崩溃=无 VERDICT） |
| `b_reverify_after_reboot.py` | `r["recovery"]["WriteBack"]=None` → `checks["E_config_restored"]` False | 同上 |
| `a2_repro_ab.py` | `result["recovery_error"]` 出现 + `RECOVERY_FAILED` 行，但**退出码仍是 0**（该文件本来恒 `return 0`，§B 未覆盖它） | **仍是假绿**，见 §6 第 1 条 |
