## 1. 五要素（Surface / Audience / Tone / Brand / Scale）

| 维度 | 结论 | 依据与边界 |

## 3. 前后端联调需求（6 子项 · 逐条可验收）

> 术语：**前端** = WPF Controller（`DriverService` / `StatsService` / `MainViewModel` / `DriveItemViewModel`）；**后端** = 内核驱动 12 消息（Protocol 9，单 IOCTL `0x222000`）+ CLI。以下每条均为**可验收需求陈述**，编号 `R<子项>.<序号>`。

### 3.1 子项 A —— 12 消息 → UI 触点归属

- **RA.1** 12 条消息必须各有**唯一主触点**与明确消费组件，映射表冻结如下：

  | 消息 | 编号 | 主触点（页/组件） | 触发方式 | 期望用户可见结果 |
  |------|------|-------------------|----------|------------------|
  | GET_STATS | 1 | 状态首页三数字 + 收益页 + 状态条风险段 | 1s 轮询 | 数字随使用增长；失败显示"统计暂不可用" |
  | SET_CONFIG | 2 | 设置页（内存预算/开关/回写间隔） | 用户改设置 | 显示驱动 clamp 后的**实际生效值** |
  | FLUSH | 3 | 卷卡"立即回写" + 卸载前自动 | 用户点击/卸载 | 成功显示脏量归零；失败按 RB.1 三段式报错 |
  | GET_CONFIG | 4 | 设置页初值 + 诊断页自检 | 进入页面/启动 | 控件初值 = 驱动当前值 |
  | EXIT_SAFE_MODE | 5 | 应急页"退出安全模式" | 用户确认后 | 状态从"降级·安全模式"迁移回"就绪/加速" |
  | SET_VOLUME | 6 | 加速页写模式下拉 | 用户切换 | 切换即时生效，卡片文案同步 |
  | GET_VOLUMES | 7 | 加速页卷列表 + 首页卷卡 + 状态条挂栈/加速段 | 1s 轮询/进入页 | 每卷 Bound/Attached/WriteMode 如实呈现 |
  | ATTACH_VOLUME | 8 | 加速页开关 + 首次向导 | 用户点击 | 3 秒内卡片显示"已加速·命中率 xx%"（挂载即验证） |
  | GET_LOG | 9 | 诊断页日志区 | 进入诊断页自动拉取 | 展示最近 64 条；空态"暂无日志" |
  | GET_VERSION | 10 | 状态条驱动段 + 诊断页自检 | 启动握手 + 诊断刷新 | 显示单一用户版本串 + 协议号 |
  | PANIC | 11 | 应急页熔断开关 + 首页异常卡 | 用户确认后 | 状态条转红，风险段="熔断中" |
  | PANIC_CLEAR | 12 | 应急页"解除熔断" | 自愈完成后可点 | 状态迁移回"就绪未加速" |

- **RA.2** 任一消息**不得**出现在两个页面上语义不同的位置（避免"同一状态多处说法"）；跨页复用（如 GET_STATS 同时喂首页与收益页）必须来自**同一前端状态对象**，不得各自独立请求后自行解释。
- **RA.3** 所有写操作消息（2/3/5/6/8/11/12）必须有**结果反馈**：成功 → 状态条/卡片更新；失败 → 三段式错误 + 保持原状态（不得乐观更新后不回滚）。

### 3.2 子项 B —— 前端状态模型 ↔ 后端字段映射

- **RB.1** 前端必须定义**单一用户态枚举**（6 态：`未安装 / 已安装未挂栈 / 就绪未加速 / 加速中·直写 / 加速中·回写 / 降级·安全模式 / 熔断·全局透传`，其中熔断含"自愈中"子态），并建立**从驱动字段到用户态的唯一判定函数**。判定输入字段与规则：

  | 用户态 | 判定依据（后端字段） | 来源消息 |
  |--------|----------------------|----------|
  | 未安装 | 打开控制设备失败（Win32 2/3） | 10 失败 |
  | 已安装未挂栈 | 连接成功但无 `RB_VOLUME_INFO.Bound==1` | 7 |
  | 就绪未加速 | 存在 `Bound==1` 且该卷 `Attached==0` | 7 |
  | 加速中·直写 | `Attached==1` 且 `WriteMode==RB_WRITEMODE_THROUGH(0)` | 7 |
  | 加速中·回写 | `Attached==1` 且 `WriteMode==RB_WRITEMODE_BACK(1)` | 7 |
  | 降级·安全模式 | `RB_STATS.SafeMode==1` | 1 |
  | 熔断·全局透传 | `RB_STATS.PanicActive==1` | 1 |
  | 熔断·自愈中 | `PanicActive==1` 且自愈未结算（`PanicClear` 返回 `STATUS_DEVICE_NOT_READY 0xC00000A3` / 或需由 UI 依据"解除被拒"进入该子态） | 11/12/1 |

- **RB.2** 字段映射必须**单一事实源**：`Bound/Attached/WriteMode`（来自 7）与 `SafeMode/PanicActive/DirtyBytes/LostDirtyBytes`（来自 1）在 UI 内合并为一个状态对象后，再由唯一函数产出用户态、文案、颜色、主行动、禁止动作（对齐体验架构 §5.1）。禁止各页面自行拼装状态。
- **RB.3** 原始字段（`Attached=1`、`WriteMode=2`、`PanicPassthrough`、`DirtyBytes` 等）**只允许出现在诊断页**，且必须附中文解释；面向用户界面只允许 6 态文案 + 术语白名单（挂栈/加速/直写/回写/熔断/安全模式/命中率/未落盘数据）。
- **RB.4** `DirtyBytes` / `LostDirtyBytes` 必须能映射为"未落盘数据 N MB / 已确认丢失 M MB"并在状态条风险段与应急页核对区一致呈现；`LostDirtyBytes>0` 时风险段必须变琥珀并给出核对入口。
- **RB.5** `WriteMode==RB_WRITEMODE_GLOBAL(2)` 在 UI 文案为"跟随全局设置"，不得直译为数字 2。

### 3.3 子项 C —— 错误码 → 用户语言映射

- **RC.1** 前端必须提供**错误码 → 三段式文案**（发生了什么 / 为什么 / 下一步做什么）的集中映射表，至少覆盖：

  | 错误码 | 含义 | 目标用户文案（三段式） |
  |--------|------|------------------------|
  | Win32 **5** | 拒绝访问 | "没有权限访问缓存驱动。原因：控制设备仅允许管理员访问。下一步：右键以管理员身份运行本程序。" |
  | Win32 **2 / 3** | 文件/路径未找到 | "未检测到缓存驱动。原因：驱动未安装或未启动。下一步：点击『运行安装向导』。" |
  | Win32 **21** | 设备未就绪 | "该卷尚未准备好。原因：卷信息仍在读取中。下一步：稍候几秒后重试，或重启一次。" |
  | Win32 **170** | 驱动忙 | "驱动暂时繁忙。原因：正在执行其他操作。下一步：程序会自动重试；若持续失败请稍后手动重试。" |
  | Win32 **87** | 参数非法/协议不一致 | "驱动与控制台版本不匹配。原因：安装包与控制台不是同一版本。下一步：使用同一发布包重新安装。" |
  | NTSTATUS **0x80000011**（STATUS_DEVICE_BUSY） | 设备忙 | 同 Win32 170 文案（瞬时，可重试） |
  | NTSTATUS **0xC00000A3**（STATUS_DEVICE_NOT_READY） | 设备未就绪 | 熔断解除被拒场景 → "暂时不能解除熔断。原因：驱动正在把未落盘数据写完（自愈中）。下一步：等待风险段变为『无』后重试。" |
  | NTSTATUS **0xC0000011** / FLUSH 失败 | 回写失败 | "数据尚未完全写入磁盘。原因：磁盘报告写入错误。下一步：检查磁盘健康；未落盘数据仍在缓存中，可稍后重试。" |

- **RC.2** 错误必须**区分"权限不足(5)"与"驱动未加载(2/3)"**，二者文案与下一步动作必须不同（修复轮 P2-5 已修 CLI，UI 必须对齐）。
- **RC.3** 前端 `DriverException.Win32Error` 需同时承载 Win32 与 NTSTATUS 两类取值域；判定函数（如 `IsTransientAttach`）必须**显式枚举**两个域，禁止依赖数值巧合。
- **RC.4** 统一应答语义：`RB_MSG.Status` 偏移 8 处**非 0 即错**，优先采用驱动回填的 NTSTATUS，其次回退 Win32 错误。
- **RC.5** 所有错误弹窗/卡片必须含"下一步做什么"的可点击动作（如"以管理员身份重开""运行向导""打开诊断"），不允许只给错误码。

### 3.4 子项 D —— 降级 / 重试 / 轮询策略

- **RD.1** 统计轮询周期 **1 秒**；单次采样失败**不得**终止轮询任务（整轮 try/catch + 分发单独 try/catch），失败只记日志并继续。
- **RD.2** 轮询失败需有**退避**：连续 N 次失败（建议 ≥3）后周期从 1s 指数退避至上限（建议 ≤10s），任一次成功后立即恢复 1s；退避期间状态条显示"正在重连…"。
- **RD.3** 采集键集合在 `Start` 时**物化**为不可变数组，避免与 UI 线程并发修改集合导致轮询静默停更。
- **RD.4** ATTACH 瞬时冲突（170/21/2/0x80000011/0xC00000A3）自动退避重试**最多 3 次**（300ms×(n+1)）；确定性拒绝（5 / 负 NTSTATUS）**立即失败**不重试，并提示检查 panic/保护状态。
- **RD.5** 统计**不可用**时（采样失败/驱动未连接）必须显示"统计暂不可用（原因）"，**禁止显示 0**（避免误读为"没生效"）。
- **RD.6** 连接建立/重连策略：启动握手失败 → Banner 给出三段式；运行中断连（错误 2）→ 触发 `DriverReportedUnmounted`，状态条驱动段转灰/红并自动尝试重连。
- **RD.7** 超过 1 秒的动作（自愈、回写、卸载、attach 重试）必须有"正在…"进度反馈，禁止"点了没反应"。

### 3.5 子项 E —— 版本协商与协议不匹配

- **RE.1** 启动握手（GET_VERSION）必须**硬校验协议号**：驱动协议号 ≠ 控制台期望（Protocol 9）即**拒绝连接**，并给出"驱动版本与控制台不匹配（驱动 vX / 控制台 vY）。原因：安装包与控制台不是同一版本。下一步：使用同一发布包重新安装。"
- **RE.2** 驱动三段版本号（如 `1.1 Build19`）与 UI 期望不一致时，协议一致则**软校验放行**（记 WARN），不得阻断使用。
- **RE.3** 面向用户**只显示一个版本串**：`RAMBlockCache V10.4.3 Build 19（10.3.4.19）`；驱动内部三段号仅出现在诊断页并标注"驱动内部版本（用于支持排查）"。
- **RE.4** 版本串必须来自 `Version.cs`（单一事实源 `version.h`），**禁止任何界面硬编码版本**。
- **RE.5** 协议不匹配的用户可见行为：状态条驱动段转红 + 首页异常卡 + 诊断页自检项标红，且**禁用所有写操作**（避免对不兼容驱动下发错误指令）。

### 3.6 子项 F —— 联调可观测性

- **RF.1** 诊断页必须提供**自检清单**，逐项给出"正常/异常 + 证据"，至少含：驱动连接（含错误码）、协议版本、驱动版本 vs 控制台版本、卷过滤链实际值（UpperFilters）、安全模式、熔断状态。
- **RF.2** 每条 UI 错误必须**携带可归因信息**：错误码（Win32/NTSTATUS）+ 消息号 + 时间戳，便于判断"是驱动问题还是 UI 问题"。
- **RF.3** 必须提供**一键导出诊断包**：含驱动日志（GET_LOG 64 条）、自检清单、版本信息、UI 日志，落为可交付文件供支持人员分析。
- **RF.4** UI 侧日志（`LogService`）与驱动侧日志（GET_LOG）需**可区分来源**（如 `[驱动 INFO]` vs `[UI INFO]`），并在诊断页可同屏对照时间线。
- **RF.5** 归因指引：诊断页需用一句结论性文案区分常见故障——"UI 未能打开控制设备（错误 2/3）= 驱动未加载"、"错误 5 = 权限问题"、"协议不匹配 = 版本问题"，并各自给出下一步。

## 4. 设计约束（硬约束，不可违反）

1. **语言**：界面**全中文**；术语限白名单（挂栈/加速/直写/回写/熔断/安全模式/命中率/未落盘数据）；禁止术语表见体验架构 §8.3。
2. **平台**：**Windows 桌面**（WPF 技术栈语义）；固定窗口布局，需支持 1080p / 2K 常见缩放；不追求移动端/响应式。
3. **视觉**：**深色为硬约束**（沿用 `#0E0E11` 系深色底）；颜色语义固定：**红=需立即处理 / 琥珀=降级但可用 / 蓝=就绪待配置 / 绿=正常工作 / 灰=未知/未安装**；颜色与状态文案一一绑定。
4. **六原则必须体现**（体验架构 §1.2）：P1 结论优先 / P2 状态单一事实 / P3 动作可逆 / P4 失败可解释 / P5 渐进披露 / P6 一键回到安全态。原型须逐页可验证这 6 条。
5. **12 消息全覆盖**：重设计后 UI 必须能触达全部 12 条消息能力（对齐 §3.1 映射表）；不得出现"驱动支持但 UI 不可达"（B4/B6 类断点）。
6. **每页五态**：正常 / 空 / 加载 / 错误 / 危险操作，五态齐全。
7. **危险操作护栏**：熔断、缓存系统卷、退出安全模式、卸载、回滚指引，均需"影响说明 + 二次确认"，危险按钮不做默认焦点。
8. **禁用态必须给原因**（悬停/副文本），禁止"点了没反应"；解除熔断在自愈未完成时**置灰 + 说明原因**。
9. **修复轮强相关项必须落地**：panic 自愈世代号握手后才允许解除熔断；FLUSH 失败必须以错误完成且 UI 能解释"数据未完全落盘"；CLI/UI 错误文案区分权限(5)与未加载(2/3)；默认写模式 = 直写；版本串统一 `V10.4.3 Build 19（10.3.4.19）`。
10. **原型可超越性**：本次产出必须**超越** `ux-prototype-ramblockcache-v1.html`（粗糙版）——补齐五态、真实状态机、联调错误文案、向导与应急页完整交互，达到品牌级视觉质量（Anti-Slop）。

## 6. 待用户确认项（不反问，仅记录供后续拍板）

1. **保守模式（`ramboostsetup.ps1`）是否在向导中作为一等选项**：体验架构 J1 将其列为"备选模式"，但修复轮 P1-8 明确其与标准模式**互斥、勿混用**。建议向导保留"二选一"但对保守模式加"高级/专家"标签，默认推荐标准模式——需用户确认是否保留双模式入口。

3. **64 stripe / pressure_level 等深度指标**是否面向普通用户折叠展示，还是仅保留在"导出诊断包"中（避免技术用户之外的信息过载）。
4. **旧代 `ui/wpf` 是否随本次交付一并归档**（修复轮 §5 标注"归档决策待用户拍板"），影响原型是否需兼顾两棵 UI 树的一致性表述。
