================================================================================
附录 A  硬件适配与换机策略
================================================================================

目标：换电脑后重跑脚本即可正常工作，不出现"一换机就不能用"。所有硬件相关量
均在安装/启动时动态探测，不硬编码。

A.1 CPU/核数
  - I/O worker 数、回写分区数在驱动加载时用 KeQueryActiveProcessorCount(NULL)
    获取逻辑 CPU 数（含超线程），按上限截断；
  - 分片条纹锁固定 64（远超常见核数，足够细分，不随核数变）；
  - 换机核数更多/更少都自动适配，无需改代码。

A.2 内存容量
  - 动态模式不假设总内存：每周期实时查询可用内存，安全预算
    =(可用−MemReserveMB)×AutoUsePct；
  - 内存更大→可缓存更多；更小→预算自动缩小；保底与比例保证不拖垮系统；
  - 固定模式设置值在新机器上若超过可用，自动按可用约束安全直写，不崩溃。

A.3 磁盘/卷
  - 卷在 AddDevice / GET_VOLUMES 时动态枚举（盘符、容量、扇区大小、可移动性、
    是否系统卷）；
  - 不写死卷 GUID/盘符/数量；新机磁盘数、接口（SATA/NVMe）不同均自动识别；
  - 每卷独立策略，默认系统卷直写、数据卷回写。

A.4 证书/签名
  - 与机器硬件无关；新机首次安装时若本机无证书，安装脚本自动新建并信任
    （CNG，100 年），再签名；
  - 也可手动导出旧证书（含私钥）导入新机，但通常直接重建更简单。

A.5 换机操作清单
  1) 安装 VS(C++ 桌面) + WDK（或使用打包好的发布产物，免编译则只需管理员权限）；
  2) 拷贝工程/产物到新机；
  3) 双击 scripts\install.cmd，UAC 点是，等待自动签名/注册/挂载；
  4) 重启一次，打开控制台确认各卷已识别并按需加速。
  （目标即"双击 + 一次重启"，其余全自动。）

附录 B  显存（GPU VRAM）作为缓存的可行性结论
================================================================================

问题：RTX 4070 显存速度看起来很快，不打游戏/GPU 空闲时，能否用显存做缓存，
效果是否更好？

结论：【不建议、本产品不采用】。在"CPU 侧块缓存"场景下，显存比系统内存
【更慢、更不可靠】，收益为负。理由：

B.1 真正的访问路径是 PCIe，不是显存本地带宽
  - 显存的高带宽（GDDR6）只有 GPU 自己的 CUDA 核心能"本地"享受到；
  - CPU（以及内核块驱动）要读写显存，数据必须经 PCIe 总线在系统内存↔显存间
    往返；CPU 经 PCIe 访问显存的【延迟】显著高于直接访问本机 DRAM（实测/资料
    口径慢约 4 倍以上），且可用带宽受 PCIe 版本/通道数与复用影响。
  - 缓存的核心价值是"低延迟命中"。用显存做缓存，命中路径反而更慢，违背目标。

B.2 内核块驱动无法直接、安全地使用 CUDA
  - CUDA 运行时主要是用户态模型并依赖 NVIDIA 内核驱动与显式上下文；卷块过滤
    驱动工作在其独立内核上下文，不能在读写快路径里建立/依赖 CUDA 上下文；
  - GPU 处于空闲降频、睡眠、驱动重置、TDR、休眠/唤醒、多显卡切换时，显存
    内容与映射可能失效，块缓存无法保证随时可用，这对存储缓存是致命的。

B.3 生命周期与一致性问题
  - 显存内容在掉电、休眠、GPU 驱动重启后丢失/失效；
  - 把脏数据放显存会引入额外丢失窗口与复杂的同步/回滚，得不偿失。

B.4 资源争用
  - 一旦开始游戏/CUDA 负载，被缓存占用的显存需紧急腾挪，造成卡顿，与"游戏
    体验"直接冲突。

综合：显存适合 GPU 本地高吞吐计算，不适合充当 CPU 侧、需要稳定低延迟的硬盘
缓存。本产品专注用系统内存（DRAM）做 L1 缓存。GPU 空闲借用仅在"用户态、可
容忍延迟与失效"的特殊应用才有意义，不在本产品范围。

Block / 子块   4KB 最小缓存/命中/脏粒度
Chunk / 大块   64KB，含 16 子块，分配/哈希/LRU 单位
LRU            最近最少使用链，回收冷数据依据
脏链           记录待回写子块/块的链
Write-through  写透传：写同时落盘
Write-back     写回：写先入内存，后台落盘
Read-back      补读：部分写/读 miss 时从盘补回旧数据
L1/L2 缓存     一级=内存；二级=SSD 持久缓存（本产品当前仅 L1）
Striped lock   分片条纹锁：按偏移哈希到多把锁，降低争用
2PL            两阶段加锁（本项目多片按升序一次性获取）
IRQL           中断请求级别（PASSIVE/APC/DISPATCH）
PnP            即插即用
IRP            I/O 请求包
Minifilter     文件系统微过滤器（V7 形态）
Upper filter   设备栈上层过滤驱动（V8 形态）
testsigning    测试签名模式（允许加载自签驱动）
HVCI           基于虚拟化的内存完整性（核心隔离）
EFS            加密文件系统
Vanguard       Riot/Valorant 内核反作弊
SafeMode        异常重启后的保守直写状态
CNG            Windows 下一代加密 API/密钥提供程序
WHQL           Windows 硬件质量实验室（微软签名，需付费/流程）
diskspd        微软官方磁盘性能测试工具
