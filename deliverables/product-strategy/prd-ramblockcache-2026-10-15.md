## 1. 产品概述

### 1.1 定位

RAMBlockCache 是一款 **Windows 内核块缓存过滤驱动 + 用户态缓存引擎**：把物理内存用作非缓冲 I/O 的读/写缓存层，位于文件系统 minifilter 层（海拔 373000），对应用透明——用户不需要改任何应用路径或设置。产品形态 = 已签名 .sys + 用户态引擎（src/core）+ CLI `ramboostctl` + WPF 五页控制台 + SHA256 哈希锚点 fail-closed 部署脚本。

### 1.2 价值主张

对「盘慢、内存有富余、不想花钱换硬件」的 Windows 用户：**重复读写第二次起飞，小块随机写合并减少 SSD 写放大，全程应用零改动，出事能一键回到"什么都没装"的状态**。安全设计（脏块不淘汰、关机全量回写、异常退出安全模式）默认可见、默认生效，而不是靠用户自觉研究参数。

### 1.3 与 PrimoCache 的本质差异

| 维度 | RAMBlockCache | PrimoCache（品类主导者） |
|---|---|---|
| 工作层级 | 文件系统 minifilter（Cc 之上），**V7 定稿仅加速非缓冲 I/O** | 卷级扇区过滤驱动（Cc 之下），全部 I/O 可见（含分页 I/O） |
| 普通缓冲应用 I/O | V7 透明旁路（V8 块层路线图） | ✅ 覆盖 |
| 持久性 | 无 L2，重启清空重新预热 | L1+L2 双级，L2 SSD 持久缓存（重启即热） |
| 安全工程 | 防蓝屏 IRQL 规范 + 已证实崩溃修复台账 + 异常退出安全模式 + 部署 fail-closed 门禁 | 15 年口碑，但官方 KB 明示延写断电丢数据、建议 UPS |
| 形态 | WPF 五页 + CLI + 部署脚本，中文原生 | GUI+CLI，英文为主（有中文站） |
| 价格 | 未定（建议见 §16 待确认问题 ②） | $29.95/台 perpetual 起 |

**本质差异一句话**：PrimoCache 强在"层级位置带来的覆盖与持久性"，本品强在"安全工程与部署可控"——社区决策因素排序（信任/蓝屏记录 > 数据安全设计 > 价格授权 > 安装门槛 > 效果感知 > 性能参数，来源：瑞思·用户研究综合 §4.1 / 竞析 §4.1）恰好在安全侧给本品留出差异化空位。

### 1.4 范围边界（V7 定稿口径）

| I/O 类型 | 是否加速 | 依据 |
|---|---|---|
| 非缓冲 I/O（FILE_FLAG_NO_BUFFERING） | ✅ 读+写 | 仓库底稿 12-V7架构定稿 §1 |
| 缓存方式普通应用 I/O | ❌ 透明旁路 | 同上；V8 块层路线图 |
| 分页 I/O | ❌ 透明旁路 | 同上（消除与 Cc 双写冲突的结构性根因） |
| NTFS 元数据 / 系统卷关键路径 / 压缩 / 稀疏 / EFS 加密文件 | ❌ 透明旁路 | 同上 |

平台边界：Win10 1809+ / Win11（含 26H2）、x64、NTFS 卷（FAT/exFAT/ReFS 不附加）；建议内存 ≥8GB；缓存大小默认自动预算（物理内存 25%，上限 32GB）。

## 2. 产品目标

> 三个目标正交：目标一管"敢不敢用"（信任），目标二管"有没有用"（价值感知），目标三管"用不用得下去"（激活留存）。成功指标引用数析 KPI 树（data-insights §3）。

### 目标一（信任）：把"确定感"做成可出示的证据链

**一句话**：在首发门禁前完成验证基建与正式签名 + HVCI 兼容，使"可归因蓝屏率 = 0、部署门禁误拦截 = 0、卸载干净率 = 100%、LostDirtyBytes 非零事件 = 0"成为可验证、可出示的产品证据，而不是文档承诺。

| 成功标准 | 目标值 | 来源 |
|---|---|---|
| B1 归因本驱动蓝屏率 | **0**（内核产品无可接受崩溃率） | 数析 §3.3 B1 |
| B2 LostDirtyBytes 非零事件 | 0；FLUSH 失败穿透率 100%（失败必须报失败） | 数析 §3.3 B2 |
| B3 部署成功率 / 卸载干净率 | ≥99% / 100% | 数析 §3.3 B3 |
| B4 panic 恢复握手成功率 | 100% | 数析 §3.3 B4 |

### 目标二（价值感知）：3 秒内看见效果，数字随使用增长

**一句话**：挂载即验证（3 秒内显示"已加速·命中率 xx%"）+ 首页三数字 + "本次开机累计省下磁盘读"累计叙事，以 North Star 指标「周活跃设备周命中读取数据量」衡量，健康水位 20-60 GB/设备/周（估计初值，待首批遥测校准）。

| 成功标准 | 目标值 | 来源 |
|---|---|---|
| A1 读命中率（块级） | 日常桌面负载 70%-90%（新装前 7 天允许 30%-60%） | 数析 §3.3 A1 |
| A3 应用可感知加速比 | P95 读延迟下降 30%-60%；4K 随机读 IOPS 提升 3-10 倍 | 数析 §3.3 A3 |
| North Star | 20-60 GB/设备/周（冷启动目标） | 数析 §3.1 |

### 目标三（激活留存）：从安装到持续启用的漏斗不断链

**一句话**：安装成功率 ≥99% 之后，装机用户中 ≥80% 启用至少一个缓存卷、D30 留存 ≥40%、30 天后缓存持续启用率 ≥60%——用留存而非跑分证明产品价值。

| 成功标准 | 目标值 | 来源 |
|---|---|---|
| 缓存卷启用率（激活率） | ≥80% | 数析 §3.3 B4 |
| WAU/MAU | ≥40% | 数析 §3.3 B4 |
| 留存 D7 / D30 | ≥50% / ≥40% | 数析 §3.3 B4 |
| 缓存持续启用率（30 天） | ≥60% | 数析 §3.3 B4 |

## 5. 用户研究洞察（精选对功能设计有直接约束的发现）

来源：瑞思《用户研究综合》§7.1（R1-R6）+ §4 痛点清单。

**流失链判断**（瑞思 §4 小结）：信任→数据→效果→门槛构成「不敢装 → 不会装 → 装了没感 → 卸了」完整流失链；PRD 优先级排序以打断该链为先，而非先堆性能参数。

## 9. 用户流程（文本流程图）

### 9.1 首次安装向导（对齐 01-requirements §2.3，U1）

```
启动控制台 → 状态「未安装」→ 运行安装向导
  → ①环境自检（管理员权限 / 驱动状态 / 残留 UpperFilters / 是否需重启）
  → ②安装模式二选一（标准=挂栈+需重启【默认推荐】/ 保守=运行时挂载+免重启【高级/专家标签】）
  → ③首次加速（默认勾选非系统数据卷 + 默认直写 + 缓存大小默认 0=自动预算）
  → 部署门禁校验（SHA256 + 签名，fail-closed）→ [需重启] → 重启后续跑（幂等）
  → 挂载即验证：3 秒内卡片显示「已加速·命中率 xx%」
  → 状态「加速中·直写」
```

### 9.2 加速配置（U3）

```
加速页 → 卷列表（盘符/卷标/容量/状态/写模式）→ 逐卷开关
  → 写模式切换（直写默认；切回写 = 危险操作护栏：影响说明 + 二次确认 + "异常退出可能丢未落盘数据"一句话确认）
  → 即时生效（SET_VOLUME 结果反馈，失败三段式报错并保持原状态，不乐观更新）
```

### 9.3 日常使用

```
1 秒轮询（GET_STATS/GET_VOLUMES）→ 状态条四段（驱动·挂栈·加速·风险）
  → 首页三数字（命中率 / 省下磁盘读 / 缓存占用）随使用增长
  → 收益页：命中率趋势 / 累计省下磁盘读 / 脏量与回写速率
  → 内存预算：自动（物理内存 25%，上限 32GB）+ 空闲自动释放；占用与机会成本可见（P1-06）
```

### 9.4 异常处置（U4/C8）

```
异常退出后开机 → 驱动自动进入安全模式（直写降级）
  → UI 红色横幅说人话（发生了什么/为什么/下一步）→ 用户一键确认恢复 → 回「就绪/加速」
另分支：panic 熔断 → 状态条转红「熔断中·全局透传」→ 自愈进行（进度可见）
  → 自愈完成才可点「解除熔断」（未完成置灰 + 说明原因，0xC00000A3 文案映射）
另分支：LostDirtyBytes > 0 → 风险段变琥珀 + 核对入口（未落盘/已确认丢失 MB 一致呈现）
```

### 9.5 卸载回滚（U6/R5）

```
设置页卸载入口（危险操作护栏）→ 卸载前全量回写（>1 秒动作有进度反馈）
  → 恢复 UpperFilters/服务/计划任务 → 明示「已保留第三方卷过滤器」
  → 应急页回滚三步图 + 导出救援卡（含 WinRE 步骤与 offline_rollback.cmd 路径）
  → 卸载干净率 100% 验收（B3）
```

## 10. 交互逻辑（产品级约束，引用对齐 01-requirements.md）

> 本节为产品级约束摘要；字段级细节以 `deliverables/design/01-requirements.md`（RB.1-RF.5）为唯一事实源，本文不复制。

1. **6 态状态机**：未安装 / 已安装未挂栈 / 就绪未加速 / 加速中·直写 / 加速中·回写 / 降级·安全模式 / 熔断·全局透传（含"自愈中"子态）。驱动字段 → 用户态必须经**唯一判定函数**（RB.2）；面向用户界面只允许 6 态文案 + 术语白名单（RB.3）。
2. **12 消息触点**：Protocol 9（IOCTL 0x222000）12 条消息必须各有唯一主触点，不得出现"驱动支持但 UI 不可达"（RA.1/C1）；跨页复用必须来自同一前端状态对象（RA.2）；所有写操作必须有结果反馈，失败三段式 + 保持原状态（RA.3）。
3. **错误码三段式**：发生了什么 / 为什么 / 下一步做什么，集中映射表至少覆盖 Win32 5/2/3/21/170/87 与 NTSTATUS 0x80000011/0xC00000A3/0xC0000011（RC.1/C3）；权限(5)与未加载(2/3)必须可区分（RC.2）；所有错误必须含可点击"下一步"动作（RC.5）。
4. **危险操作护栏**：熔断、缓存系统卷、退出安全模式、卸载、回滚指引均需"影响说明 + 二次确认"，危险按钮不做默认焦点；禁用态必须给原因（01-requirements 设计约束 7/8）。
5. **降级不静默**：统计不可用显示"统计暂不可用（原因）"禁止显示 0；轮询单次失败不停更、连续失败指数退避至 ≤10s（RD.1/RD.2/C4）。
6. **版本协商**：协议号不一致即拒绝连接 + 禁用所有写操作；面向用户只显示一个版本串（RE.1/RE.3/U8）。

## 14. Non-goals（明确不做什么）

1. **不做订阅制**——对齐品类 perpetual 心智（竞析 §5.2）；授权形态为一次性买断 + 大版本内免费更新。
2. **不承诺大文件拷贝加速**——带宽约束下 SSD 本身已够快（延迟差约 1000 倍 vs 带宽差 5-10 倍，数析 §2.4）；禁用大文件顺序读写作为宣传指标。
3. **不做 NVMe 顺序读加速叙事**——Gen5 SSD 顺序读已 14GB/s 量级，RAM 缓存边际收益低（竞析 §8.2）；对外只讲随机小块与重复读。
4. **V8 块层落地前不承诺普通应用加速**——V7 定稿仅非缓冲 I/O；普通缓冲应用与分页 I/O 透明旁路（仓库底稿 12 章）；UI/外宣口径以此为准，不得引用旧 FAQ 表述。
5. **不承诺 100% 不蓝屏**——内核驱动固有风险；对外只讲"可归因蓝屏率 0 的证据链 + 安全模式 + 回退路径"。
6. **不做缓存系统卷默认开启**——默认关闭（最安全），可手动开启且走危险操作护栏。
7. **不做块大小运行时热切换**——V7 明确强重建 UAF 风险；切换引导至"回写脏=0 → 重载驱动"流程。
8. **暂不做**：FAT/exFAT/ReFS/网络驱动器、32 位/ARM64、Server 版/NUMA、未识别内存（UIMMI）、破解/注册机相关生态零容忍。
9. **不做响应式/移动端/平板形态**——桌面固定窗口（01-requirements 设计约束 2）。
10. **不以 CrystalDiskMark 短时跑分作为成功标准**（社区权重最低，竞析 §4.1；数析 §4.1-1）。
