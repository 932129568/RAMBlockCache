# 11 实机验证清单（Windows 实机 A/B 验收）

> **说明**：本包是 **Windows 包**；驱动内核运行时行为（加载 / attach / IRQL / 并发）
> **尚未在真实 Windows 11 26H2 上加载验证**（此前只能在用户态沙箱编译与自测，无法
> 加载内核驱动；并非"Linux 环境"问题）。以下为在**隔离虚拟机快照**中逐项验收的清单。
> **禁止在用户生产机上执行，尤其禁止在系统卷上做缓存/蓝屏验证、禁止直接拔电**；
> 请在可回滚的虚拟机快照或可弃用的专用非系统数据盘（如 D 盘）上验证，并先备份重要数据。

## 0. 前置

1. 按 `docs/01/02/05` 编译、自签名、开测试签名、安装驱动（**注意 `scripts\install.cmd` 当前不可用**，请用 `setup\ramboostsetup.ps1`）。
2. 打开 WPF 控制台（`dist\wpf\RAMBlockCache.Controller.exe`；**本包未提供 `scripts/serve.cmd`**），确认"已连接"，分页 IO 缓存开关=开，
   缓存大小=自动（0）。
3. 准备测试盘：数据卷（如 D:，NTFS），放 2~4GB 测试文件（如视频/压缩包）。

## 1. 功能验收（每项 1 分钟）

| # | 验证项 | 方法 | 预期 |
|---|---|---|---|
| 1 | 普通应用命中 | 反复打开同一个大文件/软件（走系统缓存的 IO） | 控制台读命中率从 0 上升到 >30% |
| 2 | 无缓冲 IO 命中 | 用 `crystaldiskmark`/`diskspd -b64K`（FILE_FLAG_NO_BUFFERING）反复测同一区间 | 第二次起读命中率接近 100% |
| 3 | 写缓存吸收 | 拷贝 2GB 文件到 D 盘，观察"缓存吸收" | 吸收率 >80%，回写字节随后跟上 |
| 4 | 句柄关闭落盘 | 拷贝后立即 `ramboostctl flush`，再强制断电模拟前先正常关机 | 无脏数据残留（LostDirty=0） |
| 5 | 立即回写 | 控制台"立即回写" | 脏数据降到 0 |
| 6 | 配置持久化 | 改 size=16384 → 重启 → `ramboostctl config` | 仍为 16384 |
| 7 | 水位在线同步 | `ramboostctl set high=50 low=30` → 观察 | 高水位生效（脏数据到 50% 即开始回写） |
| 8 | 自动预算 | 删注册表 Parameters 后重启，`ramboostctl config` | size=0，生效大小=物理内存 25%（64G→16G） |
| 9 | 系统卷开关 | **仅在隔离虚拟机快照**中勾选缓存系统卷 → 重启（**禁止在用户生产机的系统卷上执行**） | 虚拟机内 C 盘 IO 命中上升；不勾选则无 |
| 10 | 安全模式 | 在隔离虚拟机快照中触发蓝屏/断电后开机（**禁止直接拔电、禁止在生产机操作**） | 控制台出现安全模式横幅；写直写；确认后恢复 |

## 2. 数据一致性（重点，逐项核对哈希）

```bat
:: 准备：生成 1GB 随机测试文件
fsutil file createnew D:\rb_test\a.bin 1073741824
certutil -hashfile D:\rb_test\a.bin SHA256 > a.before.txt
```

| # | 场景 | 步骤 | 预期 |
|---|---|---|---|
| 1 | 回写模式读写一致 | 开启写缓存回写，循环读写 a.bin 20 次（每次写不同内容） | 每轮读回哈希与写入内容一致 |
| 2 | 短写/扇区对齐 | 用 `diskspd -t2 -o8 -b4K -w100` 压力写 10 分钟 | 无 STATUS_INVALID_PARAMETER、无蓝屏 |
| 3 | 4Kn 卷（若有） | 在 4Kn 原生扇区盘上重复 #2 | 同上（验证对齐分配修复） |
| 4 | EFS 加密文件 | 对 a.bin 右键"属性→高级→加密"，重复读写 | 读回内容正确（非密文） |
| 5 | 多句柄同文件 | 两个进程同时写同一文件不同区域（diskspd -t2 同文件） | 最终哈希 = 最后完成写入的内容，无错乱 |
| 6 | 断电模拟 | **仅在隔离虚拟机快照**中：写大量数据（未回写完）→ 用虚拟机"强制断电"开关关机 → 开机。**禁止直接拔电、禁止在用户生产机执行** | 系统能进、文件系统无损（回写缓存的固有权衡：最后一批未确认写入可能丢，安全模式接管） |
| 7 | 关机保存 | 写入后正常关机再开机 | 数据完整（关机回调全量回写） |

## 3. 与 PrimoCache 的 A/B 对比（同一台机器）

> 先装 RAMBoostFS 测一轮 → 卸载 → 装 PrimoCache 试用版（30 天）测一轮，
> 条件完全一致（同一文件、同一磁盘位置、同一 workloads）。

| 对比项 | 工具 | 方法 |
|---|---|---|
| 顺序读 | CrystalDiskMark SEQ1M Q8T1 | 各跑 3 次取中位 |
| 随机读 4K | CrystalDiskMark RND4K Q32T16 | 同上 |
| 随机写 4K | CrystalDiskMark RND4K Q32T16 | 同上 |
| 重复读命中 | diskspd 同一区间循环读 100 轮，对比吞吐 | 首次 vs 第 50 轮 |
| 写放大 | Windows 资源监视器 / SSD 厂商工具看写入量，对比两次 10GB 拷贝 | 回写 vs 直写 vs PrimoCache 延迟写入 |
| 启动软件耗时 | 关闭所有缓存 → 开缓存，各启动同一大型软件 5 次计时 | 平均值对比 |
| 稳定性 | 连续 72h 常规使用 + 游戏 2h | 无蓝屏、无文件损坏 |

**记录表**：按上述每项记录三列（无缓存 / RAMBoostFS / PrimoCache），
差值>5% 视为显著。命中率对照可直接用 RAMBoostFS 控制台自带统计；
PrimoCache 用其监视窗口。

## 4. 已知边界（如实记录，验收时一并确认）

- FAT/exFAT/ReFS 卷不附加（设计如此）；
- 未映射网络驱动器（RAMBoostFS 仅本地卷）；
- 写回缓存的断电丢数据为固有权衡（PrimoCache 同样存在，官方建议 UPS）；
- 混合"缓冲 + 无缓冲"句柄写同一文件存在 Windows 自身的可见性语义，不属于
  本驱动引入的问题（PrimoCache 同样存在）；
- 分页 IO 参与会占用额外内存（系统缓存 + 本缓存双份），内存 <16G 的机器
  建议关闭 `CachePagingIo`。
