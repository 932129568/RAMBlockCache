## 本轮三项优化

### 1. 单 chunk 锁获取快路径【高并发直接收益】

**位置**：`core/cache.c` → `lock_stripes()`

**问题**：每次 IO 都无条件跑一遍 **O(n²) 去重循环 + 插入排序 + 加锁遍历**。而 4K/64K 单块 IO（随机读写的 100% 场景、顺序 IO 的绝大多数）只涉及**一个 stripe**——n==1 时那些循环是纯浪费。高并发下这些指令争同一执行端口，属于"看不见的 CPU 税"。

**优化**：
```c
if (cs == ce) {            // 单 chunk：直接取锁返回
    k = stripe_of(cs);
    lock(stripes[k]);
    held[0] = k;
    return 1;
}
```

**收益**：单块 IO 的锁准备开销从 ~O(1) 环 + 排序降到 3 条指令；对 4K 随机 IOPS 场景最直接。

### 2. 日志拷贝移出自旋锁【高并发锁争用】

**位置**：`driver/rbdriver.c` → `RbLog()`

**问题**：`KeAcquireSpinLock` 内做 `RtlStringCchCopyW`（最长 96 wchar 的**变长循环拷贝**）。故障风暴时多核同时打日志，每个 CPU 排队等这把全局锁，**锁持有时间被拷贝拉长数倍**——表现为"日志一多整个 I/O 路径变慢"。

**优化**：先在锁外把文本拷进栈缓冲，锁内只做固定长度搬运。

**收益**：锁临界区缩短到纯内存写（无循环无分支），日志风暴下的 I/O 抖动显著降低。

### 3. 命中计数采样：**试做后回退**（记录决策）

**尝试**：把 `hits++`（每 IO 一次跨核原子）改为 1/64 采样，消除热块缓存行 ping-pong。

**结果**：`test_evict_wire` 契约断言失败（`chunk fill+1命中 → Hits==1` 得到 0）。

**回退理由**：`hits` 是 **L2 淘汰过滤的判定依据**（`Hits<2` 即判为冷块并送入 L2）。采样会让"刚热起来"的块被误判成冷块、被送进 L2 存储——**语义被破坏**。正确性优先于这点 CPU。

> 这条记录保留在代码注释里（`[OPT-HITS]`），避免后人重犯。
