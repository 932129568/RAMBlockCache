## 1. 功能模块逐项梳理与升级

### 1.1 诊断日志系统【本轮重点升级】

**问题（实测确认）**：
- 环容量 **64 条**，日志按 8 秒级写入 → **历史不到 1 分钟即被覆盖**
- 文本上限 **48 字符**，仓库内 **61 处日志文案超过该长度被截断**
- 0x7B 事故复盘时无法拿到"崩溃前最后几条完整日志"，只能靠推测

**升级（三层）**：

| 层 | 改动 | 兼容性 |
|---|---|---|
| 驱动环 | 64→**512 条**；文本 48→**96 字符**；新增单调 `Seq` | 内部实现，无外部影响 |
| **新 IOCTL** `0x809` | 新增 `ctl/rb_logq.h`（独立 ABI 头）：按 Seq 游标分页，单批 32 条，不受 8224B 信封限制 | 协议版本不变（Protocol 9），`check_proto_sync` PASS |
| **桥接落盘** | 新增 `bridge/server/log-sink.ts`：2 秒增量拉取 → 追加写 `%ProgramData%\RAMBlockCache\logs\driver-YYYYMMDD.log`；单日 8MB 滚动保留 3 份 | 只读，失败静默降级 |
| 原生插件 | 新增导出 `rb_log_page(fromSeq, maxCount)` | 接口可选（旧插件仍可用，桥接自动跳过） |

**旧接口保证**：`RB_MSG_GET_LOG` 的 `RB_LOG_LIST`（64×48）结构与语义**完全不变**——驱动内部把 512×96 记录**转译截断**为 64×48 输出，字段/顺序/截断行为逐字节一致。

**效果**：故障现场可回溯**完整 512 条日志 × 96 字符**，且**持久化到磁盘**，重启不丢。

### 1.2 卷枚举【本轮升级】

**问题**：OEM 恢复分区/EFI 系统分区/未分配盘符的卷在列表中显示为空盘符的 `•` 行——界面噪声，且无盘符即无法 attach/detach（无操作价值）。

**升级**：枚举时过滤 `Letter == 0 && Attached == 0` 的实例；**已加速的实例保留**（用户可能靠它排障）。

**兼容性**：`RB_VOLUME_LIST` 结构与 `Count` 语义不变（只减少噪声项）；CLI/Web 无需改动。

### 1.3 驱动版本可见性【本轮升级】

**问题**：`GET_VERSION` 在传输层存在但**零消费**——换机/升级后确认"跑的是哪个构建"只能靠命令行。

**升级**：状态页新增常驻**驱动版本卡**（版本号 / 签名者 / 测试签名态）。
