## §3 根因（F1）：不是切片代码的问题，是 store 根本没发生几次

### 3.1 唯一实证

驱动日志 `C:\ProgramData\RAMBlockCache\logs\driver-20261113.log:26`：

```
2026-11-12T17:27:11.561Z WARN [890] l2: evict rejected (cold, hits<2) [diag O9]
```

`rbfeat.c:886 if (Hits < 2) return;` —— 驱逐时块级命中次数不足 2，被拒收。
（该诊断按 1/4096 采样，**1 条日志代表约 4096 次同因拒绝**。）

另核对了另一条可能的门：`rbL2.c:1168 if (len != RB2_L2BLK) return;`（只收 64KB 整块）。
驱动日志里**没有** `store rejected (len!=64KB)` 记录 ⇒ 长度门不是原因。

### 3.2 为什么本轮 Hits 不足，而上一轮是 2051

| | 上轮 `l2-p0c-20261112T154807Z` | 本轮 `l2-p0c-20261112T172701Z` |
|---|---|---|
| boot | 同一 boot 内**第二次**运行 | 本 boot **首次**运行 |
| baseline L2 计数 | `l2s=3 l2m=12`（已累积） | `l2s=0 l2m=0` |
| `post-load` coreHit / coreMiss | 537 / 3120 | 269 / 1033 |
| `pre-shrink` | `coreHit=537 coreMiss=3120` | `coreHit=269 coreMiss=1033` |
| `shrink 100` 后 | `l2s 3 → 2051`（+2048） | `l2s 3 → 3`（+0） |
| 阶段 A | 2048 块，最长连号 474 | 7 块，最长连号 1 |

同一驱动、同一夹具、同一 `-ProbeStats -PostC -P5B`，**唯一变量是 core 里块的既有热度**。

### 3.3 机制

```
store 唯一入口：eviction → RbFeatOnEvict → rbfeat.c:886 `if (Hits < 2) return`
Hits 来源：      cache_read.c:47 `InterlockedIncrement(&c->hits)`（仅命中时 +1）
```

一次「写 + 3 遍读」在**理想**情况下给出 `miss(Hits=0) → hit(Hits=1) → hit(Hits=2)`，刚好压线。
但 128 MB 的 sweep 在动态水位低于文件大小时会发生**再次驱逐**，后面的 pass 又 miss，
Hits 停在 0/1 ⇒ 驱逐时被 cold 拒收。上一轮的 2048 块之所以能过，是因为它们来自
**更早一次运行留下的块**（Hits 早已远超 2）。

补充事实（解释了为什么不能靠"多 shrink 几次"解决）：
`cache_evict.c:224` 的 `idle_reclaim` 只回收 `!c->dirty && c->last_access <= now - idle_reclaim_ms`，
而 `IdleReclaimSec=1800` ⇒ **30 分钟内访问过的块永远不会被 idle_reclaim 回收**。

## §4 已做的修复（只改夹具，未动驱动、未重签、未部署、未重启）

`deliverables/RB-l2-p0c-test.ps1` 新增 **C-SLICE warm-up**（仅在 `-SliceTest -and -P5B` 时执行）：

1. 阶段 A 之前，最多 3 轮：**只读文件前 16 MB（256 × 64 KB）3 遍 → `shrink 100` → 重扫容器**
2. 每轮打印 `blocks=N longest consecutive run=M`，凑到 `M >= 16` 立即停止
3. 新增 `Invoke-UnbufferedReadPass -MaxBytes` 参数（默认 0 = 读全文件，向后兼容）
4. 3 轮仍不足则 `SayWarn` 并在阶段 D 如实标 `skipped`（保持 `$SliceExit=-1` ⇒ WARN 而非 FAIL）

**为什么是 16 MB 而不是 128 MB**：短区间能在 core 里完整驻留 3 遍（Hits 必然到 2），
且驱逐时是一整段连续块——正是阶段 D 需要的形状。
