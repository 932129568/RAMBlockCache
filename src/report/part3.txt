3.2 WPF 控制台页面（ui/wpf）
--------------------------------------------------------------------------------
采用 Win11 Fluent 风格、.NET 8、MVVM；左侧导航 + 内容区，含流畅过渡动画
（克制不堆砌）、深浅色与主题资源、自定义开关/折线图/分片热力控件。
页面：
  (1) Dashboard 仪表盘
      - 总开关、当前模式（加速/直写/安全模式）徽标；
      - 读命中率、写吸收量、内存压力、驱动块层信息卡；
      - 实时吞吐趋势折线图（读/写/命中）；
      - 64 分片吞吐热力条（多核并行可视化）；
  (2) Volumes 卷管理
      - 枚举所有卷（系统卷/数据卷/光驱），显示容量、绑定/加速徽标；
      - 每卷独立：加速开关、读使能、写使能、写模式下拉（透传/回写/跟随全局）；
      - 系统卷默认强制直写并明确安全提示；
  (3) Memory 内存
      - 动态/固定模式切换；动态显示实时可用、已缓存、保底、安全预算；
      - 缓存大小设置（0=自动；显式 MB）、MemReserveMB、AutoUsePct；
      - 脏水位百分比、延迟写入间隔、写后释放、空闲回收开关与时长；
      - 内存压力等级指示与"立即回收/立即刷盘"按钮；
  (4) Security 安全
      - 安全模式状态与"退出安全模式"；
      - 蓝屏防护各开关说明、关机落盘、异常重启识别；
      - 签名/证书状态、testsigning 状态、游戏模式入口；
  (5) Log 日志
      - 内核环形日志实时查看（级别/来源/状态/文本），支持过滤与导出。
通信：RbClient 经 CreateFile(\\.\RAMBlockCache)+DeviceIoControl(IOCTL 0x222000)；
      另提供 MockRbClient 用于无驱动时的界面演示。

3.3 配置项字典（RB_CONFIG，含默认值与合法域）
--------------------------------------------------------------------------------
字段                 默认        合法域 / 钳制规则
CacheSizeMB          0           0=动态；>0 固定上限（无强制最大值，受可用内存约束）
MemReserveMB         4096        留给系统保底；建议 ≥2048
AutoUsePct           80          1–95（%，只借可用空闲的比例）
FlushIntervalMs      60000       1000–3600000（周期回写）
DirtyHighPct         60          50–95（脏到该比例触发回写）
DirtyLowPct          40          5–90，且 < DirtyHighPct（回写目标）
WriteBack            1           0=透传 1=回写（全局默认）
BlockSize            4096        {4096,8192,16384,32768,65536,131072}，非法回落4096
IdleReclaimEnabled   1           0/1
IdleReclaimSec       1800        60–86400（空闲多久回收冷块）
WriteRelease         1           0/1（落盘后是否释放块）
ReadaheadEnabled     0/1         顺序负载建议开
ReadaheadWindow      2MB         预读窗口
ParallelFlush        1           0/1（zone 并行回写）
AutoAttach           1           0/1（卷挂栈即自动入缓存，系统卷除外）
ProtocolVersion      8           与驱动 build 对齐
说明：
  - "不设上限"的含义：动态模式（0）下不人为封顶，硬顶=按实时可用内存算出的
    安全预算，天然不会超过物理可用；固定模式允许任意指定，但实际仍受可用内存
    与保底约束（超出部分安全直写），不会因设大而崩溃。
  - BlockSize 变更随驱动重载生效（当前不做运行时热切换，避免几何迁移风险）。

3.4 写模式语义
--------------------------------------------------------------------------------
THROUGH(0)：写同时落盘才完成（最安全、无断电丢失窗口）。
BACK(1)   ：写先入内存即完成，后台按策略落盘（最快、有受控丢失窗口）。
GLOBAL(2) ：该卷跟随全局 WriteBack 设置。
系统卷（C:）：默认强制 THROUGH（避免系统关键数据进入回写窗口），是否对系统卷
启用加速需用户明确决定（见第 7 章未决项）。

3.5 游戏模式与内核反作弊（Valorant/Vanguard）★用户重点
--------------------------------------------------------------------------------
事实：开启 testsigning（测试签名模式）后，带内核级反作弊的游戏（如 Valorant
无畏契约 / Vanguard）会拒绝启动；普通软件不受影响。
合规结论：【不存在】"让反作弊识别不到 testsigning / 隐藏测试签名 / 欺骗 CI-DSE"
的正当办法，任何此类尝试都会被判定为作弊并可能导致封号。本产品不提供、不尝试
任何隐藏或欺骗。
正确用法（双模式一键切换 + 重启）：
  - 玩游戏前：game_mode game → bcdedit /set testsigning off → 重启 →
    驱动不加载、Vanguard 正常启动；
  - 需要加速：game_mode accel → bcdedit /set testsigning on → 重启 →
    恢复内存加速。
脚本 scripts/game_mode.ps1 / game_mode.cmd（菜单或参数 game/accel，自带 UAC 提权）；
WPF 安全页亦有入口。此重启是 Windows 对 testsigning 的硬性要求，无法免重启。

3.6 特殊场景（来自 PrimoCase 公开更新日志的对标核验）
--------------------------------------------------------------------------------
以 PrimoCache v2.0.1→v4.4.1 公开更新日志为线索，逐条核验本产品是否存在同类问题：
  - 电源/关机路径丢脏数据：已由关机全量落盘覆盖；
  - 写放大（部分写导致整大块重复写）：RMW 精确到 4KB，用例固化"回写恰好 8KB"；
  - 可移除介质意外移除：可移除介质安全处理、移除时不落盘到已消失设备；
  - 损坏缓存/坏道：补读失败直写、脏块保留、lost 精确计数；
  - EFS（加密文件系统）：块层只缓存密文块，无额外密钥/明文问题，天然免疫；
  - HVCI（内存完整性/核心隔离）：块驱动不做被 HVCI 禁止的操作（如动态内核代码、
    不兼容的页属性），可与 HVCI 共存（真机需在安全中心确认无冲突）；
  - L2 二级缓存（SSD 上的持久缓存）：本产品定位 L1（内存）缓存，内存态天然无
    "L2 缓存损坏"问题；L2 为后续可选功能（见第 7 章）。
注：以上为设计层核验，HVCI/真机行为仍需在真机确认。
