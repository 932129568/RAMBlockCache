5.5 静态专项审查（人工 + 只读审查 agent）

引用计数：流/扩展/工作项的 io_users、Refs 取还配对；REMOVE/flush 快照路径
          先引用后使用、完成后释放，未发现失衡。

第 6 章  部署、真机验证与用户操作指南
================================================================================

6.1 一键部署（推荐，保留"无需用户懂技术"的版本）
--------------------------------------------------------------------------------
前置：已按 docs/01 安装 VS 2022（含 C++ 桌面开发）+ WDK（本机已具备）。
步骤：
  1) 以【管理员】或直接【双击】 scripts\install.cmd（批处理会自请求 UAC）；
     在"用户账户控制"窗口点【是】；
  2) install_auto2.ps1 自动完成（全部本地、不联网）：
       a. 用已有/新建代码签名证书给 RAMBlockCache.sys 签名（CNG，RSA/SHA256）；
       b. 复制驱动到 C:\Windows\System32\drivers\；
       c. 创建内核服务 RAMBlockCache（内核驱动类型、demand/boot 按需）；
       d. 写 Parameters\AutoAttach=1（数据卷重启后自动加速）；
       e. 在 Volume 设备类 UpperFilters 追加 RAMBlockCache（保留 volsnap）；
       f. bcdedit /set testsigning on；
       g. 启动服务；
  3) 按提示【重启一次】（首次注册卷过滤必须）；重启后数据卷 D/F 应自动加速，
     系统卷 C: 默认直写。
窗口行为：脚本已处理编码（含中文路径用 GBK、PowerShell 脚本纯 ASCII/带 BOM），
出错时窗口保持不关闭以便看到原因。

6.2 首次真机验证（强烈建议按顺序，先安全后性能）
--------------------------------------------------------------------------------
建议先开启 Driver Verifier（仅对本驱动，便于首载暴露问题）：
  verifier /standard /driver RAMBlockCache.sys  → 重启
(1) 挂卷确认：
    双击 WPF 控制台（ui\wpf 发布版 RamBoostFS.Wpf.exe），进入 Volumes：
    数据卷 D/F 应显示已绑定/加速；系统卷显示直写。
(2) 小 I/O 防蓝屏冒烟：
    在 D: 新建/复制一个小文件（几 MB）、打开、删除；观察无蓝屏、无异常卡顿。
    若蓝屏：记录停止代码与 dump（C:\Windows\Minidump），重启后会进安全模式
    （SafeMode 强制直写），把停止代码反馈定位。
(3) diskspd 基线与加速对比（脚本 scripts\run_diskspd）：
    先在【加速关闭】跑基线并记录；再开启加速，对同一测试文件跑两遍：
      第二遍顺序读/随机读应主要命中内存，吞吐显著高于基线。
    参考命令（D: 上 1GB 测试文件）：
      diskspd -b4K -o32 -t4 -r -w0 -d30 -c1G D:\rbspd\test.dat   随机读
      diskspd -b4K -o32 -t4 -s -w0 -d30 -c1G D:\rbspd\test.dat   顺序读
      diskspd -b4K -o32 -t4 -r -w100 -d30 D:\rbspd\test.dat      随机写
    （具体以 scripts\run_diskspd.ps1 为准；测试文件可安全删除。）
(4) 动态内存确认：
    Memory 页设为自动（0）；复制数据观察缓存按需增长；打开多个程序/复制大文件
    制造内存压力，观察缓存自动收缩、系统流畅、无崩溃、无内存耗尽。
(5) 热切换/配置生效确认：
    在网页/WPF 关闭某卷加速 → 立即生效（统计停止增长、I/O 走盘）；重新打开
    立即恢复；修改配置后用 GET_CONFIG/界面回读，确认值确实改变并被采用。
(6) 稳定后关闭 Verifier 做干净性能复测：
    verifier /reset → 重启 → 再跑 diskspd，得到无 Verifier 开销的真实数据。

6.3 日常使用
--------------------------------------------------------------------------------
  - 默认对数据卷回写、系统卷直写；WPF/HTML 均可操作；
  - 关机/重启自动落盘脏数据，无需手动；
  - 长时间空闲自动回收冷块；
  - 玩带内核反作弊游戏前：scripts\game_mode.cmd 选 game → 重启；玩完选 accel
    → 重启恢复（见 3.5）。

6.4 卸载
--------------------------------------------------------------------------------
  双击 scripts\uninstall.cmd（UAC 点是）：先停服务、刷脏，再移除 UpperFilters、
  删除服务与驱动文件、testsigning off，重启后完全移除。证书可在卸载脚本选择
  是否一并删除。

6.5 命令行（ramboostctl）
--------------------------------------------------------------------------------
  支持：状态/统计、读配置、写配置、强制刷盘、退出安全模式、卷列表、卷挂载/
  卸载、日志、版本；改后自动回读。详见 ctl 源码与 docs/03。

6.6 签名与续签（单机自用、不联网）
--------------------------------------------------------------------------------
  - 自签证书有效期 100 年、RSA4096/SHA256、含代码签名 EKU；签名不加时间戳
    服务器，证书链本机闭环，全程不联网、无 CRL/OCSP 依赖；
  - testsigning 模式下本机信任该自签证书即可加载；
  - 若证书/私钥异常（历史上有损坏的 legacy CSP 证书，已弃用），安装脚本会
    新建 CNG 证书并重签；重跑安装脚本等价于续签，不会"用着用着过期不能用"。


================================================================================
第 7 章  风险声明、已知限制与待办
================================================================================

7.1 已知限制
--------------------------------------------------------------------------------
L1  块大小（BlockSize）变更需驱动重载，不做运行时热切换（规避几何迁移风险）。
L2  AddDevice 对扇区大小存在默认假设（512），4Kn 原生盘需按查询到的物理/逻辑
    扇区校正（本机 NVMe 为 512e，SATA SSD 常规，当前无影响）。
L3  miss（未命中）首次访问需下盘，预热阶段可能略增开销；第二次即命中。后续
    可优化 miss 快路径。
L4  写回写模式存在受控的断电丢失窗口（由脏水位/延迟写入限制其大小）；最保守
    场景请用写透传。
L5  首载建议 Driver Verifier，Verifier 本身带来性能开销，稳定后需关闭复测。
L6  testsigning 与内核反作弊互斥，游戏模式切换必须重启（操作系统限制）。
L7  当前为 L1（内存）缓存；尚无 L2（SSD 持久二级缓存）。

7.2 未决项（需用户决定）
--------------------------------------------------------------------------------
D1  是否对系统卷 C: 启用回写加速：默认系统卷强制直写更安全；启用需用户明确。
D2  真机首载的 UAC/重启必须用户本人完成（安全边界无法替代）。
D3  真机 diskspd 验收目标值需在真机实测后确定（本报告不预设、不虚构数值）。

7.3 后续可选增强（Backlog）
--------------------------------------------------------------------------------
B1  L2 二级缓存（在 SSD 上持久缓存，兼顾掉电保护与大容量）。
B2  miss 快路径优化、更细的自适应块大小/预读策略。
B3  按进程/文件类型的缓存策略（白名单/黑名单）。
B4  更丰富的性能分析与一键诊断报告。
B5  4Kn/大容量（>2TB 单卷已支持）与未来 Windows 版本的持续适配。

7.4 总体评审结论
--------------------------------------------------------------------------------
- 工程架构成熟：V8 块层正确解决了 V7 文件层的结构性蓝屏根因，与 PrimoCache
  同层、单一视图，具备"加速一切块 I/O"的结构基础；
- 三轮评审 + 独立审查 + 本轮真机修复中的全部 Critical（R1、N1、C1–C5、V1–V3
  等）均已闭环；
- 交付前可由开发侧执行的门禁（零警告编译、用户态 12/12 回归、静态专项）通过；
- 但"真机零蓝屏、diskspd 真机更快"是产品最终验收标准，当前【尚未在真机完成】，
  必须按第 6 章走完真机流程方可判定。
- 建议：在真机完成 6.2 的全部步骤并留存 diskspd 对比数据后，再决定是否日常
  长期启用及是否对系统卷加速。
