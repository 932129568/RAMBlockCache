## §4 本轮发现（要点，详见 145 号）

### 门禁侧

- **P0-1 的机制值得记住**：`& <不存在的exe>` 抛命令解析错误，**不写 `$LASTEXITCODE`**。会话首条命令时为 `$null`（`+= $null` 等于没加 → 假绿）；已有前序命令时**继承旧值**（伪装成上一条结果）。两处修复：`qa_w4check` 用 `$null` 判定 + obj 计数；`qa_recovery` 用 `Test-Path`/`Get-Command` 预检。
- **P0-4**：`Path.relative_to` 在目标不在子树下抛 **`ValueError` 而非 `OSError`**，逃出 `except OSError`；异常在 `print` 之前 → **stdout 零字节，此前累积的 finding 全丢**。门禁崩溃比误红更危险。
- **G19 的教训**：修法不是把 `src\core\build` 改成 `tests\core\build`（只是把硬编码挪位），而是新建 `qa_paths.ps1` 从 manifest `targets.core.outDir` 读。单一事实源不只是一个 JSON，而是"所有消费方都去读它"。
- **`qa_geom_gate` 抓到第三类缺陷**：`65536` 已于 2026-11-08 `[64K-UNBAN]` 恢复白名单，gate 期望表未跟上 → 对合法值期待 exit=2 → 假 FAIL。已修并补正向断言（5 个合法值必须被接受），否则"拒绝一切"的坏实现也能全绿。

### UI 侧

- **F-UI1**（已修）：5 个令牌被引用但未定义，裸 `var()` 静默失效。
- **F-UI2**（已修）：`prefers-reduced-motion` 对 motion 组件完全无效（duration 硬编码）；弹层无出场；图表全无动画；Skeleton 借用 SLO 违约样式。
- **F-UI3**（已避开）：`App.tsx` 历史上曾因双层动画叠加导致 `opacity:0` 残留。A6 依此设计四条约束。

调用它们不会报错，而是让 `$LASTEXITCODE` 继承上一条命令的值（"看起来成功"）。

**Git Bash / pwsh 坑（都踩过）**：
- `grep -F "--rbc-x"` → 必须 `grep -F -- "--rbc-x"`
- 中文路径 `grep -r` 可能失配 → 先 `cd /c/Users/陈/...`
- 对比文件先 `tr -d '\r'`
- pwsh 正则 `\obj` 是未定义转义 → 必须写全 `\\obj\\`
- `Where-Object` 内正则出错会**逐文件重复打印且管道返回空**
- `Where-Object` 命中 1 个元素返回**标量**，`$x[0]` 取到字符串首字符 → 必须 `@(...)`
- **`build.ps1` 输出被管道完全缓冲**：`| Out-Null` 会导致日志 0 字节 → 用 `-File ... > log 2>&1`
- `& <不存在的exe>` **不写 `$LASTEXITCODE`**（首条为 `$null`，否则继承旧值）→ 调用前 `Test-Path`/`Get-Command`
