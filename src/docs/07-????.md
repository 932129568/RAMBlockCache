# 07 常见问题（FAQ）

## 1. 装好后没有效果 / 命中率一直是 0？

- 确认驱动已加载：`fltmc` 能看到 RAMBoostFS。
- 确认控制台总开关、读缓存、写缓存都开着。
- 缓存只对**重复读**和**写**有效：第一次读永远不命中（要先读盘进缓存）。
  用"重复打开同一个软件/文件"来验证最直观。
- 确认你缓存的卷上真的有 IO：系统卷默认不缓存，如果只开了默认配置，
  去 D 盘跑点 IO（解压、看视频、开软件）。
- **（V5.1 起）** 默认已开启"分页 IO 缓存"（`CachePagingIo=1`），普通应用
  （浏览器、办公、影音、游戏资源加载等走系统缓存的 IO）也能命中。若命中率
  仍为 0，请确认控制台里"分页 IO 缓存"开关是开的；旧版（≤V5.0）只对
  `FILE_FLAG_NO_BUFFERING`（数据库等）生效，普通应用命中率天然为 0，
  这是设计缺陷，已修复。

## 2. 控制台显示"驱动未连接"？

- 驱动没加载：先跑安装入口（**注意 `scripts/install.cmd` 当前不可用**：其调用的 `install_auto2.ps1` 已废弃并无条件 `exit 1`；请用 `setup\ramboostsetup.ps1`）。
- 控制程序启动早于驱动：重启控制台（**本包未提供 `scripts/serve.cmd`**；请重新运行 `dist\wpf\RAMBlockCache.Controller.exe`）。
- 端口被占用：改端口 `ramboostctl serve 9000`，浏览器访问 http://127.0.0.1:9000。

## 3. 缓存大小设了 16GB，但占用一直涨不满 / 不动？

- 缓存是**按需填充**的：只有"读过/写过"的数据才进缓存。没访问过的数据不会占内存。
- 占用涨到接近上限后，LRU 会淘汰最久未用的干净块，保持水位，所以不会一直涨。

## 4. 直写和回写到底怎么选？

- **回写**（默认）：快 + 省 SSD 寿命，但断电瞬间可能丢最后一批数据。
- **直写**：写入立即落盘，慢一点，但和"没装缓存"一样安全。
- 建议：普通使用回写；写重要数据前点"立即回写"或直接开直写。

## 5. 蓝屏了怎么办？

1. 重启进系统（驱动默认手动启动，不自动加载，能进）。
2. 管理员运行 `scripts/uninstall.cmd` 卸载。
3. 记下蓝屏代码（如 `PAGE_FAULT_IN_NONPAGED_AREA`、`BUGCODE_USB_DRIVER` 等），
   以及蓝屏前你在做什么，发给我排查。
4. 处理完再决定是否重装试用（可先只缓存一个非关键卷观察）。

## 6. 驱动加载失败，事件查看器提示"签名验证失败"？

- 没重启（测试签名模式未生效）→ 重启。
- Secure Boot 开着 → 进 BIOS 关闭（见 `05-签名与安全启动.md`）。
- 没签名 → 重跑 `scripts/sign_test.cmd`。

## 7. 为什么系统卷默认不缓存？我想缓存 C 盘。

- 系统盘 IO 最复杂（页面文件、系统数据库、大量临时文件），且蓝屏/回写失败
  直接影响系统。默认排除是最安全的。
- 想开：控制台勾选"缓存系统卷"，或命令行 `ramboostctl set sys=1`。
  **注意：缓存页文件（pagefile.sys）没有意义还会浪费内存**，系统会自行管理。

## 8. 会不会和杀毒软件冲突？

- 大部分杀毒软件用 minifilter，我们也在文件系统栈上。海拔 373000 在
  "Cache Manager" 组，与 AV 的过滤层（通常更高/更低海拔）不冲突。
- 如遇到奇怪的文件 IO 问题，先临时卸载 RAMBoostFS 验证是否冲突。

## 9. 内存 64GB，给多少缓存合适？

- 默认已改为**自动预算**：缓存大小填 `0`（控制台滑块拖到 0 = 自动），驱动按
  物理内存 25% 自动分配（64G→16G、32G→8G、16G→4G），换电脑无需重配。
- 手动设置建议 8~24GB。**给系统运行留足内存**：Windows 自己 + 浏览器 + 应用
  通常需要 15~25GB。缓存过大导致系统内存紧张反而会拖慢一切。

## 9.5 配置会保存吗？重启后还要重新设置？

- 会。V5.1 起配置实时写入注册表（服务 `Parameters` 键），重启自动恢复。
- 旧版配置只存在内存中，重启即回默认值（已修复）。

## 10. 开机自动启动吗？

- 默认**手动启动**（更安全）。需要开机自启：
  `sc config RAMBoostFS start= auto`（管理员），再重启即可。
- 卸载前记得 `sc config RAMBoostFS start= demand` 恢复或直接卸载。

## 11. 这个项目安全吗？能用在生产环境吗？

- 逻辑层经过完整单元测试（14 用例 + 刁钻/压力/并发 + ASAN/UBSAN/TSAN 零告警 +
  V5 回归），设计上做了多层数据安全防护。但**未经过 WHQL 认证，属个人自用
  测试软件**，请勿用于重要生产服务器；重要数据永远要有备份。

## 12. 加密文件（EFS）能缓存吗？

- 能，且读写内容正确。V5.1 移除了回写/补读路径上的 `NO_DECRYPT` 标志，
  加密文件的读写按正常解密/加密路径处理（旧版会缓存/回写密文，用户读到
  坏数据，已修复）。

## 13. 用显存（GPU 显存）做缓存会不会更快？

- 结论：**不会，反而更慢**。详细分析见 `10-竞品对比与优化.md`：
  显存带宽虽高（RTX 4070 笔记本 8GB GDDR6 ≈256GB/s，远高于双通道 DDR5
  ≈77GB/s），但数据必须先经 PCIe 传输（笔记本一般 x8 Gen4，实际约
  13~14GB/s），且内核驱动无法直接调用 CUDA（CUDA 是用户态运行时），
  只能走"内核→用户态服务→CUDA→显存"的桥接，单次小块传输固定开销
  10~100 微秒。**缓存命中走显存比命中内存慢一个数量级**，只有大块顺序
  场景才可能追平，而那正是 SSD 本身就不慢的场景。64GB 内存 + 8GB 显存
  的容量对比也不占优。真正的"额外加速"应做 L2 SSD 持久缓存（重启预热），
  而不是显存缓存。

## 安全模式与数据保全

**Q：开机后发现控制台顶部有红色"安全模式"横幅，怎么回事？**
A：驱动检测到上次退出异常（蓝屏、断电、强制关机、被强杀进程）。
这是**蓝屏识别修复**机制：此时写缓存已自动关闭、一切写入直达磁盘，
保证不会再丢任何已确认写入的数据。确认系统稳定后点"恢复写缓存"
（或 `ramboostctl safe-mode off`）即恢复全部加速。

**Q：缓存占用了 80% 会怎样？**
A：触发**余量分级整理**：① 不常调用且干净的临时缓存块直接释放（不写盘，
纯内存数据无丢失风险）；② 非临时脏数据按脏量从多到少、按读写顺序回写磁盘，
回写后释放。整理在锁内串行执行，不阻塞新读写、不与磁盘 IO 打架。

**Q：会不会把内存写满导致应用崩溃？**
A：不会。占用到 **95% 硬上限**后，新写入自动改为直写（直接落盘），
缓存永不膨胀到失控；整理/淘汰也始终在安全水位内进行。
