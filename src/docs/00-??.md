# RAMBoostFS —— 免费的内存加速硬盘工具（对标 PrimoCache）

用你的内存给硬盘加速：**读缓存 + 写缓存（write-back）**，重复读写命中内存、减少小块随机写对 SSD 的写放大，保护硬盘寿命。Windows 内核 WDM 卷块上层过滤驱动实现（运行时定向挂载、无类级 UpperFilters；I/O 分类经准入门统一进缓存通路，不按非缓冲/分页区分），性能接近 PrimoCache 的同类方案，完全免费、开源可控。

> **重要前提（请先读完）**：这是一款 **Windows 内核驱动**。内核驱动有蓝屏风险，
> 本项目的全部代码和文档都围绕"数据安全"做了防护设计（见 `04-数据安全与防蓝屏.md`），
> 但**没有任何驱动能保证 100% 不蓝屏**。安装前请先备份重要数据。
> 使用即代表你了解并接受内核驱动的固有风险。

## 它和 PrimoCache 比，有什么不一样

| 能力 | PrimoCache（付费） | RAMBoostFS（本项目） |
|---|---|---|
| 价格 | 授权费（不便宜） | **免费**，源码完整 |
| 读缓存 | ✅ | ✅（64KB 块 + 4KB 子块位图，部分命中；V9-V10 已迁移至 WDM 卷块上层过滤层，**I/O 分类经准入门统一进缓存通路**——分页/缓存方式 I/O 架构上已纳入，属"已加速待验证"，证据待采，见 `deliverables/block-coverage-matrix-2026-10-15.md`） |
| 写缓存 | ✅（回写/直写可选） | ✅（写**全部先进内存**，部分覆盖自动读-改-写补缺口；回写/直写可切） |
| 减少 SSD 写放大 | ✅ | ✅（脏子块按连续段合并回写：块内合并 + 相邻块边界合并，单次最大 4MB） |
| 内存余量管理 | 有 | ✅（占用≥80% 分级整理：临时缓存直接丢弃、脏数据按频次回写；≥95% 硬上限新写直写，防写满崩溃） |
| 可视化控制台 | 有 | ✅（深色玻璃拟态页面，开关/内存分配/实时图表/占用环形仪表/**64 分片多核负载**，2 秒刷新） |
| 在线调整缓存大小 | ✅ | ✅（控制台拖滑块即时生效，无需重启；**0=自动预算**，按物理内存 25% 自适应，换电脑免重配） |
| 配置持久化 | ✅ | ✅（注册表保存，重启自动恢复） |
| 同文件多核并行 | ✅ | ✅（V4：64 分片条纹锁，同一文件不同区域读写在多核真正并行） |
| 玩内核反作弊游戏 | 需手动关加速 | ✅（`game_mode.cmd` 或前端按钮一键切「游戏模式」，干净关闭测试签名，重启即可） |
| 防数据丢失 | 有 | ✅（句柄关闭强制回写、FlushFileBuffers 强制回写、脏块永不因淘汰丢失、卸载前全量回写、**关机自动全量保存**） |
| 防蓝屏自愈 | 有 | ✅（记录上次退出状态，异常退出后自动进入**安全模式**写直写，控制台一键恢复） |
| 系统卷缓存 | 可 | 默认排除（更安全，可显式 opt-in；引导关键卷双闸门硬排除，不可判定按引导关键处理） |

## 支持环境

- Windows 10 1809+ / Windows 11（含 26H2），x64
- NTFS 卷为首验目标；exFAT/ReFS/动态磁盘等未验证类标注「验证中」——附加与否以覆盖矩阵结论为准，未验证前不预先声明；引导关键卷硬排除、系统卷默认排除
- 建议内存 ≥ 8GB；缓存大小默认**自动预算**（物理内存 25%，上限 32GB），换电脑无需重配

## V5.1 修复与增强（甲方评审驱动）

本次评审以甲方视角全量审查，修复了以下问题（详见 `10-竞品对比与优化.md` 与交付报告）：

1. **致命/高危**：
   - EFS 加密文件：回写/补读回调带 `FLTFL_IO_OPERATION_NO_DECRYPT`，加密文件会缓存/回写密文 → 已移除该标志（恢复解密路径）。
   - 短读/短写未校验：磁盘短读会把缓冲尾部垃圾并入缓存并拷给用户（数据损坏）→ 改为严格校验 `bytesRead/bytesWritten == len`。
   - 非缓存 IO 缓冲未扇区对齐（仅 16 字节对齐）→ 512e/4Kn 卷上回写可能 `STATUS_INVALID_PARAMETER`、脏数据滞留丢失 → 新增 4KB 对齐分配器。
   - 内核 `RB_AADD32` 为"读+写"两步非原子 → 多核并发统计丢计数 → 改用 `InterlockedExchangeAdd`。
2. **功能缺失（普通应用完全无法命中缓存的根因，V5.1 时期记录）**：分页 IO（Cache Manager 读写）被无条件放行，只有 `FILE_FLAG_NO_BUFFERING` 的 IO 才进缓存 → V5.1 曾新增 `CachePagingIo`（默认开）缓解。**该缓解已被 V9-V10 架构迁移取代**：现行驱动位于 WDM 卷块上层过滤层（Cc 之下单一视图，不产生双写者），I/O 分类经准入门统一进缓存通路、不按 I/O 类型区分；当前口径为**架构就位、证据待采**——"普通缓冲 IO 命中"的对外声明须待《覆盖矩阵验证报告》（`deliverables/block-coverage-matrix-2026-10-15.md`）逐格冻结，覆盖承诺永远滞后于证据。
3. **中危**：`DirtyHighPct/DirtyLowPct` 在线变更被忽略（只同步了大小）；`need_flush` 置位后回写线程仍要等整个周期；`max_merge_len`（宣称 4MB）从未生效（实际 64KB）；配置重启即丢（无持久化）；`install.cmd` 缺 `Instances\DefaultInstance`（过滤器不会附加卷）；HTTP 服务目录穿越 + 无 Origin 校验（任意网页可改配置）；`CacheSizeMB` 固定 8GB 不随机器变化（现 0=自动预算）。
4. **已实测验证**：核心层全部回归通过（普通/ASAN/UBSAN/TSAN 零告警），新增 V5 用例覆盖水位同步、need_flush、跨块合并（单次回写 128KB、边界退化正确）。
5. **待实机验证**（本环境无 WDK/MSVC，编译与真机验收均为零；Phase 0 验证基建未就绪）：驱动层修复需在真实 Win11 26H2 上按 `11-实机验证清单.md` 与《覆盖矩阵验证报告》（`deliverables/block-coverage-matrix-2026-10-15.md`）T1–T6 验收，重点：分页 IO 一致性、4Kn 卷回写、EFS 文件读写一致性、安全模式与关机回写。
