## 2. 测试设计（`test_flushpar.c`）

### 2.1 先读源码确认的真实 API 与几何

lead 任务书里的 `rb_engine_flush_zones(eng, zones)` 是推测名；**实际公开 API**（`src/core/cache.h` / `cache.c`）：

- `rb_flushws *rb_flushws_create(void)` / `rb_flushws_free(ws)` —— 每 worker 一个可复用 workspace；
- **`size_t rb_stream_flush_zoned(rb_stream *s, int zone_sel, int nzones, rb_flushws *ws)`** —— 分片并行回写核心，`zone_sel ∈ [0,nzones)`，返回落盘字节；
- `size_t rb_stream_flush_partition(s, my, n)` —— legacy 入口（内部转 zoned）；
- `size_t rb_stream_flush(s, force)` / `rb_engine_flush(eng, force)` —— 串行 force（与 zoned **互斥 per stream**，收尾排空用）；
- `rb_stream_set_exclude` / `rb_stream_truncate` / `rb_stream_invalidate_range` —— 直写/元数据覆盖；
- 分区规则（`cache.c:2256`）：`(zone_of(c->start) % nzones) == zone_sel`，`zone_of(off) = off >> 28`（**256MB/zone**，`RB_ZONE_SHIFT`）；chunk = `block_size*16 = 64KB`，sub = 4KB。

**测试几何**：16 个离散 256MB zone 窗口，每窗口 `WSPAN_A = 256KB+4093`（轨道 A 卷尾非对齐）/ `WSPAN_B = 256KB`（轨道 B 4KB 对齐），缓冲 `WINCAP = 260KB`（4KB 对齐，容纳 RMW 补读的末子块）；`VOL_TOP = 4GB`（truncate 安全尺寸，≥ 所有 chunk start）。**不用 4GB 大数组**：按 `off>>28` 映射到 16 个 260KB 窗口缓冲，ASan 友好，总常驻 ~4MB。

### 2.2 双轨 oracle（关键设计）

沿用 `test_wsconc` 的 `wb_fn` 口径「盘面字节 = `f(off)`，`f(off)=(off*131+7)&0xff`」，但补一条轨道解决 overlap 模式「丢写在盘面不可见」的固有局限：

- **轨道 A `concurrent`**：盘面初值 = `f(off)`；写者随机、重叠、非 4KB 对齐、跨 chunk 边界、卷尾非对齐；小缓存（4MB）强制驱逐/回写交织。`wb_fn` **落盘前逐字节校验 `b[i]==f(off+i)`**，任何非 f 值（零数据 / `RB_POISON_NEW_CHUNKS` 毒化残留 / 陈旧副本）→ 打印首个坏偏移+期望/实际+路数+种子并**返回 -1 拒绝落盘**（core 不 clean → 收尾 `dirty!=0` 双失败）。价值：抓静默写坏、竞态、分片漏刷、记账漂移。
- **轨道 B `sentinel`**：盘面初值 = `sent(off) = f(off)^0x3C`（≠ f）；写区间 4KB 子块对齐（避免 RMW 补读把哨兵混进落盘段造成 oracle 误报），用按 seed 打乱的确定性作业序列保证每个 active zone 的每个 chunk 都被覆盖、每轮重写（重叠写）、长度 1~3 个 64KB chunk（跨 chunk 边界）；**收尾要求应写区逐字节 == f(off)**，任何未落盘/丢写的字节保持哨兵 → 立即失败。价值：**真正抓「零丢失」**。

两轨都用同一 n、同一 seed，每档固定跑 `track{concurrent,sentinel} × phase{full,sparse} × cfg{write-back,write-through}` = **8 组合**，各组合独立 engine/stream，独立断言与吞吐统计。

### 2.3 覆盖矩阵

| 覆盖项 | 实现方式 |
|---|---|
| 每路互不重叠 zone 集合 | 每路一线程调 `rb_stream_flush_zoned(s, lane, lanes, ws)`；core 按 `zone_of%lanes==lane` 分区；`full` 阶段 16 个 zone 全部有脏写（写者按 `idx % active_zones` 轮转保证覆盖） |
| chunk 边界 / 卷尾非对齐 | 轨道 A 非对齐随机起点 + 最长 200KB（跨多 chunk），每 13 次写注入 `wspan-4093` 起 4093B 卷尾写；窗口按 4KB 上取整容纳末子块 RMW |
| 重叠写 | 多写者共享打乱作业序列；轨道 B 每 chunk 每轮重写一次；数据确定性 `f(off)` 保证任意交错收敛 |
| 失效 / truncate | 写者周期性触发 `rb_stream_invalidate_range`（**先镜像后失效**，驱动「直写成功后失效旧副本」同款 superseded=1 纪律）与 `rb_stream_truncate(VOL_TOP)`（≥ 所有 chunk start，不销毁任何 chunk、不触发尾部清零，仅 bump 视图世代 + 内部 force flush） |
| 写回 / 直写两种 cfg | `cfg=0` 正常吸收 → zoned 回写；`cfg=1` `rb_stream_set_exclude` 覆盖所有窗口 → `rb_write` 返回 direct 区间 → 测试侧整段镜像 + 失效（驱动 P2-1 同构）。**core 无显式 write-through cfg 开关，此为用户态等价建模，不代表驱动配置面**（如实披露） |
| 空 zone | `sparse` 阶段 `active_zones = min(lanes,3)`；`lanes>3` 时多数路 zone 集合为空；断言 `dirty/lost=0` + 全盘一致 = 空路不丢作业 |
| 周期性 flush | flusher 持续循环调用 zoned flush（无活让出 1ms）；写者 join 后 `stop=1`，**每路仍再跑一轮本路分片 flush 才退出**（避免短窗口把高路数误判空路） |

### 2.4 断言（每组合硬门）

- 零丢失：`lost_dirty_bytes==0`、`dirty_bytes==0`、`rb_engine_has_dirty==0`、轨道 B 应写区全盘逐字节 == `f(off)`；
- 零静默写坏：`wb_bad==0`（`wb_fn` oracle 违反 + 镜像越界器具自检，均带现场打印）；
- 零重复落盘计数错：`wb_flush<=wb_calls`、`wb_bytes<=回调实测字节`、`wb_bytes%4096==0`；`cfg=1` 时 `wb_bytes==0 && wb_calls==0`（直写不产生回写）；
- 链表净：`rb_stream_destroy` 后 `chunk_count==0`；
- 失败现场：首个坏偏移、got/exp、路数、种子、track/phase/cfg（`test_flushpar <lanes> <rounds> <seed>` 可复现）。

### 2.5 参数与运行姿态

`test_flushpar [lanes 1|2|4|8|16] [rounds] [seed]`；**无 `argv[1]` → 自动跑 1/2/4/8/16 五档 40 组合**（全量回归的免参数门禁姿态，与 `.ps1`/`run_all.bat` 的无参调用兼容）；有参数 → 单档 8 组合（逐档粗测）。`argv[2]`=迭代轮数（默认 6），`argv[3]`=种子（默认 20261106）。输出全部为 ASCII（避免 cmd/PowerShell OEM 代码页把中文输出替换成 `?`），每路 `bytes/passes/busy/thr(MB/s)`、总 `total_wall`、`wb_calls/wb_bytes/mirror/wb_bad/lost/dirty/wb_flush`。

> **可选增强未启用**：`cache.c` 的 `RB_POISON_NEW_CHUNKS=1`（新块填 0xA5）可把未初始化字节落盘变成确定性失败；按「只增行不改构建逻辑」的最小改动原则，本轮未在 `.ps1` 增加该 define，建议后续 QA round 以 `/DRB_POISON_NEW_CHUNKS=1` 单独加跑一轮（见 §6）。

## 5. 限制声明（安静模式 + Driver Verifier：绝对值不作峰值宣称）

- **本机为安静模式**（lead 给定）且 **Driver Verifier 仍开启**——注册表实测 `HKLM\...\Memory Management\VerifyDrivers = RAMBlockCache.sys`。双重因素使任何吞吐数字都受额外开销与调度噪声影响。
- 本轮所有 `thr (MB/s)`、`total_wall`、`busy` **只能作为同条件相对粗测**：测试窗口极小（16×260KB 逻辑盘、单组合 3~80ms）、回写量 0~20MB、用户态模拟盘为内存 `memcpy`（无真实块设备时延）、短窗口下部分 lane 可能空转（§3.2），且**未测真机端到端、未测驱动侧动态路数、未测签名后产物**。
- **明确不作**：不作峰值宣称、不据此给出「最优路数」结论、不把用户态 core 的粗测外推到驱动/整机。程序输出首行亦固定打印 `NOTE quiet-mode+Verifier: throughput is RELATIVE coarse only`。
- **真机端到端与最优路数结论，需在收网后（工程师完成驱动 worker 动态路数 + 配置/UI、重编签名、Verifier 关闭或基线化）于最佳性能档复测**；建议复测时固定盘面规模、轮数、seed，多轮取中位数，并同时记录 `wb_flush/wb_bytes/lost_dirty` 一致性。
