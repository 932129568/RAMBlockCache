## 〇、结论摘要

以最强怀疑态度逐环核了工程师的证伪链：**其更宽结论成立**——QA 的 1MB 写复现器从未执行 -2/P2-1 路径（QA 自装覆盖率计数器实证 `wrc_neg=0`、`dc_gt160=0`、逐区间分支 `b3=0`），"P2-1 主路径未闭合"失去证据支撑，**BLOCKER-2 改判为测试 bug 并撤回**。**但其给出的具体根因（QA 插桩丢锁+无主解锁导致失败）被数据证伪**：该分支在 mirrorall 模式下从不执行，且补回锁后照样失败（3/15）——失败与丢锁无因果关系；真实失败面是 mirrorall 保留的 `dc>0 → 整段镜像` 条款，即**超出驱动行为的应力模式**（与 Round 1 旧口径同根）。

修复包经**当前源码清空重建**后独立验证：core 40/40、test_wsconc 七模式全净、驱动 0/0、五件套 PASS（锚点 5ebde9e2 未动）、WPF 0/0。**本批修复（stage_revalidate + 失效升代 + wb_drain 双挂点 + Sleep(1) + p21/bigwrite 测试 + 文档）值得保留**：竞态类真实（在途回写旧数据盖已镜像新值+失效清脏位→永久污染），修复在驱动可达路径（direct 逐区间 / -2 整块）上设计级闭合且有测试覆盖。

## 一、裁决任务逐项（team-lead 六问）

### ① test_big.c 原始代码：锁缺失与无主解锁是否属实？归因是否仍成立？

**属实（QA 认账）**：`build/qa2_mut/test_big.c` 的 `dc>0` 逐区间分支（原 167-175 行）中，QA 插入 wlog 插桩时误删了 `pthread_mutex_lock(&g_disk_mx)`，使该分支的 `memcpy(g_disk+o,...)` 无锁运行，且分支末尾的 `pthread_mutex_unlock` 成为无主解锁（CRITICAL_SECTION UB）。已全部补回（`test_big_lockfix.c`）。

**但归因不成立（数据证伪）**：
- QA 自装分支覆盖率计数器（逻辑未动）实测：mirrorall 模式下**逐区间分支执行次数 b3=0**——该分支从未运行，锁缺失/无主解锁在复跑的失败中**不可能**是原因；
- 对照实验：补回锁后**照样失败 3/15**（原样 1/15）——失败与丢锁无因果关系；
- 工程师"500s 挂死/0.28s CPU"的观察应来自 default 模式（该模式逐区间分支执行、无主解锁 UB），与 mirrorall 失败不是同一现象。

**"FLUSH 末写"归因的存续性**：失败运行中最后写损坏字节者确实恒为 FLUSH（core 回写）——该观测本身仍成立（损坏字节所在 64KB 区域的最后磁盘写来自回写路径）；但由此推出"core 缺陷"的**解释链不成立**，因为触发失败的调用序列（`mirrorall && dc>0 → 整段镜像+整段失效`）**驱动从不执行**（详见②），属测试人造序列，其失败不能归责于 core。

### ② 覆盖计数器：m2/dc>160 是否为 0？"P2-1 未闭合"是否失去支撑？

**实测为 0（QA 自装计数器，与工程师声称互证）**：`wrc_neg(-2)=0`、`dc_gt160=0`（每 10 轮 ~1714 次写）。原因：direct 区间按连续性合并，顺序写的未吸收子块是连续区间 → dcnt 难自然 >160。

**结论**："P2-1 主路径未闭合"的前提（该路径被执行）**不成立**——5/22"损坏"全部来自驱动不可达的整段镜像应力模式，**该结论失去证据支撑，BLOCKER-2 改判**。

### ③ 锁修复版对照：是否真 15/15+15/15？

**部分互证，存在量级差异（如实记录）**：
- 工程师：锁修复版 × 修复 core = 15/15；× 回退 core = 15/15。
- QA（同法补锁，保留 wlog 插桩的 ASAN 构建）：× 修复 core = **3/15**（未跑 × 回退 core 组合）。
- 差异归因：该现象对构建/时序敏感（插桩扰动、ASAN 减速、调度）；QA 构建在"整段镜像+1MB 写"这一**驱动不可达模式**下仍以 ~10-20% 失败，工程师构建未现。**两种测量都不构成 core 缺陷信号**（模式本身驱动不可达）；该差异不影响改判结论，但证明"锁修复版 15/15"不是稳定事实，引用时需注明构建依赖性。

### ④ p21 新模式：确定性触发 -2？修复 core 全净？回退 core 能否复现？

**触发确定性：证实**。QA 覆盖率计数器实测 p21 模式 `wrc_neg(-2)=72 次/10 轮`（官方构建）；变异构建下 4086 次/10 轮（无排空→缓存饱和→direct 区间更多，次数升高合理）。工程师声称 307 次/10 轮与 QA 的 72 次同量级——**-2 路径被真实、反复执行**。

**修复 core 全净：证实**（当前源码清空重建后复跑，见 §二）：p21 Release 10/10、p21 bigwrite 10/10、ASAN p21 5/5、bigwrite（1MB 忠实逐区间）5/5、default 10/10+ASAN 5/5、mirrorall 20/20+ASAN 5/5。

**回退 core 复现：不能（如实记录，不硬造复现）**：p21 × 回退 core（stage_revalidate 恒真 + wb_drain no-op）= **0/10**（4086 次 -2 执行下仍全净）。原因：该测试模型的顺序单写语义不构造"旧脏版本"前置条件（每个子块只被写一次，除边界子块外无旧版可被 stage）。**因此 -2 路径的结论是"修复后通过"而非"修复实证有效"；该竞态在 -2 路径上的闭合为设计级论证（wb_drain 挂点 + 复检 + 升代的组合覆盖），测试无法区分修复/回退——此点已如实记入报告，不作为放行障碍，但建议后续以"覆盖式重写"（同区间二次写）构造旧脏版本使 p21 获得牙齿。**

### ⑤ 全量回归（当前源码清空重建后独立复跑）

见 §二数据表。**core 40/40；七模式 ×8 全净；ASAN 关键模式全净；驱动 0/0；五件套 PASS（锚点 5ebde9e2 未动）；WPF 0/0**。排空点有界性：Sleep(1) 后 60000×1ms=真 60s 上界（已验证代码）；锁不进 I/O 纪律：stage_revalidate 仅 RLOCK+比较、wb_drain 无持锁等待——维持。

## 三、BLOCKER-2 改判的完整证据链

1. **归因层**：工程师根因声称（插桩丢锁）→ **证伪**（b3=0 分支未执行；补锁对照 3/15 仍失败）。QA 认账丢锁事实本身，但失败与之无因果关系。
2. **前提层**：BLOCKER-2 的核心前提（-2/P2-1 路径被执行）→ **证伪**（QA 自装计数器 wrc_neg=0/dc_gt160=0，与工程师覆盖实证互证）。
3. **模式层**：失败调用序列（mirrorall dc>0 整段镜像）→ **驱动不可达**（读码证实 rbio.c:522-612：dc>0 逐区间镜像；整段仅 -2）。Round 1 旧口径同根——**QA 两轮 BLOCKER 的证据均建立在超驱动行为的测试模式上，竞态类真实但"驱动可达"表述不成立**（已追溯修订）。
4. **保留层**：工程师修复包对**驱动可达路径**的覆盖经独立验证通过（default/bigwrite 逐区间 + p21 确定性 -2）；-2 路径为设计级闭合（测试无法区分修复/回退，已如实记录）。
