# 下一版本安装与使用体验优化方案

**日期**：2026-10-19 · **状态**：待评审 V1.0 · **类型**：体验优化方案（安装/部署/测试链路）
**输入**：用户诉求（部署测试流程繁琐：依赖命令行、每次测试手动重启）+ 仓库现状 + 竞品安装体验调研

---

## 📌 TL;DR

- **一句话**：把「开发者工具式的安装部署」改造成「消费品式的三步体验」——普通用户：双击安装器 → 一次重启 → 首跑向导自动完成配置；测试者：测试模式下一键编译-签名-部署-挂载，**全程零重启**。
- **核心判断**：① 「安装后需重启一次」是卷级过滤驱动的品类固有成本（PrimoCache 亦然），不可消除但可被「内嵌重启 + 重启后自动向导」消化——真正的丑不是重启，是重启后面对一个空白控制台还要手动挂载；② 「每次测试需手动重启」**可以消除**——用测试模式（DEMAND_START + 运行时开卷挂栈）换 dev loop 零重启，生产路径零变化；③ 当前五痛：入口四个（install.cmd/install.ps1/ramboostsetup/deploy.ps1 职责重叠）、安装器是控制台、无首跑向导、无托盘、dev loop 六步全手工。
- **落地清单**：P0×4（安装器 GUI 化、测试模式+devloop、首跑向导、安装即用默认值）、P1×3（托盘、卸载 GUI、批量静默）、P2×2（EV 签名消 SmartScreen、安装遥测）；总估 ~10-13 人周，与迭代计划 W0/W1/W1.5 并行插入。
- **红线不变**：签名预检 fail-closed 先于一切变更（10-18 严重-1 教训）；测试模式默认关，须过 Driver Verifier；生产模式如实告知需重启一次，不虚假承诺「免重启安装」。

## 1. 现状与问题（内部证据）

### 1.1 当前安装/部署链路实况

| 环节 | 现状 | 痛点 |
|---|---|---|
| 安装入口 | 四个并存：`install.cmd`→`install.ps1`（legacy 调试，DEMAND_START+UpperFilters）、`ramboostsetup.exe`（权威，BOOT_START）、`deploy.ps1`（带哈希门禁的部署链）、`verify_install.ps1`（验收） | 用户/测试者不知道跑哪个；install.ps1 自述「仅 legacy 开发调试用」但仍可双击 |
| 安装器形态 | `ramboostsetup.c` 控制台程序：wprintf 输出中英混合、错误码 `err=%lu`、结尾一句 "Reboot ONCE" 文字提示 | 普通用户面对黑窗恐惧；签名失败只报 WinVerifyTrust 十六进制，无可执行建议 |
| 安装后 | 无重启引导、无自动配置确认——用户自己重启、自己开 WPF、自己逐卷点「挂载」 | PrimoCache 重启后自动弹向导；本品重启后是一片空白 |
| 测试循环 | 编译 → `signtool`（手工）→ copy 到 dist → `sync_anchors.ps1` → `deploy.ps1`（MoveFileEx）→ **手动重启** → 挂载 → 测 | 六步全手工，每步都是 PowerShell；一次循环 ≥10 分钟 + 一次重启 |
| 常驻形态 | 仅 WPF 窗口，无托盘、无最小化常驻 | 命中率/状态不可常显；关了窗口就像「没在工作」 |

### 1.2 为什么必须重启（架构事实，决定方案边界）

- 过滤设备在 **PnP AddDevice** 时挂上卷栈（`rbdriver.c:704-725`）；AddDevice 只对「驱动已加载后的新 PnP 到达」触发——既有卷要拿到过滤设备，必须驱动在开机时就加载（**BOOT_START**）或设备级重扫。
- 0x7B 事故根因即「DEMAND_START + 卷类 UpperFilters」组合；现行安全姿势 = BOOT_START + 不依赖类级 UpperFilters 的运行时定向挂载 + 三重回滚（boot_guard/offline_rollback）。
- 结论：**生产模式「安装后重启一次」不可协商**（与竞品一致）；**测试模式的免重启空间在「驱动已停止状态下的换载 + 运行时开卷挂栈」**——驱动卸载后 `sc start` 重新加载，AddDevice 不会为既有卷重跑，须由 ATTACH 路径自行「打开卷→构造过滤设备→挂栈→建流」（V9 曾实现过：`rbctl.c` 注释「V9：运行时从零打开卷→挂栈→建流（不依赖已存在 ext）」，V10.2 为 0x7B 安全改为纯 AddDevice——**代码资产仍在 git 历史/备份中，可复活为测试模式专用路径**）。

## 2. 竞品安装体验参照（外部调研，2026-10-19）

| 产品 | 安装流程 | 重启 | 首次使用 | 常驻形态 |
|---|---|---|---|---|
| **PrimoCache**（Romex，直接竞品） | 官方安装包（GUI）→ 管理员安装 | **必须重启**（教程原话「安装成功后必须重启，因为它需要改写磁盘驱动栈」；重启不当会 0x7B，官方与教程均警示） | **重启后首次启动自动弹出向导**：勾选卷 → 选配置模式（提升读&写）→ L1 大小/L2 空间（选空闲空间+格式化）→ 块粒度（建议 4KB）→ 延时写入（建议 60s）→ 启动 | 托盘图标实时命中率/内存曲线 |
| **ImDisk Toolkit**（开源内存盘，邻近竞品） | 标准安装器（组件可选）→ 「no reboot required」 | **免重启**（驱动需求启动 + 运行时创建设备） | RamDisk Configuration GUI：容量/盘符/文件系统/动态内存/TEMP 一键/镜像同步 | 开始菜单应用 + 可选开机项 |
| **SoftPerfect RAM Disk** 等同类 | 标准 MSI 向导 | 多数需重启一次 | GUI 创建 RAM 盘 | 托盘 |

**三条可借鉴（不照抄）**：
1. **PrimoCache 的「重启后自动向导」是本品最该抄的**——它把品类固有成本（重启）转化为「被引导的第一次配置」，用户零决策负担；
2. **ImDisk 证明「免重启」在 Windows 驱动品类成立**，但其架构前提是「创建新虚拟设备」而非「过滤既有卷栈」——本品不能全盘照抄，但**测试模式可以**（运行时挂栈本就是 V9 老路）；
3. **托盘+实时命中率是信任显性化的最低成本形态**（与用户研究 M1「效果可感知」直接对应）。

## 3. 目标体验设计（三态）

### 3.1 普通用户（生产模式，默认）

```
双击 RAMBlockCache-Setup.exe
  → UAC 一次
  → 向导 4 页（欢迎/许可协议/安装中-进度+签名预检/完成页勾选"立即重启"）
  → 重启（完成页内嵌重启按钮 + "稍后我自己重启" + 托盘/开始菜单提示）
  → 重启后首跑向导自动弹出（3 步）：
      ① 一句话认知："RAMBlockCache 用内存给你的数据盘加速；系统盘默认不加速"
      ② 卷选择：数据卷默认全选（每卷显示容量/类型/建议档），系统卷灰显+说明
      ③ 完成页："已加速 N 个卷 · 打开控制台查看命中率" + 效果验证入口（3 秒）
  → 日常：托盘常驻（命中率气泡），双击进 WPF 五页控制台
```

### 3.2 测试者/开发者（测试模式，opt-in）

```
安装器加参数 -TestMode（或设置页开关）：
  服务 = DEMAND_START；不写任何 UpperFilters；驱动启用运行时挂栈路径
之后每次迭代一条命令：
  devloop.ps1            # 编译→签名→停服→换文件→启服→attach→打印验收清单
  （全程零重启；卸载 = sc stop，干净）
```

### 3.3 批量部署（网吧/电竞酒店/工作室，W4 商业场景）

```
静默安装：Setup.exe /S /D=... /AutoAttach=1 /DefaultMode=WriteBack
  → 无人值守完成 + 一次重启窗口由运维统一安排
  → ramboostctl.cmd 做装机后自检（volumes/stats）——已就绪
```

## 4. 方案 A：普通用户安装流程（避免 cmd/命令行）

### A1 安装器 GUI 化（P0，杠杆最大）

- **形态**：保留 `ramboostsetup.exe` 的原语（服务创建/UpperFilters/签名预检/默认值）作为静默引擎，外覆 **WPF 安装引导**（或直接 C# 重写安装器，调 sc.exe/reg/signtool——依赖更少；签名预检用 `Get-AuthenticodeSignature` + WinVerifyTrust P/Invoke 等价实现）。
- **铁律保持**：验签先于一切变更（旧安装拆除之前）；失败时机器保持原状。GUI 只负责把 `err=0x800b0100` 翻译成「驱动签名无效/被系统策略阻止」+ 三步解决方案（检查测试签名模式/更换签名证书/以管理员运行）。
- **重启内嵌**：完成页「立即重启」按钮（`ExitWindowsEx`）+「稍后重启」+ 开始菜单固定磁贴提示「重启后生效」。
- **卸载同源**：同一 GUI 的「卸载」模式（先回写全量脏数据→停服→摘 UpperFilters→删服务→删文件），进入「应用与功能」列表（ARP 注册）。

### A2 首跑向导落地（P0，接口已预留）

- 接口层已就绪（`IFirstRunExperience` + `FirstRunDone` setting + FeatureRegistry，10-17 UI 重设计预留），本方案做**真实实现**：
  1. 三步向导（复用已建的 Motion/NumberRoller/Toast 动效设施）；
  2. 卷选择页数据来自 `GET_VOLUMES`（容量/类型/是否系统卷），默认勾选数据卷、**系统卷灰显**（与「系统卷默认不自动加速」的产品口径一致，同时保留手动 opt-in 入口）；
  3. 完成页做一次 3 秒效果验证（读一个小文件两遍，展示「已加速·命中率 xx%」——用户研究 R3「效果 3 秒可感知」）；
  4. 「不再显示」写入 FirstRunDone；设置页保留「重跑向导」按钮（10-17 已埋）。

### A3 托盘常驻 + 状态可见（P1）

- NotifyIcon：最小化到托盘、命中率/脏数据量气泡 tooltip、右键菜单（打开控制台/立即回写/暂停/退出）；
- 与 W1-2「信任显性化」共享数据源（RB_STATS + RB_STATS2），不新增协议面。

### A4 安装即用默认值复核（P0，防「装完没效果」）

- 安装器写入推荐档：AutoAttach=1（已上线）、块大小默认 4K（小随机为主的家用场景）、回写周期默认 60s、**写模式维持直写默认**（安全叙事；回写入口在卷卡片+设置页，文案说清「回写=写加速唯一入口」——跑分分析结论）；
- 完成页/向导附「适用/不适用」一页（NVMe 系统盘用户收益有限等——用户研究 R1 场景白名单），把预期管理做在安装时而非售后。

## 5. 方案 B：免重启测试模式与快速热更新（P0）

### B1 测试模式架构（TestMode，默认关）

| 维度 | 生产模式（默认） | 测试模式（opt-in） |
|---|---|---|
| 服务启动类型 | BOOT_START（System Bus Extender 组） | DEMAND_START |
| 卷类 UpperFilters | 不依赖（AddDevice 挂栈） | **不写**（彻底断 0x7B 路径） |
| 过滤设备来源 | PnP AddDevice（开机） | ATTACH 时**运行时开卷挂栈**（V9 路径复活，TestMode 编译/运行门控） |
| 装载/卸载 | 开机加载；更新需重启 | `sc stop` 干净卸载 → 换文件 → `sc start` 即用 |
| 数据面行为 | 完全一致（同一数据通路代码） | 一致（仅挂栈来源不同） |
| 安全网 | 三重回滚 + 签名门禁 | 签名门禁保持；boot_guard 不适用（不碰启动路径） |

- 实现要点：① `rbctl.c` ATTACH 分支在 TestMode 下走「IoGetDeviceObjectPointer 开卷 → IoCreateDevice → IoAttachDeviceToDeviceStack → 建流」；② detach = 拆流 → IoDetachDevice → IoDeleteDevice（V9 曾有，需按现行拆除铁律重写：停流入→等在途排空→销毁）；③ 运行期挂栈的设备 removal 处理（卷被热插拔时我们的过滤设备在栈上会收到 REMOVE——现有 PnP  handler 覆盖）；④ 注册表 `TestMode=1` + 安装器 `-TestMode` 双入口，UI 设置页同步暴露。

### B2 devloop 一键脚本（P0）

`src\scripts\devloop.ps1`（扩展 `_build_manual.ps1`）：编译 → signtool 自动签名（证书 thumbprint 已知：DF1A0ADA…，`/sm /s My /sha1`）→ `sync_anchors.ps1` → 测试模式下 停服/换文件/启服 → attach 数据卷 → 打印验收清单（volumes 期望 attached=1、stats 两遍读判据）。**一次回车 = 一轮可测迭代，零重启。**

### B3 生产模式热更新的诚实边界

- 生产模式更新仍需一次重启（BOOT_START 映像锁定）——与 PrimoCache 一致，UI/文档如实告知，不做「免重启安装」虚假承诺；
- 缓解：更新检测 + 「重启后生效」提示 + 重启前脏数据已由安全网保证（关机全量回写）。

## 7. 风险与红线

1. **签名预检 fail-closed 不可因 GUI 化而松动**：验签必须保持在拆除旧安装/写 UpperFilters 之前（10-18 严重-1 同型纪律）；GUI 的「友好」只体现在文案，不体现在放行条件。
2. **测试模式的运行时挂栈是新代码路径**：必须 Driver Verifier（特殊池+IRQL+死锁）+ 热插拔/睡眠循环 + attach/detach 数百次无泄漏；**TestMode 默认关**，生产安装路径零变化；不过验收不默认开。
3. **不虚假承诺「免重启」**：生产模式一次重启是品类固有成本（PrimoCache 亦然），对外话术是「一次重启 + 重启后自动配好」，不是「无需重启」。
4. **安装器重写的回归面**：装机/重装/升级/卸载四路径 + 签名失败/服务占用（1072）/旧版残留清理都要有对应用例；重装时 TestMode 参数不得静默丢失。
5. **首跑向导的默认勾选范围**：只勾数据卷；系统卷保持「默认不加速、可手动 opt-in」的产品口径——跑分分析与竞品分析都指向这是信任资产。

## 8. 与迭代计划的衔接

- **U0-1/U0-2/U0-3/U0-4 插入 W0 出口后立即启动**（与 W1 信任遥测并行、先于 W1.5 读写路径专项收尾）——安装体验是「可发布」定义的一部分（Gate 0 精神）；
- **U1-x 随 W1 信任显性化同波次**；**U2-1/U2-2 归 W4 合规商业化**；
- 10-17 迭代计划中「信任显性化/游戏模式 UI 化/一键安装器 Alpha」等 W0/W1 项与本方案 U0/U1 重叠部分，以本方案为准合并排期（安装器 Alpha → GUI 正式版）。
