### 1.2 单线程延迟分解（164µs，命中读 1MB）

```
├─ 1MB 内存拷贝        ≈ 50µs   物理极限（25GB/s 单核有效带宽）
├─ Windows IRP 进出    ≈ 80µs   存储栈框架成本（过滤器无法回避）
└─ filter 层自有成本   ≈ 34µs
   ├─ 16×per-chunk（桶锁/查找/seq 快照复核）≈ 25µs  ← 可压缩
   ├─ 遥测（FeatOnRead/Admit/LatSample）    ≈  5µs  已最简
   └─ stats/分支                             ≈  4µs
```

**竞品对标**：标称 10GB/s 单线程 = 100µs/IO——比 memcpy+IRP 硬成本（130µs）还低 →
其数字要么来自多线程口径，要么其 filter 层 <20µs（需内核trace证实）。我方 filter 层
压到 ~15µs 后单线程 ≈ **7.5-8GB/s**（+25%），此为代码可交付的天花板。

### 1.3 已确认的结构性问题

| 问题 | 证据 | 影响 |
|---|---|---|
| per-chunk 开销 ×16 | 1MB 读跨 16 个 64KB 块 | 单线程 -15%（16K 后 ÷4） |
| **单次顺序读不驻留** | D 盘 20GB 文件读后 142MB/s（区域不在缓存） | 二次读同一大文件=再冷读 |
| 预算分配盲目 | 4GB 预算被三卷均沾，无命中率驱动 | 热卷被冷卷挤占 |
| bypass 诊断盲区 | LastBypassReason 不进协议 | D 盘排查耗时 1h+ 的根因 |
| VSS 一致性（ARCH-1） | 注册序 volsnap 在上 | 快照时点被污染 |
| 64K 崩溃未解 | 11-03 内核踩踏，用户态审计全净 | BlockSize 白名锁定死 4K |

## 3. P1：性能深度（2-4 周，代码级）

### 3.1 filter 层延迟压缩（目标 34µs → 15µs）

| 优化 | 设计 | 预期 | 风险 |
|---|---|---|---|
| 3.1a **seq 批量校验** | try_cache 两阶段化：阶段①全 chunk lookup+ref++（桶锁最短持有）；阶段②统一 seq 快照→memcpy→复核。1MB=16 次桶锁往返保留但锁内工作减半 | -5µs | 低（ref 协议不变） |
| 3.1b **遥测合并** | RbFeatOnRead+RbFeatAdmit+RbLatSampleStart 合并为单次分支树（一个 volatile flags 读判三者） | -3µs | 低 |
| 3.1c **stats 写合并** | 读路径 4 项分片写→2 项（req+bytes 合槽、hit+hit_bytes 合槽，解码时拆） | -2µs | 低 |
| 3.1d **16K/32K 大块**（=P0-2 转正） | per-chunk 开销÷4 | -19µs | 中 |

### 3.2 大文件驻留（"读一次就忘"问题）

**设计：读驻留策略（Read-Residency）**
- 现状：miss 读→回填→**但预读窗口外的主读区域是否 commit 取决于 full_cover**——大文件
  顺序读的 commit 实际发生（实测 CurBytes 涨 4.3GB）但**二次读仍 miss** → 怀疑
  **预读与主读的区间错位**（预读回填前方、主读回填被 LRU 中的预读块挤占）。
- 动作（诊断先行）：
  1. per-stream CurBytes 读数出口（协议加 per-volume stats——观测性补齐）
  2. 复现脚本：20GB 文件读两遍，第二遍逐 GB 打命中率曲线 → 定位丢失区间
  3. 修法候选：顺序读的 commit 走"受保护 LRU"（residential 标志，驱逐跳过一次）
- 收益：大文件二遍读 142 → 6GB/s（**42×**），这是**用户可感知的最大单项收益**

### 3.3 写路径

- 顺序写 7.8GB/s 已接近回写吸收上限（memcpy+标记）；next = **批量刷盘聚合**（相邻脏块
  合并为大 IO 下盘——zone flusher 已有 run 合并，验证 64K 块后的合并尺寸）
- 4K 随机写 636K：锁定在 per-IO 锁成本——受益于 16K（块大→同数据量块数少）与 3.1 系列

## 4. P2：缓存策略科学化（1-2 月）

### 4.1 命中率驱动的自适应预算

```
每卷独立记账（新增 per-stream stats 出口）
每 60s：rate_v = volume 命中率变化率
预算再分配：rate 高的卷 +预算（从 rate 低的卷借用，下限各保 512MB）
```
- 依据：D 盘（SATA 慢源）命中价值 = NVMe 卷的 10 倍（每命中省的盘时间多）——
  **按"节省的毫秒"加权**而非均分
- 风险：低（预算调整=LRU 水位参数，无数据面改动）

### 4.2 分层缓存

- 热/温/冷三档（hits 阈值）：热档永不驱逐、温档 LRU、冷档先逐
- 依据：当前 hits 计数已存在（chunk.hits）——只差驱逐策略消费它
- 收益：工作集波动场景（游戏切换）命中率稳态提升

### 4.3 观测性基建（今天教训的固化）

| 项 | 设计 |
|---|---|
| bypass 计数出口 | per-ext `BypassCnt[16]`（按原因分桶）→ GET_VOLUMES 新字段——D 盘排查 1h 的教训 |
| per-stream stats | CurBytes/HitRate/DirtyBytes per volume → 收益页逐卷卡片 |
| 延迟直方图 | RbLatNote 已采样 1/64——分桶（<100µs/1ms/10ms）进 GET_STATS |
| 命中率时序 | 收益页 2 分钟窗口已有——加 24h 环 |

## 7. 不做清单（负空间，防散焦）

- ❌ SPDK/用户态接管（破坏"透明无损缓存"定位）
- ❌ 压缩/去重（CPU 代价 > SATA 源收益；NVMe 源场景负优化）
- ❌ 写穿模式优化（直写语义=透传，无可优化面）
- ❌ 多队列并行 pass1（锁序复杂化，收益<4K 随机写已有的 636K）
