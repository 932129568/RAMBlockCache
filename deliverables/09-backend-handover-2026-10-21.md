## 0. 给后端的三个要点（先读这段）

1. **最硬契约 = B-4 二遍读基准执行体**：它是「可信」支柱的地基（用户自己跑冷热对比证明缓存有效），硬门槛 = 与 `ramboostctl stats` **同一测量代码路径、误差 <2%**。做不到这条，前端宁可继续显示降级横幅也不用假数据。
2. **B-7 操作进度事件是多面共用的公共基座**（二遍读运行/预设多卷应用/卸载回写/L2 重建），建议最先落地——它一个事件解锁四个界面的进度可见性。
3. **协议面变更的纪律**（B-1/B-12/B-13 若走新协议面）：三副本同步（`rb_proto.h` ↔ `Models.cs` ↔ `RbProto.cs`）+ `check_proto_sync --strict` + sys 哈希变动后三锚点同步（`deploy.ps1`/`verify_deploy_signature.ps1`/README）+ 未签名不得部署——这是本项目既有铁律，后端侧同样适用。

## 3. 契约详规（P0 五项——W1 内冻结）

### B-3 · ApplyPreset / GetPresetDiff（服务层）

- `ApplyPreset(presetId: "safe"|"balanced"|"perf")` → `ApplyResult{ok, failedField?, errorText?}`
  - **原子性**：全字段成功或全回滚；任一 SET_CONFIG 失败即回滚已应用项（前端已在退化方案中实现同语义，后端编排上线后前端切换调用，行为不变）
  - 受管字段（7 项）：每卷写模式 / 读预取总开关 / 每卷预读窗口 / L2 / 回写周期 / 进程准入 / 全局内存预算（B-13 未确认前不覆写）
  - **永不覆写**：每卷配额、挂载状态、自定义排除名单（用户个体决策）
- `GetPresetDiff()` → 差异行列表（当前实况 vs 基础档位，前端「自定义（基于：X）」+ 差异清单消费）
- 失败错误沿用三段式归因（发生了什么/影响与风险/如何撤销），前端不发明新错误范式
- **验收**：HDD/SATA SSD/NVMe 三盘型 × 三预设矩阵各跑一遍；注入单字段失败 → 已应用项全部回滚可见

### B-4 · 二遍读基准执行体（CLI 同款）——最硬契约

- `RunColdWarmBenchmark(path)` → `{firstMbps, firstSec, secondMbps, secondSec, bytes, secondHitRate, ioMode, toolVersion}`
- **测量纪律（写进发版门禁）**：
  1. **no-buffered I/O**（`FILE_FLAG_NO_BUFFERED` + 对齐读）——不过 Windows 文件缓存，否则第一遍不是冷读，对比即造假
  2. **与 `ramboostctl stats` 同一测量代码路径**（同一函数/同一时钟 `QueryPerformanceCounter`）
  3. **误差 <2%**：UI 显示值 vs CLI 值 vs 遥测值三方一致（前端已在界面常驻口径声明 + 禁一切不可复现营销数字）
- 进度事件复用 B-7：`{pass: "first"|"second", percent, mbpsInstant, cancelable}`
- 取消语义：取消后 stats 口径不变（不污染统计）
- 前置依赖：B-5（第一遍冷读需要刷新该文件的缓存范围）
- **验收**：同机同文件跑 5 次，UI/CLI/遥测三方误差均 <2%；第一遍速率 ≈ 盘速量级、第二遍 ≈ 内存量级（量级倒挂 = 测量路径错误）

### B-5 · FlushFileRange(path)

- 语义：把指定文件当前占用的缓存块失效/刷新，使第一遍读真正落到磁盘
- 失败/不支持时的约定：返回明确错误码，前端降级横幅已就绪（「缓存范围刷新能力不可用，第一遍可能不是冷读，结果仅供参考」）
- **验收**：调用后立刻读该文件，命中率增量 ≈ 0（证明缓存范围确被刷新）

### B-6 · 驱动签名态暴露

- 版本/配置查询（`GetVersion` 或 `GetConfig`）加字段：`{testSigned: bool, signer: string}`
- 取不到时的约定：**前端按测试签名保守处理**（反作弊警示照弹）——即后端若不能稳定提供，前端永不静默，这是有意的安全默认
- **验收**：正式签名构建 → `testSigned=false` 且前端零弹窗；测试签名构建 → `testSigned=true`

### B-7 · 操作进度事件（公共基座，建议最先落地）

- 事件结构：`{opId, opType: "benchmark"|"preset-apply"|"unmount"|"l2-rebuild", percent, stageText, cancelable}`
- 前端统一渲染：进度条（4Hz 节流）+ 阶段文案 + 取消按钮（cancelable 时）
- 消费面：冷热对比运行态 / 预设多卷应用 / 卸载回写 / L2 重建——**一个事件解锁四个界面**
- **验收**：四个场景各触发一次，前端进度与阶段文案同步刷新；取消事件被正确应答

## 5. 联调协作建议

1. **冻结节奏**：B-4/B-5/B-6/B-7/B-3 五项 P0 契约 W1 内双方冻结（前端已按上文形状建好消费位与降级路径）；P1 随 W1.5；B-14 随渠道周。
2. **进度事件先行**：B-7 与任何一项 P0 无依赖，可最先交付，立即解锁四面进度可见性。
3. **降级即解锁**：后端每交付一项，前端对应处从「降级/占位」切真数据——无联调大爆炸，逐项验收即可。
4. **双栏日志对照**：前端把预设应用/回写引导选择/反作弊检测/基准结果摘要写入 UI 日志，诊断包导出与驱动日志同屏——排障时后端可直接对照前端侧决策记录。
5. **遥测同口径（I-02）**：二遍读采样口径 UI=CLI=遥测三方一致；默认关、一键可关（设置页开关已有）。
6. **协议面变更走既有门禁**：三副本同步 + check_proto_sync --strict + sys 三锚点 + 未签名不部署（见 §0-3）。
