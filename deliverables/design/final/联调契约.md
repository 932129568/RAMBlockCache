## 0. 术语与约定

| 术语 | 含义 |
|------|------|
| **前端** | C# WPF Controller 进程（用户态），本契约中即「控制台 / UI」 |
| **后端 / 驱动** | 内核卷块过滤驱动 + 内存缓存，单 IOCTL `0x222000` 承载 `RB_MSG` |
| **消息** | `RB_MSG.MsgId` 的 12 个取值（1–12） |
| **用户态** | §C 六态状态机中的一个（含「熔断·自愈中」子态），**面向用户唯一状态语言** |
| **通道状态** | IOCTL 通道健康视图中单条消息的调用健康（正常 / 降级 / 不可用 / 未接通） |

### 0.1 `RB_MSG` 信封（Protocol 9）

```
偏移  字段      类型        说明
 0    Size      uint32      报文总长度
 4    MsgId     uint32      消息号 1..12
 8    Status    int32       统一应答语义：非 0 即错；优先取驱动回填的 NTSTATUS，其次回退 Win32 错误（RC.4）
12    Flags     uint32      保留 / 方向位
16    Epoch     uint32      熔断自愈世代号（PANIC / PANIC_CLEAR 专用握手）
20    Reserved  uint32      保留
24    Data[]    uint8       消息体（按 MsgId 解释）
```

> **统一应答语义（RC.4）**：前端读取 `Status`，**非 0 即视为失败**。取值判定顺序：① 若落在 NTSTATUS 域（`0xC0000000`–`0xFFFFFFFF`）则按 NTSTATUS 解释；② 否则按 Win32 错误码解释；③ 两者都不识别 → 归入「未知错误」并附原始十六进制。

| 12 | **PANIC_CLEAR** 解除熔断 | `{}` | `PanicActive, PanicEpoch, Settled` | 应急页「解除熔断」 | **自愈完成后可点** | 未完成 → `0xC00000A3`：按钮**置灰 + 原因 + 下一步**（不报错，RD/§C 子态） |

### RA.2 单一事实源约束
- 任一消息**不得**出现在两个页面上语义不同的位置。
- 跨页复用（#1 同时喂首页与收益页；#7 同时喂加速页与首页与状态条）**必须来自同一前端状态对象**（`MainViewModel` 的单一快照），不得各页面独立请求后自行解释。
- 前端**唯一状态对象**：`AppState { Version, Connection, Volumes[], Stats, Config, Channel[], LogCursor }`；所有页面渲染函数只读该对象。

### RA.3 写操作结果反馈约束
- 写操作消息集合 = {2, 3, 5, 6, 8, 11, 12}。
- 成功 → 更新状态条 / 卡片；失败 → 三段式错误 + **保持原状态**。
- **禁止**乐观更新后不回滚（如先置绿再失败却不变回）。

## 2. 状态映射表（覆盖 RB.1–RB.5 · 唯一判定规则）

### 2.1 后端字段 → 用户态（唯一判定函数 `ResolveUiState`）

**输入字段**（合并自 #7 与 #1 的同一快照）：

| 字段 | 来源 | 取值 |
|------|------|------|
| `ConnOk` | 打开控制设备结果 | true / false |
| `ConnErr` | 打开失败的错误码 | Win32 5 / 2 / 3 |
| `ProtocolOk` | #10 硬校验结果 | true / false |
| `Bound` | #7 每卷 | 0 / 1 |
| `Attached` | #7 每卷 | 0 / 1 |
| `WriteMode` | #7 每卷 | 0 直写 / 1 回写 / 2 跟随全局 |
| `SafeMode` | #1 | 0 / 1 |
| `PanicActive` | #1 | 0 / 1 |
| `PanicEpoch` | #1 / #12 | 世代号 |
| `DirtyBytes` / `LostDirtyBytes` | #1 | 字节数 |

**判定优先级（自上而下，命中即返回，避免歧义）：**

| 优先级 | 用户态 | 唯一判定规则 | 语义色 | 主行动 | 禁止动作 |
|:---:|--------|--------------|--------|--------|----------|
| 1 | **未安装** | `ConnOk==false && ConnErr ∈ {2,3}` | 灰 `neutral` | 运行安装向导 | 挂载 / 调优 / 熔断 |
| 2 | **版本不匹配**（阻断） | `ConnOk==true && ProtocolOk==false` | 红 `danger` | 重新安装同一发布包 | **所有写操作**（2/3/5/6/8/11/12 全部置灰） |
| 3 | **熔断·自愈中**（子态） | `PanicActive==1 && Settled==false` | 红 `danger` + 呼吸圆点 | 等待自愈完成 | 解除熔断（置灰 + 原因） |
| 4 | **熔断·全局透传** | `PanicActive==1 && Settled==true` | 红 `danger` | 解除熔断 | 直接恢复加速（须先等自愈） |
| 5 | **降级·安全模式** | `PanicActive==0 && SafeMode==1` | 琥珀 `warning` | 确认数据无误 → 退出安全模式 | 静默恢复回写 |
| 6 | **已安装未挂栈** | `PanicActive==0 && SafeMode==0 && ∀卷 Bound==0` | 蓝 `info` | 运行首次向导 / 重启挂栈 | 开启加速（无挂栈卷） |
| 7 | **就绪未加速** | `… && ∃卷 Bound==1 && ∀卷 Attached==0` | 蓝 `info` | 开启加速 | — |
| 8 | **加速中·回写** | `… && ∃卷 (Attached==1 && WriteMode==1)` | 绿 `success` + 琥珀角标 | 查看脏量 / 立即回写 | 关机前不提示风险 |
| 9 | **加速中·直写** | `… && ∃卷 (Attached==1 && WriteMode∈{0,2})` | 绿 `success` | 查看收益 | — |

> **规则 8 先于 9**：只要存在任一「加速中·回写」卷，**全局状态条「加速」段**即呈现回写语义（绿 + 琥珀角标），避免回写风险被直写卷掩盖。卷级徽标则按各卷自身状态独立渲染。

**卷级判定函数 `ResolveVolumeState(v)`（供卷卡/卷列表复用）：**

```
if PanicActive:                    → 熔断·透传（红）
elif !v.Bound:                     → 未挂栈（灰）
elif !v.Attached:                  → 就绪未加速（蓝）
elif v.WriteMode==1:               → 加速中·回写（绿 + 琥珀角标）
elif SafeMode:                     → 加速中·直写（安全模式）（琥珀）
else:                              → 加速中·直写（绿）
```

### 2.2 字段 → 状态条四段（覆盖 design-system §C.3）

| 段 | 正常 | 降级 | 异常 | 未知 |
|----|------|------|------|------|
| **驱动** | `已连接 v{machineVersion}` | `正在重连…`（退避期间） | `未连接（错误 N）` | `—` |
| **挂栈** | `已挂 {N} 卷`（N>0） | — | `未挂栈`（N=0） | — |
| **加速** | `正常加速中`（含回写卷） | `安全模式` | `熔断中` / `已禁用`（协议不匹配） | `就绪未加速` / `未安装` |
| **风险** | `无` | `未落盘 {DirtyBytes} MB` / `安全模式（上次异常退出）` | `熔断中` / `已确认丢失 {LostDirtyBytes} MB` | — |

- **风险段取值优先级**：`熔断中` > `已确认丢失 M MB` > `安全模式` > `未落盘 N MB`（阈值 >200 MB 才提示）> `无`。
- `LostDirtyBytes>0` → 风险段**必须**变琥珀并给「核对丢失量」入口（RB.4）。
- 四段任一非「正常」→ 该段**可点击**并跳转处置页：驱动→诊断、挂栈→加速、加速→状态、风险→应急。

### 2.3 字段可见性白名单（覆盖 RB.3 / RB.5）

- 原始字段（`Attached=1`、`WriteMode=2`、`PanicPassthrough`、`PanicEpoch`、`DirtyBytes` 等）**只允许出现在诊断页**，且必须附中文解释。
- 面向用户界面只允许六态文案 + 术语白名单：**挂栈 / 加速 / 直写 / 回写 / 熔断 / 安全模式 / 命中率 / 未落盘数据**。
- `WriteMode==RB_WRITEMODE_GLOBAL(2)` → UI 文案「**跟随全局设置**」，**禁止显示数字 2**（RB.5）。
- `DirtyBytes/LostDirtyBytes` → 「**未落盘数据 N MB / 已确认丢失 M MB**」，在状态条风险段与应急页核对区**一致呈现**（RB.4）。

## 3. 错误码 → 用户语言映射表（覆盖 RC.1–RC.5）

### 3.1 三段式文案表（发生了什么 / 为什么 / 下一步）

| 错误码 | 域 | 严重度 | ① 发生了什么 | ② 为什么 | ③ 下一步做什么 | 可重试 | 重试策略 |
|--------|----|:---:|--------------|----------|----------------|:---:|----------|
| Win32 **5** | Win32 | 阻断 | 没有权限访问缓存驱动。 | 控制设备仅允许管理员访问。 | **右键以管理员身份运行本程序。** | 否 | 不重试（确定性拒绝）；提供「以管理员身份重开」按钮 |
| Win32 **2** | Win32 | 阻断 | 未检测到缓存驱动。 | 驱动未安装或未启动。 | **点击「运行安装向导」。** | 否 | 不重试；提供「运行安装向导」按钮 |
| Win32 **3** | Win32 | 阻断 | 未检测到缓存驱动。 | 驱动路径不存在（未安装或已被移除）。 | **点击「运行安装向导」。** | 否 | 不重试 |
| Win32 **21** | Win32 | 警告 | 该卷尚未准备好。 | 卷信息仍在读取中。 | 稍候几秒后重试，或重启一次。 | **是** | 退避重试（300ms×(n+1)，≤3 次） |
| Win32 **170** | Win32 | 信息 | 驱动暂时繁忙。 | 正在执行其他操作。 | 程序会自动重试；若持续失败请稍后手动重试。 | **是** | 退避重试（同 21） |
| Win32 **87** | Win32 | 阻断 | 驱动与控制台版本不匹配。 | 安装包与控制台不是同一版本。 | **使用同一发布包重新安装。** | 否 | 不重试；**禁用全部写操作**（RE.5） |
| NTSTATUS **0xC00000A3** | NTSTATUS | 警告 | 暂时不能解除熔断。 | 驱动正在把未落盘数据写完（自愈中）。 | 等待风险段变为「无」后重试。 | **是** | 按钮置灰，不自动轮询重试；由 #1 的 `Settled` 翻转后自动恢复可点 |
| NTSTATUS **0xC0000001** | NTSTATUS | 警告 | 数据尚未完全写入磁盘。 | 磁盘报告写入错误。 | 检查磁盘健康；**未落盘数据仍在缓存中，可稍后重试**。 | **是** | 手动「稍后重试」；不自动重试（避免写放大） |
| NTSTATUS **0x80000011** | NTSTATUS | 信息 | 设备忙。 | 驱动正在处理其他请求。 | 程序会自动重试。 | **是** | 同 Win32 170 |
| **协议不匹配**（#10） | 语义 | 阻断 | 驱动版本与控制台不匹配（**驱动 8 / 控制台 9**）。 | 安装包与控制台不是同一版本。 | 使用同一发布包重新安装。 | 否 | 阻断连接；禁用写操作（RE.1/RE.5）；**归因码 `Win32 87`** |
| **未知错误** | 兜底 | 警告 | 发生未识别的错误（0x…）。 | 驱动返回了控制台未识别的状态码。 | 打开诊断并导出诊断包。 | 视情形 | 提供「打开诊断」入口 + 原始码（RF.2） |

### 3.1.1 错误码归属约束（MF-1 · 防「同态多说法」）

> 本节为 **MF-1 定点修正**的契约条款，用于消除同一状态在不同页面的错误码 / 版本号矛盾。

1. **协议不匹配（#10 GET_VERSION 硬校验失败）统一使用 Win32 87**。禁止复用 `0xC0000001` 或其他错误码。
   - 自检证据串固定为：`Protocol 不匹配（期望 9，实际 8）· Win32 87`。
   - **禁止**出现 `GET_VERSION.Status 偏移 8 = 0xC0000001` 之类的错误复用。
2. **`0xC0000001`（STATUS_IO_DEVICE_ERROR）专属 FLUSH 回写失败（#3）**，不得出现在协议不匹配 / 权限 / 未加载等其他场景。
3. **同一用户态的版本号表述全站唯一**：协议不匹配统一为「**驱动 8 / 控制台 9**」（`S.drvProto=8` / `S.uiProto=9`），首页协议卡、诊断页自检行、状态条驱动段三处必须一致。
4. **日志与状态一致**：诊断页日志随当前场景渲染（协议不匹配场景出现 `Win32 87` 协议行，**不出现** FLUSH 的 `0xC0000001`；回写失败场景反之），避免跨场景误导。
5. 原型对应：`03-prototype-v2.html` 首页 `pgState` 协议卡、诊断 `pgDiag` 自检行、`logView()` 三处已统一。

### 3.1.2 错误码可演示态映射（MF-2 / MF-3 · 支撑 C3 验收）

> 为支撑 C3（错误码映射完备）可验收，原型提供以下**可触发演示态**，每个错误码在 UI 上均有可达触点：

| 演示态 key | 触发错误码 | UI 触点 | 呈现 |
|-----------|-----------|---------|------|
| `access` | Win32 **5** 权限不足 | 首页异常卡 / 状态条驱动段 | 「没有权限访问缓存驱动…右键以管理员身份运行本程序」 |
| `notinstalled` | Win32 **2/3** 未加载 | 首页异常卡 / 状态条驱动段 | 「未检测到缓存驱动…运行安装向导」 |
| `flushfail` | `0xC0000001` FLUSH 失败 | 首页 + 应急页**三段式卡** | 「数据尚未完全写入磁盘 / 磁盘报告写入错误 / 检查磁盘健康；未落盘数据仍在缓存中，可稍后重试」+「稍后重试」按钮 |
| `attaching` | Win32 **170** / **21** / `0x80000011` 瞬时冲突 | 加速页开关 + 通道 #8 + 状态条 | 「正在挂载…第 N 次重试，退避 300/600/900ms」 |
| `protocol` | Win32 **87** 协议不匹配 | 首页异常卡 + 诊断自检 + 状态条 | 「驱动 8 / 控制台 9…使用同一发布包重新安装」+ 禁用全部写操作 |
| `heal` | `0xC00000A3` 自愈未完成 | 应急页 / 首页 | 解除熔断置灰 + 原因 + 下一步 |

### 3.2 判定函数约束（RC.3）

`DriverException.Win32Error` 同时承载 **Win32 与 NTSTATUS 两个取值域**，判定函数（如 `IsTransientAttach`）必须**显式枚举两个域**，禁止依赖数值巧合：

```
IsTransientAttach(err) :=
    err == ERROR_BUSY(170)        ||
    err == ERROR_NOT_READY(21)    ||
    err == ERROR_FILE_NOT_FOUND(2)||
    err == STATUS_DEVICE_BUSY(0x80000011) ||
    err == STATUS_DEVICE_NOT_READY(0xC00000A3)

IsDeterministicReject(err) :=
    err == ERROR_ACCESS_DENIED(5) ||
    (err 落在 NTSTATUS 域 && (int32)err < 0)
```

> 注意：`0x80000011` 与 `0xC00000A3` 数值上远大于 Win32 域，**不得**用「数值小于某个阈值」之类的巧合判断；必须按显式枚举匹配。

### 3.3 呈现规范（RC.5）

- 所有错误弹窗 / 卡片**必须含「下一步做什么」的可点击动作**（如「以管理员身份重开」「运行向导」「打开诊断」），**不允许只给错误码**。
- 归因元信息（RF.2）以折叠区呈现：`错误码（Win32/NTSTATUS）+ 消息号 + 时间戳`，等宽栈 11px。
- 严重度三级：信息（蓝，允许继续）/ 警告（琥珀，允许继续 + 风险说明）/ 阻断（红，禁止相关写操作）。

## 4. 轮询与降级策略（覆盖 RD.1–RD.7）

### 4.1 统计轮询（RD.1–RD.3）

| 项 | 契约 |
|----|------|
| 周期 | **1 秒**（`StatsService` 定时器） |
| 异常隔离 | 整轮 `try/catch` + 每消息分发单独 `try/catch`；单次采样失败**不得**终止轮询任务（RD.1） |
| 采集键集合 | 在 `Start` 时**物化为不可变数组**，避免与 UI 线程并发修改集合导致轮询静默停更（RD.3） |
| 失败处理 | 失败只记 `LogService`，UI 显示「统计暂不可用」并继续下一轮 |

### 4.2 失败退避（RD.2）

| 连续失败次数 N | 轮询周期 | 状态条 |
|:---:|:---:|--------|
| 0（成功） | 1 s | 正常 |
| 1–2 | 1 s | 正常（仅记日志） |
| ≥3 | 指数退避：`min(1s × 2^(N-2), 10s)` | 驱动段显示「**正在重连…**」 |
| 任一次成功 | **立即恢复 1 s** | 恢复正常 |

> 退避上限 **10 s**；恢复条件为「任一次成功」而非「连续成功」，避免抖动。

### 4.3 统计不可用呈现（RD.5 / C4）

- 采样失败或驱动未连接：三数字卡**不显示 0**，而是：
  - 数值位 → `—`（32px/600，`--rbc-text-tertiary`）
  - 副文本 → `统计暂不可用（原因）`（12px `--rbc-warning-fg`）
  - 卡右上角 → 琥珀小徽标「**数据暂停**」
- 原因取自 §3.1（如「驱动未加载」「权限不足」），并给「重试」幽灵按钮。
- 趋势图 / 环图同步显示「暂不可用」占位，**不画归零曲线**。

### 4.4 ATTACH 瞬时冲突退避（RD.4）

```
for n in 0..2:                          # 最多 3 次
    result = ATTACH_VOLUME(...)
    if success: return success
    if IsTransientAttach(err):
        sleep(300ms × (n+1))            # 300 / 600 / 900 ms
        continue
    if IsDeterministicReject(err):
        return fail(err)                # 立即失败，不重试
return fail(LAST_ERR)                   # 3 次耗尽
```

- 确定性拒绝（5 / 负 NTSTATUS）→ **立即失败** + 三段式 + 提示「检查 panic / 保护状态」（RD.4）。
- 重试期间状态条 / 开关显示「正在…」进度反馈（RD.7）。

#### 4.4.1 退避重试的可观测呈现（MF-4 · 支撑 M8 验收）

> 为支撑 M8（轮询退避 / attach 重试 / 断连降级）可验收，原型提供 `attaching` 演示态，把退避过程**可视化**：

| 触点 | 呈现 | 依据 |
|------|------|------|
| 加速页卷开关 | 开关置灰 + 「**正在挂载…**」+ 副文本「第 N 次重试，退避 {300×N}ms（瞬时冲突自动重试）」 | RD.4 / RD.7 |
| IOCTL 通道健康 #8 | 状态点转**琥珀**「降级 · 重试中」，延迟列显示 `—`，时间列「重试中」 | §6.1 |
| 顶部状态条 | 追加「**正在重试挂载 F:…（第 N 次，退避 Xms）**」 | RD.2 同款退避提示 |
| 诊断日志 | 追加 `[驱动 WARN] ATTACH_VOLUME 冲突：Win32 170（驱动忙），退避重试 600ms` | §6.3 |

- 与「断连降级」（`statsfail` → 状态条「正在重连…」）**共用同一退避提示范式**，避免两套说法。
- 演示轮询周期与产品一致（1s），文案「1 秒轮询」不再与演示节流冲突。

### 4.5 连接建立与断连（RD.6 / RD.7）

| 场景 | UI 行为 |
|------|---------|
| 启动握手失败 | Banner（降级条）给出三段式；驱动段变红 |
| 运行中断连（错误 2） | 触发 `DriverReportedUnmounted` → 驱动段转灰/红 + 自动重连 + 状态条「正在重连…」 |
| 超过 1 秒的动作（自愈 / 回写 / 卸载 / attach 重试） | **必须有「正在…」进度反馈**（不确定态进度条 = 40% 宽往复位移，禁止渐变扫光） |

## 5. 版本协商（覆盖 RE.1–RE.5）

### 5.1 握手流程


### 6.1 IOCTL 通道健康视图（RF.1 / RF.5）

**位置**：诊断页顶部独立面板（原型已实现）。
**形态**：12 行紧凑列表，每行：`[状态点] [消息中文名] [#编号] [延迟 ms / —] [最近调用时间] [通道状态]`。

| 通道状态 | 语义色 | 判定规则 | 用户可见表达 |
|----------|--------|----------|--------------|
| **正常** | 绿 `success` | 最近一次调用成功 | 绿点 + 延迟 ms |
| **降级** | 琥珀 `warning` | 连续失败 ≥1 但仍在退避重试 | 琥珀点 + 「重试中」 |
| **不可用** | 红 `danger` | 确定性拒绝 / 超时耗尽重试 | 红点 + 三段式错误入口 |
| **未接通** | 灰 `neutral` | 尚未调用过 / 不适用 | 灰点 + `—`（**禁止显示 0**） |

**归因结论**（面板底部一行，回答「驱动问题还是 UI 问题」）：

| 条件 | 结论 |
|------|------|
| 控制设备打不开 | 驱动问题（驱动未加载 / 权限不足） |
| 协议不匹配 | 驱动问题（版本不一致） |
| FLUSH 回写失败（`0xC0000001`） | 驱动问题（FLUSH 回写失败，可稍后重试） |
| 存在「不可用」通道 | 驱动问题（消息返回确定性错误） |
| 仅存在「降级」通道 | 瞬时问题（正在退避重试） |
| 全部正常 | 无异常 |

### 6.2 诊断包内容清单（RF.3）

一键导出 `诊断包.zip`，含：

### 6.3 日志拉取契约（RF.4）

| 项 | 契约 |
|----|------|

**C6 · 版本协商可解释**
- 验证：切换演示「协议不匹配」。
- 预期：驱动段转红 + 首页异常卡 + 诊断自检标红 + 全部写操作置灰（含原因副文本）+ 版本单轨。

**C7 · 可观测性**
- 验证：进诊断页观察通道健康 + 自检 + 日志时间线；点「导出诊断包」。
- 预期：12 条通道状态 + 归因结论；自检 6 项；日志来源标签可区分；导出含 §6.2 五项内容。

**C8 · 危险态可达**
- 验证：从首页数点击次数到达 熔断（首页按钮 1 次）/ 退出安全模式（应急页 1 次）/ 回滚指引（应急页直达）。
- 预期：均 ≤2 次点击。

### 7.2 演示态 → 验收项映射（MF-1~MF-4 可验收）

> 原型侧栏「演示 · 切换用户态」提供 15 个可触发态；下表给出各态支撑的验收项。

| 演示态 | 覆盖 | 支撑验收 |
