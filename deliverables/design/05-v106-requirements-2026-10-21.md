## 1. 设计五要素

| 维度 | 结论 |
|------|------|
| **场景（Surface）** | Windows WPF 桌面控制台，固定窗口 1180×780（min 900×600，DIP 等比缩放，响应式非目标）。六页（状态/加速/收益/诊断/应急/设置）+ 首次运行向导（现四步：认识/环境自检/选卷/完成，V10.6 增强）+ 托盘 + 三段式弹窗体系（V10.6 新增两种范式：回写引导对话框、反作弊警示对话框）+ Toast + 状态条四段。驱动侧零改动。 |
| **受众（Audience）** | 数据盘用户三类画像：① **游戏玩家**（游戏库盘，关心加载延迟与命中率）② **仓库盘用户**（大容量仓库盘，关心顺序读与冷热对比）③ **性价比装机者**（内存大、想榨干性能，能看懂参数但不想被术语包围）。共同含**非技术用户**——PRD 验证标准「3 分钟完成首配」直接推导出：F1 预设菜单与向导必须是零术语的（延续「加速/直写/回写/熔断」四词白名单）。 |
| **调性（Tone）** | **暗色精密仪表 2.0**。基调延续 V2（Linear 骨架 + Tech Utility）：8 层背景阶梯、1px 发丝描边、等宽数值、克制语义五色、六档动效。PRD「符合当前主流审美趋势」的落地方式 = **层次精度 + 微质感增量**（详见 §3）：可感知的层差序（窗口<侧栏<状态条<卡片<悬浮<浮层）、图表单色面积填充与圆角线帽、浮层微缩放入场（0.98→1 / 180ms）、受控的黑色浮层阴影。**明确拒绝**：玻璃拟态、霓虹发光、渐变文字、装饰性动效（PRD 红线与 V2 禁令双重锁定）。受众共同刚需是「确定感」——要精确，不要惊艳。 |
| **品牌上下文（Brand Context）** | 无外部品牌可遵循。RAMBlockCache 自有青色身份 `#4CC2FF`（原型 `#60CDFF` → 02 规范收敛 → V2 令牌 `RbcAccent`）为唯一品牌资产；机器版无品牌物料，**界面本身即品牌**。V10.6 不引入第二品牌色，不因「主流审美」更换身份色。 |
| **规模（Scale）** | 六页重构（V2 令牌迁移 + I-08 话术清查）+ **4 个新功能面**（F1/F2/F3/F4）+ **1 个状态展示面**（F5）+ 向导增强（预设步骤、反作弊并入自检）+ 弹窗体系扩展（两种新对话框范式）+ 演示态切换器扩展（+4 态）。交互复杂度顶格：静态 + 动效 + 交互状态（预设应用/基准运行/引导流/服务检测）俱全，全部需覆盖 reduced-motion 降级。 |

## 2. 新功能面需求细化（F1–F5）

### F1 场景预设菜单（对应 PRD I-01【P0】）

**定位**：「易用」支柱的核心交互。让非技术用户在 3 分钟内完成首配，让技术用户一键获得合理基线再微调。

#### 信息架构

| 要素 | 决策 |
|------|------|
| 主入口 | **设置页新增「场景预设」卡，置于「缓存策略」卡之上**（设置页第一张功能性卡片） |
| 次入口 | 加速页每张卷卡右上角显示**预设来源 chip**：「当前：均衡预设」/「自定义（基于均衡）」——点击跳设置页预设卡 |
| 第三入口 | **首次向导第 3 步「选卷」之后并入预设选择**（一步完成「选哪些卷+用什么档位」，支撑 3 分钟首配验收；D6 向导已建，此为步骤内容增强） |
| 控件形态 | 预设 ComboBox（四值：安全·只读 / 均衡·读写 / 性能·回写 / 自定义）+ 受管参数摘要表（默认折叠，`details` 或展开箭头）+「恢复默认」次按钮 |

#### 三档预设参数表（建议初值）

> 说明：**4K 缓存块大小为驱动固定值，非用户可配项，预设不管**（回应需求中「块大小」——真正可配的是预读窗口）。「保留全部手动项」落地为：**每卷配额、挂载状态、自定义排除名单永不被预设覆写**（配额与磁盘容量强相关，属用户个体决策）。

| 受管参数 | 安全·只读 | 均衡·读写 | 性能·回写 | 备注 |
|----------|-----------|-----------|-----------|------|
| 每卷写模式 | 直写 | 直写 | 回写 | 性能档应用时**逐卷经过 F3 引导流**；用户取消则不应用该档 |
| 读预取总开关 | 关 | 开 | 开 | 「开」仍需 C5 预取门校验（已验证 SSD 数据卷） |
| 每卷预读窗口 | 8 块（≈32KB） | 16 块（≈64KB） | 32 块（≈128KB） | 单位（块 vs KB）需与 CLI 确认，见开放决策 D-7 |
| L2 持久缓存 | 关 | 关（用户自选开） | 开 | 安全档刻意避开 L2 容器写盘；L2 属「读了才有收益」的进阶项 |
| 回写周期 | 不适用（直写无脏数据） | 60 秒 | 60 秒（提供 30 秒「更稳」选项） | 沿用设置页现有五档 |
| 进程准入排除 | 内置名单开 + 建议补备份类 | 内置名单开 | 内置名单开，**不建议再扩大**（扩大缓存覆盖） | 三档均保留手动编辑入口 |
| 全局内存预算 | 预留 4 GB / AutoUsePct 50% | 预留 2 GB / 75% | 预留 1 GB / 90% | 待 B4 协议确认后生效；未确认前预设**不覆写**此项并标注「协议待确认」 |

#### 交互流程

```
用户选择预设档位
  ├─ 目标配置不含回写开启 ──→ 即时应用（无保存按钮）→ Toast「已应用『均衡』预设」→ 受管字段全部刷新 → 统计继续
  ├─ 目标配置含回写开启（性能档，或卷卡手改）──→ 拦截：逐卷弹出 F3 引导流
  │     ├─ 用户确认 ──→ 该卷应用回写 + 其余受管项一并应用 → 记录日志
  │     └─ 用户取消 ──→ 整档不应用（原子性，见开放决策 D-2）→ 选择器回退到原档位 → Toast 说明原因
  └─ 应用失败（任一字段 SET_CONFIG 失败）──→ 已应用项回滚至原值 → Toast 三段式错误归因
用户手动修改任一受管字段 ──→ 选择器自动切「自定义」→ chip 显示「自定义（基于：上一档位）」+ 差异项列表
点击「恢复默认」──→ 轻确认（次级两段式：将把受管参数恢复为「XX 预设」标称值）──→ 应用 → 选择器回到该预设
```

#### 状态机

```
Idle ─选档─▶ Previewing ─含回写?─是─▶ Confirming(F3) ─确认─▶ Applying ─成功─▶ Applied
                │否                        │取消                │失败
                ▼                           ▼                    ▼
            Applying ◀────────────────── Reverted            RolledBack + Toast(三段式)
                │
                ▼
             Applied ─用户手改受管项─▶ Custom（正交标志，记录 basePreset）
```

#### 数据需求

- 读取：各卷当前配置（GET_CONFIG 现有字段：写模式/预读窗口/配额/预取开关）+ 全局配置（L2/回写周期/内存预算/排除名单）——均已有
- 写入：逐字段 SET_CONFIG（已有）；**建议服务层新增 `ApplyPreset(presetId)` 编排方法**（原子性：全成功或全回滚）与 `GetPresetDiff()`（前端展示与当前预设的差异）——轻量新增，见 B 类清单
- 事件：写模式变更事件（F3 拦截触发源）；操作进度事件（C1，应用多卷时的进度反馈）

#### 验收标准

1. 三档一键应用后，设置页缓存策略卡与加速页卷卡所有受管字段反映预设值；预设摘要表展示的值与落库值一致
2. 手动改任一受管字段 → 选择器即时切「自定义」并列出与基础预设的差异项；差异项可一键「恢复默认」消除
3. 性能档应用必须逐卷经过 F3；取消即整档不应用，不留半配置
4. 全流程无「保存」按钮，改动即生效；任一字段失败 → 已应用项可见回滚 + Toast 三段式归因
5. 向导内完成「选卷 + 选预设」≤ 3 分钟（PRD 验证标准，需可用性测试抽验）
6. reduced-motion 下所有过渡静态化，信息不丢

### F2 冷热二遍读对比工具（对应 PRD I-02【P0】·「可自证」核心叙事）

**定位**：三支柱「可信」的**证据工具**——让用户自己跑一遍，用数字证明缓存有效。话术纪律（I-08）要求一切性能表述可复现，本工具就是复现手段。

#### 信息架构

| 要素 | 决策 |
|------|------|
| 主入口 | **收益页新增「冷热对比」卡**，占黄金位（span2，与「读命中率趋势」并列首行） |
| 次入口 | 状态页平均命中率 KPI 下方放 LinkChip「自己跑一遍验证 →」跳收益页并高亮该卡（复用已有 LinkChip 组件） |
| 卡内结构 | ① 文件选择行（选择按钮 + 文件名/大小/所在卷 + 约束说明）② 「开始对比」主按钮 ③ 运行区（进度：遍次 + 进度条 + 已读/总量 + 瞬时 MB/s + 取消）④ 结果区（对比表 + 双条形对比图）⑤ 口径声明常驻小字 |

#### 交互流程

```
Idle ─选择文件─▶ Validating（大小≥阈值？卷已加速？文件可读？）
                    │不满足 → Error（具体原因文案，如「文件小于 512 MB，对比结果不稳定」）
                    │满足 ▼
               FileReady ─点「开始对比」─▶ Flushing（对该文件范围做缓存刷新，保证第一遍是真冷读）
                    │刷新失败 → 警告横幅「无法保证第一遍为冷读，结果仅供参考」+ 仍可继续（转 B 类能力，见契约）
                    ▼
               Pass1Running（冷读·盘速：顺序读全文件，4K 块，**绕过 Windows 文件缓存**）
                    ▼
               Pass2Running（热读·缓存速：同文件同读法）
                    ├─ 取消 ──▶ Cancelled（提示：统计口径不受影响）
                    ▼
               Result（对比表 + 双条形图 + 口径声明）
```

#### 结果对比表（结构定义）

| 行（指标） | 第一遍（盘速·冷） | 第二遍（缓存速·热） | 提升 |
|-----------|------------------|---------------------|------|
| 读取速度 | xx.x MB/s | xx.x MB/s | ×N.N |
| 耗时 | x.x 秒 | x.x 秒 | -xx% |
| 读取量 | x.xx GB | x.xx GB | — |
| 命中率 | —（冷读不命中） | xx.x% | — |

- 双条形对比图：第一遍 = `RbcChart2`（次序列）、第二遍 = `RbcChart1`（主序列），条形规范沿用图#7（无外框/无背景块/轨道 `RbcChartTrack`）；数值标签等宽右对齐
- **口径声明（常驻不可关闭）**：「同一文件 · 同样读法 · 绕过系统缓存 · 与 ramboostctl stats 同口径（误差 <2%）」

#### 状态机

```
Idle → Validating → FileReady → Flushing → Pass1Running → Pass2Running → Result
 any → Error（带原因）│ PassRunning → Cancelled │ Result → 重新选文件 → FileReady
```

#### 数据需求

- **🆕 基准执行体**：`RunColdWarmBenchmark(filePath)` → `{ pass1:{mbps,seconds,bytes}, pass2:{...}, hitRatePass2, ioMode:"no-buffered", blockKB:4, toolVersion }`；必须与 `ramboostctl stats` 同一测量代码路径与时钟（QueryPerformanceCounter），**误差 <2% 为硬性契约**
- **🆕 进度事件**：接入公共操作进度事件（C1）：`{opType:"benchmark", pass:1|2, percent, mbpsInstant, cancelable:true}`
- **🆕 取消语义**：取消后统计计数器口径不变（不污染 stats）
- **🆕 缓存范围刷新**：`FlushFileRange(path)` 或等价能力（第一遍前驱逐该文件占用的缓存块）
- ✅ 第二遍命中率：复用 StatsService 秒级计数器（同口径采样）

#### 验收标准

1. 同一文件同机重复运行三次，与 `ramboostctl` 等效命令输出误差均 <2%（写入验收门，不达标不发版）
2. 第一遍读数必须经过缓存刷新；无法刷新时界面明确警示「仅供参考」，不得伪装成严谨对比
3. 全过程绕过 Windows 文件缓存（FILE_FLAG_NO_BUFFERED_IO 或驱动侧等价）——**此项不满足则整个工具是假的**（见风险 R-2）
4. 进度可见（遍次/百分比/瞬时速度）、可取消、取消后 stats 口径不变
5. 错误态覆盖：文件过小 / 文件被占用 / 无权限 / 所在卷未加速 / 读取中途失败——各给具体原因文案
6. reduced-motion：进度条静态化，百分比与遍次文本常驻
7. 界面明示测量条件（同文件/绕过系统缓存/4K 块），不出现任何无法复现的营销数字

### F3 回写开启引导流（对应 PRD I-03【P0】·「安全」支柱）

**定位**：默认直写的产品哲学下，回写是唯一的「性能换风险」选项。引导流 = 风险知情同意机制：检测电源保障、给出场景建议、三段式确认、记录选择。

#### 触发点（全部收敛到同一对话框）

1. 加速页卷卡写模式下拉选「回写」
2. F1 应用「性能·回写」预设（逐卷触发）
3. 首次向导中若用户选择了性能档（同 2）

#### 信息架构（对话框 = 三段式结构 + 两个特有区块）

```
┌─ 开启回写确认 ────────────────────────────────┐
│ ① 将发生什么                                   │
│   回写模式下，缓存先收下写请求再定时写入磁盘，   │
│   写性能更好；但意外断电可能丢失尚未落盘的数据。 │
│                                                │
│ ② 影响与风险                                   │
│   ▸ 电源状态：{三态结论，见下}                  │
│   ▸ 场景适配：                                  │
│      ✓ 推荐开启：下载目录 / 编译输出 / 临时目录 │
│      ✗ 不建议：数据库文件 / 备份镜像 / 虚拟机磁盘│
│   ▸ 当前卷：E:（Work）                         │
│                                                │
│ ③ 如何撤销                                     │
│   随时切回直写；卸载或关机会自动回写脏数据。     │
```

#### 电源检测三态（WMI Win32_Battery 简化采集：BatteryPresent / PowerStatus / ChargePercent）

| 态 | 判定 | 对话框表现 | 按钮态 |
|----|------|-----------|--------|
| 台式机·无电池 | BatteryPresent=false | 风险句加强：「台式机没有电池备用，意外断电可能丢失未落盘数据」 | 可确认 |

### F4 反作弊环境检测（对应 PRD I-04【P0】·「安全」支柱）

**定位**：测试签名版驱动可能被反作弊系统拦截或导致游戏拒启。**正式签名版用户不应被打扰**——所以这是唯一「按构建分支分叉行为」的功能。

## 6. 范围与优先级建议（对齐 PRD 波次）

| 波次 | 优先级 | 范围 | 出口标准 |
|------|--------|------|----------|
| **W1 前置** | — | A-4 令牌迁移 + A-1/A-2/A-3 小项 | 新功能面直接在迁移后令牌上建设；grep 门禁通过 |
| **W1** | **P0** | **F1 场景预设** + **F2 冷热对比** + **F3 回写引导** + **F4 反作弊检测** + A-8 话术清查 + A-7 向导增强（随各面落地） | 四功能面全部可达可演示；F2 误差 <2% 契约签订（后端同步）；话术清查清单销号 |
| **W1.5** | **P1** | **F5 许可状态展示**（占位激活）+ 视觉微升级（V-2/V-3/V-4/V-6）+ A-12 电源 chip + A-11 演示态扩展 + A-5 诊断补全 | 五态许可 UI 可演示；新动效全部有 reduced-motion 分支 |

## 7. 风险与开放决策

### 7.1 风险

| # | 风险 | 影响 | 缓解 |

### 7.2 开放决策（需主理人/产品拍板，不阻塞设计启动）

| # | 决策点 | 建议 |
|---|--------|------|
| D-1 | 预设应用语义：全量覆写受管参数 vs 仅填「用户未调过」的项 | **全量覆写 + 自定义追踪**（更符合「一键选择、参数自动填合理值」的可预期性；差异清单可一键恢复） |
| D-2 | 性能档触发回写、用户在 F3 取消时：整档不应用 vs 部分应用 | **整档不应用（原子性）**，避免半配置态 |
| D-3 | 性能档回写周期值：60s vs 30s | 60s 默认，提供 30s「更稳」选项 |
| D-4 | L2 在安全档：关 vs 开 | **关**（安全档刻意避开 L2 容器写盘） |
| D-5 | 许可过期策略：停止新增加速 vs 功能不阻塞 | **停止新增加速 + 保留已加速卷安全卸载路径**（商业化与数据安全平衡）；需产品确认 |
| D-6 | F2 文件大小阈值 | 512 MB（256–1024MB 区间可调，界面明示） |
| D-7 | 预读窗口单位：块（4K）vs KB | 与 CLI/协议确认后冻结；建议界面显示 KB（用户友好），内部按块 |
| D-8 | WMI 采集实现：System.Management vs Windows.Devices.Power vs PowerShell 兜底 | 评估引用成本后定；采集失败必须有「未知态」降级 |
| D-9 | 反作弊警示文案（尤其「游戏无法启动」表述） | 需产品/法务 review 后冻结 |
| D-10 | 主按钮配色（04b §11.1 遗留拍板项） | 对齐规范青 `#4CC2FF`（本文延续该建议） |
